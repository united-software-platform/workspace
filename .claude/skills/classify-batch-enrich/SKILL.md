# Навык classify-batch-enrich

Обёртка пакетного прогона авто-классификации с обогащением: принимает список проектов опросом
до полного принятия, спрашивает модель исполнителя и порог, запускает параллельные фоновые
агенты по одному на проект и сводит итог в один файл `projects/{штамп}.json`. Сам навык
не порождает беклоги и не классифицирует — элементы пакета исполняют фоновые агенты операцией
`classify-project-auto` с веб-поиском, выбором источника и циклом дополнения карточки.
Доменные понятия определены в [глоссарии](../../../GLOSSARY.md).

## Вход

Вход навыка — вызов без значений: список проектов не передаётся аргументами, а собирается
опросом. Владелец называет проекты в ответах навыка.

- Вызов с перечислением проектов — список берётся из вызова, опрос идёт только по недостающему.
- Вызов пуст — навык начинает опрос с вопроса «какие проекты классифицируем».

## Опрос

Опрос идёт до полного принятия и покрывает три вопроса:

1. **Список проектов** — владелец называет проекты по одному или списком; навык показывает
   итоговый состав и предлагает дополнить либо принять; опрос продолжается до явного принятия.
1. **Модель исполнителя** — уровни: `haiku` (умолчание), `sonnet`, `opus`, `fable`. Конкретная
   модель уровня разрешается платформой через переменные `ANTHROPIC_DEFAULT_HAIKU_MODEL`,
   `ANTHROPIC_DEFAULT_SONNET_MODEL`, `ANTHROPIC_DEFAULT_OPUS_MODEL`,
   `ANTHROPIC_DEFAULT_FABLE_MODEL` — навык передаёт уровень, а не ID модели. Владелец не
   назвал уровень — берётся `haiku`.
1. **Порог confidence** — умолчание `0.5`; владелец вправе назвать свой, один на весь пакет.

Ответ на каждый вопрос показывается владельцу в сводке перед запуском агентов; запуск идёт
после принятия сводно́го состава: список, уровень модели, порог.

## Порядок

1. **Принять список** — по правилам раздела «Опрос».
2. **Проверить окружение** — заданы `WEBSEARCH_BASE_URL`, `WEBSEARCH_API_KEY`,
   `WEBSEARCH_ENDPOINT`, `EMBEDDINGS_BASE_URL`, `EMBEDDINGS_API_KEY`, `EMBEDDINGS_MODEL`;
   выгрузка `tools/classifier/taxonomy/` закоммичена (`git status --porcelain` пуст).
   При отсутствии — стоп с названным препятствием, агенты не запускаются.
3. **Построить штамп пакета** — `date +%Y%m%d%H%M%S` локального времени в момент запуска.
4. **Запустить фоновых агентов** — по одному на проект, параллельно, инструментом `Agent`:
   `model: <выбранный уровень>`, `subagent_type: claude`. Задача агента — породить и исполнить
   беклог операции `classify-project-auto` по своему проекту: `backlog generate
   --operation classify-project-auto --subject {штамп}-item-{NN} --value project_name=<имя>
   --value threshold=<порог> --value package_stamp=<штамп> --value item_number=<NN>
   --value runner_model=<уровень>`, затем исполнить его до конца по порядку
   `/backlog:backlog-run` и вернуть структурный результат. Предмет беклога —
   `{штамп}-item-{NN}`, реальное имя проекта живёт только во фронтматтере.
5. **Собрать результаты** — дождаться всех агентов; агент не смог вернуть результат —
   проект получает статус `failed` с причиной из отчёта агента либо «агент не вернул результат».
6. **Написать итоговый файл** — единственный файл `projects/{штамп}.json`, пишется один раз
   по завершении всех агентов; формат записей — раздел «Контракт записи прогона».
7. **Сообщить итог** — сводный отчёт по разделу «Сводный отчёт».

## Контракт записи прогона

Итоговый файл — JSON-массив записей, по одной на проект, в порядке принятого списка. Поля записи:

| Поле | Состав |
|------|--------|
| `project_name` | Имя проекта из принятого списка |
| `status` | `classified` либо `failed` |
| `source` | URL выбранного источника; `null` при отказе до выбора |
| `card` | Объект карточки (`purpose`, `facets`); `null`, если карточка не составлялась |
| `classification` | Итог утилиты целиком; `null` при отказе до классификации |
| `failure_reason` | Причина отказа; `null` при успехе |

Карточки прогона хранятся файлами `projects/{штамп}.cards/item-NN.json` — по одной на проект;
агенты пишут их при исполнении задачи 4.1 шаблона. Каталог `projects/` игнорируется git.

## Сводный отчёт

По завершении прогона владелец получает:

- штамп прогона и путь итогового файла;
- по каждому проекту: статус, выбранный источник, авторство решений (`<уровень>: <значение>`);
- перечень упавших с причинами;
- напоминание: повторы — новым прогоном либо одиночным навыком `classify`.

## Отказы

- Переменные окружения не заданы либо таксономия не закоммичена — стоп до запуска агентов,
  препятствие названо.
- Часть агентов упала — прогон завершается полным составом: упавшие проекты в итоговом файле
  со статусом `failed` и причинами; падение одного не останавливает остальных.
- Порождение беклога элемента отказало — проект получает статус `failed` с причиной отказа
  порождения из таблицы исходов `backlog-generate`.

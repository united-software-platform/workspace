# Навык classify

Обёртка запуска операции `classify`: принимает путь к карточке проекта одним вызовом,
строит предмет-адрес прогона и делегирует порождение и исполнение навыкам плагина
backlog. Сам навык не порождает беклоги, не вызывает утилиту и не исполняет задачи —
всё это делают `/backlog:backlog-generate` и `/backlog:backlog-run`.

## Вход

Вход навыка — путь к файлу карточки проекта: что классифицируем, текстом вызова.

- Путь назван — навык не спрашивает его повторно.
- Вызов пуст — навык задаёт ровно один вопрос «какая карточка» и после ответа продолжает
  без повторных вопросов о недостающем вводе.

Карточка — файл JSON вне репозитория по контракту
[`tools/classifier/docs/contracts.md`](../../../tools/classifier/docs/contracts.md).
Карточка и её копии в репозиторий не попадают; прогон не коммитится.

---

## Порядок

1. **Принять путь карточки** — по правилам раздела «Вход».
2. **Построить предмет прогона** — строку `{YYYYMMDDHHMMSS}-{краткое_описание_на_анг}`:
   штамп `date +%Y%m%d%H%M%S` локального времени в момент вызова и слаг из 2–5
   английских слов через дефис по смыслу карточки. Предмет — адрес прогона; коллизию
   адреса штамп делает практически невозможной.
3. **Предложить `target`** — репозиторий из `git remote get-url origin` текущего
   проекта, приведённый к виду `owner/repo`. Навык предлагает значение сам, вопрос
   «какой репозиторий» не задаётся.
4. **Вызвать `/backlog:backlog-generate`** с операцией `classify`, предметом из шага 2
   и значениями `card` (путь карточки) и `threshold` (порог; не задан владельцем —
   пустая строка, шаблон применяет умолчание 0.5). Собранный вызов `backlog generate`
   показывается владельцу целиком до прогона — предмет и слаг правятся при подтверждении.
5. **Проверить окружение перед порождением** — карточка существует, переменные
  `EMBEDDINGS_BASE_URL`, `EMBEDDINGS_API_KEY`, `EMBEDDINGS_MODEL` заданы; при
  отсутствии — стоп с названным препятствием, беклог не порождается.

---

## Передача исполнения

Вызов этого навыка — заранее данный ответ «исполнить». После успешного порождения
навык передаёт исполнение `/backlog:backlog-run` без повторного вопроса «исполнить
либо остановиться».

Стоп-знак принятия классификации (задача 3.1 шаблона) сохраняется и спрашивает
владельца всегда — он принадлежит шаблону и исполнителю, обёртка его не снимает.
Режима авто нет: без явного принятия классификация не считается присвоенной.

---

## Отказы

Отказы передаются владельцу как есть, навык не разбирает их сам и не заводит шаблон:

- шаблона `templates/classify.md` нет — отказ навыка `/backlog:backlog-template`;
- порождение не удалось — ввод, дефект шаблона, окружение — отказ `backlog-generate`
  по его таблице исходов;
- адрес занят лежащим беклогом — вопрос «исполнить лежащий либо породить с новым
  предметом» решает владелец.

# Навык requirement-add

Обёртка запуска операции `requirement-add`: принимает требование владельца одним вызовом, строит
предмет-адрес прогона и делегирует порождение и исполнение навыкам плагина backlog. Сам навык
не порождает беклоги, не пишет шаблоны и не исполняет задачи — всё это делают
`/backlog:backlog-generate` и `/backlog:backlog-run`. Доменные понятия определены
в [глоссарии](../../../GLOSSARY.md).

Продукт операции — требование-документ `docs/requirements/<ID>.md`: карточка BR из девяти полей
(ID, Name, Description, Rationale, Business Outcome, Success Criteria, Priority, Status,
Source), принятая владельцем на стоп-знаке и зафиксированная артефактом. На время прогона
карточка живёт во фронтматтере беклога значением `br_card`; после принятия покидает прогон —
требование доступно для работы вне беклога, сам беклог остаётся свидетельством прогона.
Операция с GitHub не работает: задач на GitHub, веток и коммитов она не создаёт — заведение
задачи по принятому требованию несут операции `workflow`, вызываемые отдельно.

Домен входит в прогон дважды: глоссарий `GLOSSARY.md` — обязательный контекст с предусловий
шаблона, доменная сверка предмета и терминов — его задача перед прожаркой; при введении
новых понятий сверка вызывает `/mattpocock-skills:domain-modeling`. Механику сверки несёт
шаблон операции — обёртка её не пересказывает.

## Вход

Вход навыка — требование владельца: что нужно бизнесу, текстом вызова.

- Требование названо — навык не спрашивает его повторно.
- Вызов пуст — навык задаёт ровно один вопрос «какое требование» и после ответа продолжает
  без повторных вопросов о недостающем вводе.

---

## Порядок

1. **Принять требование** — по правилам раздела «Вход».
2. **Построить предмет прогона** — строку `{YYYYMMDDHHMMSS}-{краткое_описание_на_анг}`:
   штамп `date +%Y%m%d%H%M%S` локального времени в момент вызова и слаг из 2–5 английских слов
   через дефис по смыслу требования. Предмет — адрес прогона, исходная формулировка требованиям
   не адрес; коллизию адреса штамп делает практически невозможной.
3. **Вызвать `/backlog:backlog-generate`** с операцией `requirement-add`, предметом из шага 2
   и значением `requirement` (исходная формулировка владельца). Собранный вызов
   `backlog generate` показывается владельцу целиком до прогона — предмет и слаг правятся
   при подтверждении. Значения `target` операция не принимает: с GitHub она не работает.

---

## Передача исполнения

Вызов этого навыка — заранее данный ответ «исполнить». После успешного порождения навык передаёт
исполнение `/backlog:backlog-run` без повторного вопроса «исполнить либо остановиться».

Стоп-знак принятия карточки BR (задача 3.1 шаблона) спрашивает владельца всегда — он принадлежит
шаблону и исполнителю, обёртка его не снимает.

---

## Отказы

Отказы передаются владельцу как есть, навык не разбирает их сам и не заводит шаблон:

- шаблона `templates/requirement-add.md` нет — отказ навыка `/backlog:backlog-template`;
- порождение не удалось — ввод, дефект шаблона, окружение — отказ `backlog-generate`
  по его таблице исходов;
- адрес занят лежащим беклогом — вопрос «исполнить лежащий либо породить с новым предметом»
  решает владелец.

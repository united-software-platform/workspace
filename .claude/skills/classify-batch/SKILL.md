# Навык classify-batch

Обёртка пакетного карточного прогона классификации: принимает JSON-массив карточек по входному
контракту `tools/classifier/docs/contracts.md` — текстом вызова либо путём к файлу вне
репозитория — и без веб-поиска и обогащения прогоняет каждую карточку фоновым агентом,
сводя итог в один файл `projects/{штамп}.json`. Сам навык не порождает беклоги
и не классифицирует — элементы пакета исполняют фоновые агенты операцией
`classify-card-auto`.

## Вход

Вход навыка — карточки: JSON-массив, каждый элемент — карточка по входному контракту
`tools/classifier/docs/contracts.md` (`purpose` обязателен, `facets` опционален). Два способа
задать состав пакета:

- **Массив текстом вызова** — вызов навыка несёт JSON-массив карточек; навык принимает его
  как состав пакета и не переспрашивает состав.
- **Путь к файлу** — вызов называет путь к JSON-файлу массива карточек вне репозитория;
  навык читает массив из файла и принимает его как состав пакета.

Модель исполнителя и порог принимаются из вызова с умолчаниями: уровень модели `haiku`
(`sonnet`, `opus`, `fable` — по названию; уровень разрешается платформой через
`ANTHROPIC_DEFAULT_<УРОВЕНЬ>_MODEL`, навык передаёт уровень, а не ID модели), порог `0.5`.
Повторять enrich-опрос ради двух значений не нужно: карточный прогон адресован сценаристу,
а не диалогу.

## Порядок

1. **Принять массив** — по правилам раздела «Вход»; состав пакета несёт сам вход.
2. **Нормализовать массив** — каждый элемент проверяется: это объект с непустым `purpose`.
   Элемент без `purpose` не отбрасывается молча: прогон останавливается до запуска агентов
   с перечнем бракованных индексов (счёт с нуля). Одна бракованная карточка останавливает
   весь прогон: молчаливый пропуск искажал бы состав пакета, а исправить одну карточку
   до старта дешевле повторного прогона.
3. **Проверить окружение** — заданы `EMBEDDINGS_BASE_URL`, `EMBEDDINGS_API_KEY`,
   `EMBEDDINGS_MODEL`; выгрузка `tools/classifier/taxonomy/` закоммичена
   (`git status --porcelain` пуст). Переменные веб-поиска не проверяются и не нужны.
   При отсутствии — стоп с названным препятствием, агенты не запускаются.
4. **Построить штамп пакета** — `date +%Y%m%d%H%M%S` локального времени в момент запуска.
5. **Разложить карточки** — оркестратор записывает каждую карточку файлом
   `projects/{штамп}.cards/item-NN.json` (NN — двузначный порядковый номер с единицы,
   в порядке массива) до запуска агентов: агент получает карточку путём файла,
   а не телом задачи — в истории агента не остаётся дубля данных карточки.
6. **Запустить фоновых агентов** — по одному на карточку, параллельно, инструментом `Agent`:
   `model: <выбранный уровень>`, `subagent_type: claude`. Задача агента — породить и исполнить
   беклог операции `classify-card-auto` по своей карточке: `backlog generate
   --operation classify-card-auto --subject {штамп}-item-{NN} --value
   card_json=<карточка сериализована строкой> --value threshold=<порог> --value
   package_stamp=<штамп> --value item_number=<NN> --value runner_model=<уровень>`, затем
   исполнить его до конца по порядку `/backlog:backlog-run` и вернуть структурный результат.
   Предмет беклога — `{штамп}-item-{NN}`, реальные данные карточки живут во фронтматтере
   и файле карточки.
7. **Собрать результаты** — дождаться всех агентов; агент не смог вернуть результат —
   карточка получает статус `failed` с причиной из отчёта агента либо «агент не вернул
   результат».
8. **Написать итоговый файл** — единственный файл `projects/{штамп}.json`, пишется один раз
   по завершении всех агентов; формат записей — раздел «Контракт записи прогона».
9. **Сообщить итог** — сводный отчёт по разделу «Сводный отчёт».

## Контракт записи прогона

Итоговый файл — JSON-массив записей, по одной на карточку, в порядке входного массива. Поля записи:

| Поле | Состав |
|------|--------|
| `project_name` | Имя проекта из поля `name` карточки |
| `status` | `classified` либо `failed` |
| `source` | Всегда `null` — карточный прогон источник не выбирает |
| `card` | Объект карточки из входного массива |
| `classification` | Итог утилиты целиком; `null` при отказе до классификации |
| `failure_reason` | Причина отказа; `null` при успехе |

Карточки прогона хранятся файлами `projects/{штамп}.cards/item-NN.json` — по одной на карточку;
оркестратор раскладывает их до запуска агентов. Каталог `projects/` игнорируется git: карточки
и итоговый файл содержат данные владельца и в репозиторий не попадают.

## Сводный отчёт

По завершении прогона владелец получает:

- штамп прогона и путь итогового файла;
- по каждой карточке: статус, итоговую классификацию, авторство решений
  (`<уровень>: <значение>`);
- перечень упавших с причинами;
- напоминание: повтор с уточнённой карточкой — новым прогоном, одиночная проверка —
  навыком `classify`.

## Отказы

- Массив не разобран, либо элемент без `purpose` — стоп до запуска агентов, перечень
  бракованных индексов назван владельцу.
- Переменные `EMBEDDINGS_*` не заданы либо таксономия не закоммичена — стоп до запуска
  агентов, препятствие названо.
- Часть агентов упала — прогон завершается полным составом: упавшие карточки в итоговом
  файле со статусом `failed` и причинами; падение одного не останавливает остальных.
- Код `1` (`needs_confirmation`) у элемента — карточка получает статус `failed` с причиной
  `needs_confirmation`, данные классификации сохраняются в записи прогона: дополнить карточку
  владелец может только сам, повторный прогон — его решение.
- Порождение беклога элемента отказало — карточка получает статус `failed` с причиной отказа
  порождения из таблицы исходов `backlog-generate`.

## Против enrich-прогона

| Обстоятельство | Карточный прогон `classify-batch` | Enrich-прогон `classify-batch-enrich` |
|----------------|-----------------------------------|----------------------------------------|
| Состав пакета | JSON-массив карточек — текстом вызова или файлом | Опрос владельца до принятия списка |
| Карточка | Берётся готовой из входа | Составляется агентом по выбранному источнику |
| Веб-поиск и выбор источника | Нет | Есть, переменные `WEBSEARCH_*` обязательны |
| Цикл дополнения | Нет — один вызов утилиты на карточку | Есть — до трёх вызовов на элемент |
| `source` в записи | Всегда `null` | URL выбранного источника |
| Окружение | `EMBEDDINGS_*` и таксономия | `EMBEDDINGS_*`, `WEBSEARCH_*` и таксономия |

Навык выбирает владелец: карточки уже составлены — карточный прогон; данные о проектах
добываются поиском — enrich-прогон.

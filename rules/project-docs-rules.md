# Правила документов проекта

Роль, каркас и голос трёх документов, которыми проект встречает людей: `README.md`, `CONTRIBUTING.md`
и документа кейсов, — связи между ними и блок бейджей `README.md`. Формат любого md-файла задают
[правила документации](./documentation-rules.md); здесь — то, чем эти три документа отличаются от прочих.

## Таблица правил

| ID | Правило |
|----|---------|
| DGN-001 | За каждым документом закреплён один читатель: `README.md` — применяющему систему на основном пути, документ кейсов — применяющему за его пределами, `CONTRIBUTING.md` — правящему систему; чужой материал переносится в документ своего читателя |
| DGN-002 | `README.md` обязателен; `CONTRIBUTING.md` заводится, когда систему правят не те, кто её применяет; документ кейсов — когда работа выходит за основной путь; путь документа кейсов выбирает проект и называет в `README.md` |
| DGN-003 | Каркас `README.md`: «Что нужно», затем `## Шаг N. <действие>` в порядке исполнения, затем «Куда дальше»; после него — только «Ограничения» и «Лицензия» |
| DGN-004 | `README.md` несёт блок бейджей с минимумом «версия и лицензия»; изменяемое значение читается из носителя; отсутствующий обязательный бейдж называется в «Ограничениях»; карта бейджей ведётся в `CONTRIBUTING.md`, если он есть |
| DGN-005 | Шаг `README.md`, у которого есть кейс, заканчивается строкой «Подробнее — кейс N» со ссылкой |
| DGN-006 | Кейс озаглавлен `## Кейс N. <цель от первого лица>` и несёт метки «Когда», «Что делаю», «Что получаю» в этом порядке; дополнительные метки — только после «Что получаю» |
| DGN-007 | Кейсы нумеруются сквозь документ; перенумерация правит ссылки «Подробнее — кейс N» той же правкой |
| DGN-008 | Каркас `CONTRIBUTING.md`: «Устройство репозитория», «Проверки», «Правила и процесс» в этом порядке; разделы проекта — между первым и вторым; каждая проверка названа одной командой |
| DGN-009 | `README.md` обращается к читателю на «вы», документ кейсов говорит от первого лица «я», `CONTRIBUTING.md` пишется безлично |
| DGN-010 | Норма называется кодом правила со ссылкой и не пересказывается |
| DGN-011 | Перечень, который выдаёт инструмент, в документе не повторяется: документ называет команду, печатающую перечень |
| DGN-012 | Коды возврата команды сопровождаются таблицей «Код / Что значит / Что делаю» |

## Понятия

Жанр документа (Document Genre, DGN) — роль документа, его каркас и голос: кому документ адресован,
из каких разделов и в каком порядке состоит и как обращается к читателю. Коды правил этого документа
несут префикс DGN.

| Понятие | Определение |
|---------|-------------|
| Применяющий систему (System User) | Тот, кто устанавливает систему и пользуется ею, не меняя её исходников |
| Правящий систему (System Maintainer) | Тот, кто меняет исходники, проверки и порядок выпуска системы |
| Основной путь (Main Path) | Последовательность действий, после которой применяющий систему получает её главный результат; один путь на систему, без ветвлений |
| Кейс (Case) | Задача применяющего систему за пределами основного пути, записанная от первого лица: когда она возникает, что он делает и что получает |
| Документ кейсов (Case Document) | Документ, собирающий кейсы системы; путь к нему выбирает проект |
| Носитель значения (Value Carrier) | Файл репозитория или опубликованный артефакт, из которого бейдж читает изменяемое значение |

## Границы нормы

Норма действует для трёх документов: `README.md`, `CONTRIBUTING.md` и документа кейсов. Правила,
точки входа агентов (`CLAUDE.md`, `AGENTS.md`) и прочие документы проекта ею не покрываются.

Имена `README.md` и `CONTRIBUTING.md` в корне проекта — соглашение платформ размещения репозиториев,
а не раскладка проекта: норма называет их по имени. Путь документа кейсов выбирает проект.

Каркас задаёт порядок содержательных разделов. Служебные элементы файла — заголовок, назначение
и навигация по [DOC-014](./documentation-rules.md#структура-файла), таблица версий по
[DOC-022](./documentation-rules.md#жизненный-цикл-документа) — в каркас не входят и стоят на своих
местах.

> **Внимание:** машинной проверки нормы нет: каркас и голос проверяются чтением. Аудит и правку
> документов по норме выполняет навык [`project-docs`](../.claude/skills/project-docs/SKILL.md).

## Роли читателей [DGN-001]

**[DGN-001]** У каждого документа один читатель:

| Документ | Читатель | Что он ищет |
|----------|----------|-------------|
| `README.md` | Применяющий систему на основном пути | Как получить главный результат |
| Документ кейсов | Применяющий систему за пределами основного пути | Как решить свою задачу, когда основного пути мало |
| `CONTRIBUTING.md` | Правящий систему | Где что лежит, как проверить правку, какие нормы действуют |

Материал, адресованный другому читателю, переносится в его документ, а в источнике остаётся ссылка
по [DOC-023](./documentation-rules.md#жизненный-цикл-документа).

Назначение каждого документа называет его читателя и документы, заведённые для других ролей:
дочитав назначение, читатель знает, туда ли он попал и куда идти, если нет.

Нарушение — в `README.md` устройство сборки, нужное только правящему систему:

```markdown
## Шаг 3. Выгрузить каталог

Сборка выпуска идёт в два задания: `build` собирает бинарник, `publish` выкладывает архив.
```

Правильно — материал перенесён, в `README.md` осталась ссылка:

```markdown
Как собирается выпуск — в `CONTRIBUTING.md`.
```

## Заведение документов [DGN-002]

**[DGN-002]** Состав документов определяется тем, кто работает с системой:

| Документ | Когда заводится |
|----------|-----------------|
| `README.md` | Всегда |
| `CONTRIBUTING.md` | Систему правят люди, отличные от тех, кто её применяет |
| Документ кейсов | Работа с системой выходит за основной путь `README.md` |

Проект, где систему применяют и правят одни и те же люди, а основной путь исчерпывает работу, ведёт
только `README.md`; отсутствие двух других документов нарушением не считается.

Путь документа кейсов выбирает проект и называет его в «Куда дальше» `README.md` ссылкой: по этой
ссылке документ и находят.

## Каркас README [DGN-003]

**[DGN-003]** Содержательные разделы `README.md` идут в порядке:

1. «Что нужно» — предусловия основного пути.
1. `## Шаг N. <действие>` — по разделу на шаг, в порядке исполнения, нумерация с единицы.
1. «Куда дальше» — документ кейсов, `CONTRIBUTING.md` и команды, печатающие справку.
1. «Ограничения» — по необходимости.
1. «Лицензия» — по необходимости.

Других содержательных разделов в `README.md` нет. Справочный раздел посреди пути — таблица команд,
перечень переменных, описание устройства — нарушает каркас: справочный материал уходит в документ
своего читателя или заменяется командой по [DGN-011](#нормы-и-перечни-инструментов-dgn-010011).

```markdown
# shop-cli

Выгружает каталог товаров магазина в файл CSV или JSON — для маркетплейса или учётной системы.

## Что нужно
## Шаг 1. Установить shop-cli
## Шаг 2. Подключить магазин
## Шаг 3. Выгрузить каталог
## Куда дальше
## Ограничения
## Лицензия
```

## Блок бейджей README [DGN-004]

**[DGN-004]** `README.md` несёт блок бейджей между заголовком и назначением. Разметка блока
и допустимость абсолютных URL — по [DOC-015](./documentation-rules.md#ссылки-doc-015)
и [DOC-005](./documentation-rules.md#разметка-markdown).

Обязательный минимум — **версия проекта** и **лицензия**. Проект добавляет бейджи сверх минимума
по своему усмотрению.

Значение, которое меняется со временем, бейдж читает из носителя значения. Номер, вписанный в URL
изображения вручную, — вторая копия значения, которая разойдётся с носителем при ближайшем выпуске.
Статическим бейдж бывает только для неизменной характеристики — например, лицензии.

```text
Запрещено:  бейдж версии с текстом «v2.3.0», записанным в URL изображения
Правильно:  бейдж версии, читающий номер из файла VERSION в репозитории
Правильно:  статический бейдж лицензии «MIT»
```

Если обязательному бейджу неоткуда взять значение — репозиторий закрыт для анонимного чтения,
носителя версии или файла лицензии нет, — раздел «Ограничения» `README.md` называет, какого бейджа
нет и почему. Молчаливое отсутствие обязательного бейджа — нарушение.

Если проект ведёт `CONTRIBUTING.md`, в нём есть раздел о блоке бейджей с таблицей:

| Бейдж | Источник значения | Режим | Цель ссылки |
|-------|-------------------|-------|-------------|

По этой таблице правящий систему находит бейдж, который сломается при переименовании носителя.
Проект без `CONTRIBUTING.md` не заводит его ради этой таблицы.

## Сшивка шага и кейса [DGN-005]

**[DGN-005]** Шаг `README.md`, у которого есть кейс, заканчивается строкой «Подробнее — кейс N»
со ссылкой на заголовок кейса. Шаг без кейса такой строки не несёт.

```markdown
## Шаг 3. Выгрузить каталог

...

Подробнее — [кейс 2](./docs/use-cases.md#кейс-2-хочу-выгрузить-только-часть-каталога).
```

## Каркас кейса [DGN-006]

**[DGN-006]** Кейс озаглавлен `## Кейс N. <цель от первого лица>` и несёт три метки в порядке:

1. `**Когда.**` — обстоятельство, в котором возникает задача.
1. `**Что делаю.**` — действия и команды.
1. `**Что получаю.**` — результат, по которому видно, что задача решена.

Кейс без любой из трёх меток — нарушение. Дополнительные метки вида `**<Обстоятельство>.**` —
например `**Если не вышло.**` — допускаются только после «Что получаю»; их состав открыт.

```markdown
## Кейс 2. Хочу выгрузить только часть каталога

**Когда.** Маркетплейсу нужна одна категория, а не весь каталог.

**Что делаю.** Передаю категорию ключом: `shop-cli export --category shoes --out shoes.csv`.

**Что получаю.** Файл `shoes.csv` с товарами одной категории.
```

## Нумерация кейсов [DGN-007]

**[DGN-007]** Кейсы нумеруются сквозь документ с единицы, без пропусков и без перезапуска нумерации
в разделах. Вставка кейса, сдвигающая номера последующих, правит ссылки «Подробнее — кейс N»
в `README.md` той же правкой.

## Каркас CONTRIBUTING [DGN-008]

**[DGN-008]** Обязательные разделы `CONTRIBUTING.md` идут в порядке:

1. «Устройство репозитория» — что где лежит.
1. Разделы проекта в свободном составе — например окружение разработки или блок бейджей
   по [DGN-004](#блок-бейджей-readme-dgn-004).
1. «Проверки» — каждая проверка названа одной командой.
1. «Правила и процесс» — нормы, которым подчиняется правка, кодами по
   [DGN-010](#нормы-и-перечни-инструментов-dgn-010011).

````markdown
## Проверки

```bash
make test                    # модульные тесты
sh tools/make-lint/check.sh  # объём секций Makefile
```
````

## Голос документа [DGN-009]

**[DGN-009]** Голос задан читателем документа:

| Документ | Голос | Пример |
|----------|-------|--------|
| `README.md` | Обращение на «вы» | «Установите shop-cli и подключите магазин» |
| Документ кейсов | Первое лицо «я» | «Хочу выгрузить только часть каталога» |
| `CONTRIBUTING.md` | Безлично | «Проверка запускается командой `make test`» |

Кейс, сформулированный описанием функции — «система позволяет выгрузить категорию», — нарушает голос.

## Нормы и перечни инструментов [DGN-010..011]

**[DGN-010]** Документ называет норму кодом правила со ссылкой на него и не пересказывает её
своими словами: пересказ — вторая копия правила, расходящаяся с ним при первой правке.

```text
Запрещено:  Заголовок коммита начинается с кода задачи и трёхзначного номера.
Правильно:  Формат сообщения коммита — [GIT-009](./rules/git-rules.md#формат-сообщения-коммита).
```

**[DGN-011]** Перечень, который печатает инструмент, — цели `make help`, ключи `--help`, — в документе
не повторяется. Документ называет команду, которая перечень выводит.

## Коды возврата [DGN-012]

**[DGN-012]** Документ, называющий коды возврата команды, сводит их в таблицу с действием читателя
на каждый код:

| Код | Что значит | Что делаю |
|-----|------------|-----------|
| `0` | Выгрузка прошла проверку | Отправляю файл |
| `1` | В выгрузке есть товары без цены | Исправляю цены в магазине и выгружаю снова |
| `2` | Файл не найден или не читается | Проверяю путь к файлу |

Голос колонки «Что делаю» следует голосу документа по [DGN-009](#голос-документа-dgn-009).

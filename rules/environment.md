# Правила окружения

Единый стандарт окружения зонтичного репозитория workspace: mise — единственный менеджер —
закрепляет инструментарий, задачи и демоны сервисов общего набора; порты и переменные
подключения стандартизованы, дочерние проекты подключаются через каскад mise.

## Таблица правил

| ID | Правило |
|----|---------|
| ENV-001 | Инструментарий закрепляется в `mise.toml`: рантайм проекта, CLI процесса разработки и supervisor демонов (`pitchfork`); харнессы (claude, codex, dsh) не закрепляются и поставкой не навязываются |
| ENV-002 | Долгоживущие сервисы объявляются демонами mise в `mise.toml`: PostgreSQL — нативный пресет без контейнерного рантайма, OpenSearch и MinIO — демоны docker-запуска под docker/podman; k3s, helm и Docker Compose не используются |
| ENV-003 | Демоны слушают фиксированные localhost-порты (PostgreSQL — 5432, OpenSearch — 9200, MinIO — 9000), объявленные в `mise.toml`; туннели и проброс портов не требуются |
| ENV-004 | Состояние сервисов (каталоги данных, креды, версии) декларируется декларациями демонов и переменными окружения, а не ручными командами в запущенных сервисах |
| ENV-005 | Несекретные координаты подключения (`PG_PORT`, `OPENSEARCH_PORT`, `MINIO_PORT`) — секция `[env]` файла `mise.toml` (умолчания живут в инструментах: `[env]` перекрывает process-окружение); секреты — git-ignored `.env`, подключаемый через `_.file`; шаблон `.env.example` перечисляет имена секретных переменных |
| ENV-006 | Задачи окружения — задачи mise (`mise run`), идемпотентные и вызываемые по отдельности, включая `env-up`, `env-down`, `env-status`; Makefile не используется |
| ENV-007 | Дочерние проекты потребляют общий набор сервисов через каскад mise; изоляция — общий экземпляр сервиса с разделением данных внутри него (отдельные БД, префиксы индексов, бакеты); выделенный экземпляр — собственная декларация демона в `mise.toml` проекта, осознанное исключение |

## Инструментарий [ENV-001]

**[ENV-001]** Инструментарий закрепляется в `mise.toml` и ставится командой `mise install`:
рантайм проекта (`node`, `python`), CLI процесса разработки (`npm:@fission-ai/openspec`)
и supervisor демонов общего набора (`pitchfork`). Харнессы — claude, codex, dsh —
не закрепляются: выбор агента остаётся за пользователем, окружение его не навязывает.
Состав закреплённого — минимальный: каждый новый инструмент обосновывается потребностью
задачи, а не «пригодится».

---

## Сервисы [ENV-002..004]

**[ENV-002]** Долгоживущие сервисы окружения объявляются демонами mise (экспериментальная
фича, включается `experimental = true`; статус принят осознанно). Общий набор — PostgreSQL,
OpenSearch, MinIO — один экземпляр каждого: PostgreSQL — нативный пресет демона (пресет
пинится мажором, минор разрешается свежим), OpenSearch и MinIO — демоны docker-запуска
с закреплёнными тегами образов. Локальный кластер k3s, helm и Docker Compose не
используются: два механизма запуска в одном стандарте запрещены.

**[ENV-003]** Демоны слушают фиксированные порты localhost, объявленные в декларациях
`mise.toml`: PostgreSQL — 5432, OpenSearch — 9200, MinIO — 9000. Доступ с хоста — прямым
обращением по локальному адресу; `kubectl port-forward` и иная туннельная механика не
требуются.

**[ENV-004]** Состояние, необходимое сервису (каталоги данных, креды, версии), декларируется:
каталоги данных — в декларациях демонов (вне git), креды — `.env`, версии — декларациями
демонов. Ручное наполнение запущенных сервисов не воспроизводится и не допускается.

## Переменные окружения [ENV-005]

**[ENV-005]** Несекретные координаты подключения к общему набору объявляются переменными
`PG_PORT`, `OPENSEARCH_PORT`, `MINIO_PORT` в секции `[env]` корневого `mise.toml`; каскад
конфигураций mise доносит их до дочерних проектов. Значения `[env]` перекрывают переменные
process-окружения, поэтому умолчания инструментов в `[env]` не дублируются — они живут
в самих инструментах. Секреты лежат в `.env` (git-ignored), файл подключается записью
`_.file = ".env"` в секции `[env]`. Коммитимый шаблон `.env.example` перечисляет имена
секретных и локальных переменных с пустыми или несекретными значениями; секретные значения
в репозиторий не попадают.

## Задачи [ENV-006]

**[ENV-006]** Задачи окружения объявляются задачами mise в `mise.toml` и запускаются
`mise run <имя>`: подъём и остановка общего набора (`env-up`, `env-down`), статус
(`env-status`), инициализация локальных файлов (`init-*`), openspec-init и задачи
сканирования (tldr-scan, tldr-scan-ext); перечень печатает `mise tasks`. Задачи
инициализации идемпотентны: повторный запуск не перезаписывает существующие локальные
файлы. Makefile в репозитории не используется.

---

## Зонтичная поставка [ENV-007]

**[ENV-007]** workspace — зонтичный репозиторий: общий набор сервисов объявляется демонами
корневого `mise.toml`, дочерние проекты потребляют набор через каскад mise. Ресурсы по
умолчанию шарятся: сервис набора — один экземпляр, проекты разделяются внутри него
(отдельные БД, префиксы индексов, отдельные бакеты). Выделенный экземпляр проекту —
собственная декларация демона в `mise.toml` проекта, осознанное исключение, когда изоляция
важнее экономии ресурсов.

## Ограничения

- Docker или podman — предусловие хоста: под ним исполняются image-демоны (OpenSearch,
  MinIO) и одноразовые прогоны (tldr-сканирование).
- Образ MinIO — собственная сборка форка `united-software-platform/minio` в публичном
  `ghcr.io/united-software-platform/minio`: публичные образы MinIO закрыты во всех каналах
  (Docker Hub удалён, quay — только авторизованный pull), поэтому форк собирает образ из
  исходников upstream-тега; pull анонимный, без логинов.
- OpenSearch требует `vm.max_map_count=262144` на хосте — и под docker
  (`sysctl -w vm.max_map_count=262144`).
- mise daemons — экспериментальная фича: версии mise и pitchfork закреплены, смена формата
  деклараций оформляется отдельным изменением.
- Данные демонов живут в git-ignored каталогах (`.data/`, состояние пресетов) — состояние
  не воспроизводимо из репозитория и не переносится между машинами копированием рабочего
  дерева.

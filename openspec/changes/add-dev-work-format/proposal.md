# Proposal

## Why

История git хранит работу разработчиков россыпью коммитов, а слепок кода (отчёты tldr по способности
`code-scan`) — срез текущего состояния без авторства. Связки «кто что делал» и «на какой код из слепка
это ложится» нет: каждый раз вопрос «что делал разработчик N на проекте» требует ручных git-команд
и сверки путей с отчётами. Нужен описанный контракт выгрузки работы разработчика из git-истории со
связью каждого коммита с кодом из слепка — машиночитаемый вход для дальнейшего анализа (реляционное
хранение, индекс Elastic, LLM-обработка).

## What Changes

- Определяется канонический формат контракта «реализованная работа разработчика»: YAML-документ;
  спецификация — `docs/work-format.md` с вымышленным структурно-идентичным примером.
- Определяется производная JSON-проекция того же контракта для загрузки в Elastic и реляционное
  хранилище; конверсия детерминирована и описана в спецификации.
- Единица работы — коммит, включая merge: `kind: code | integration`, у integration —
  `merged: own | others`.
- Запись коммита несёт статус-лист затронутых путей (A/M/D/R) с numstat и пары «путь ↔ слепок»
  (семантика «присутствует в слепке»; ревизия слепка неизвестна — оговорка в шапке).
- Определяется формат реестра идентичностей (`{slug, имя, emails[], команда}`) и выборка
  `person` или `team`; коммитится шаблон `docs/people.yaml` с вымышленными записями.
- Изменение содержит только документы. Инструмент извлечения выгрузки — отдельное будущее изменение.
- Данные проект-источника (имена, email, пути, отпечатки) в репозиторий не попадают.

## Capabilities

### New Capabilities

- `dev-work-format`: контракт реализованной работы разработчика — структура YAML-выгрузки (шапка
  параметров выборки, записи коммитов с типологией работы, пары «путь ↔ слепок», нормализация путей
  слепка, границы области), формат реестра идентичностей и JSON-проекция.

### Modified Capabilities

- (нет — способность `code-scan` не меняется: слепок потребляется как есть)

## Impact

- Новые файлы: `docs/work-format.md`, `docs/people.yaml` (шаблон реестра).
- Формат опирается на имена отчётов слепка способности `code-scan` (`01-tree.json`,
  `03-structure.json` и другие) как источник пары.
- Исполняемого кода, зависимостей и изменений существующих инструментов нет: tldr, forge и раннер
  не затронуты.

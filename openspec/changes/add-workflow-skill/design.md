# Design

## Context

Операция `workflow` (шаблон `templates/workflow.md` v1.0.0) уже замыкает путь «требование →
задача на GitHub → ветка → прожарка». Порождение и исполнение дают навыки плагина
`backlog@formular` — `/backlog:backlog-generate` и `/backlog:backlog-run`; их поведение менять
нельзя и не нужно: обёртка делегирует, а не дублирует. Разрыв сегодня в двух местах: владелец
собирает запуск вручную, а `subject` шаблона совмещает две роли — адрес прогона и носитель
исходной формулировки, из-за чего первый прогон положил след в каталог с кириллицей и пробелами.
Делегирование построено на контрактах: интроспекция `backlog inspect-template --json` — источник
состава подстановок, приёмка `backlog check-template` — вердикт правки шаблона.

## Goals / Non-Goals

**Goals:**

- Один вызов `/workflow <требование>` запускает операцию целиком: порождение и передачу исполнения.
- Предмет прогона — машиночитаемый адрес `{YYYYMMDDHHMMSS}-{slug}`; формулировка живёт во фронтматтере
  значением `requirement`.
- Правка шаблона проходит приёмку `backlog check-template` и не трогает лежащие беклоги.

**Non-Goals:**

- Не правятся навыки плагина `backlog@formular` и ядро `backlog`: обёртка зовёт их как есть.
- Не меняется состав задач операции после задачи 2.1: GitHub, ветка, прожарка остаются как есть.
- Не перекладывается на обёртку решение о занятом адресе и иные исходы порождения — их разбирает
  `backlog-generate` по своей таблице исходов.

## Decisions

### D1. Обёртка — тонкий проектный навык, а не копия generate

Навык `.claude/skills/workflow/SKILL.md` не порождает беклог и не собирает значения интроспекцией
сам: он принимает требование, строит предмет, предлагает `target` из `git remote get-url origin`
и зовёт `/backlog:backlog-generate`, передавая операцию, предмет и значения. Альтернатива —
обёртка, зовущая `backlog generate` напрямую, минуя навык порождения, — отклонена: она вынудила бы
дублировать показ вызова, таблицу исходов и передачу исполнения, а второй носитель порядка
разошёлся бы при первом же обновлении плагина.

### D2. Требование — значение операции, `subject` — адрес

Шаблон 1.1.0 заводит подстановку `requirement` (`--value requirement="..."`), поле во фронтматтере
и переадресует задачу 2.1 на `{{requirement}}`. Альтернатива — длинный слаг предмета вместо
отдельного значения — отклонена: слаг невыразителен для прожарки (задача 5.1 передаёт ей
формулировку требования), а формулировка во фронтматтере делает беклог самодостаточным (BKL-005)
и исполнимым в другом сеансе без повторного сбора значений.

### D3. Автозапуск исполнения — решение, принятое вызовом

После порождения обёртка передаёт исполнение `/backlog:backlog-run` сама, минуя повторный вопрос
навыка порождения «исполнить либо остановиться»: вызов `/workflow` и есть заранее данный ответ.
Отказы порождения (ввод, дефект шаблона, окружение) передаются владельцу как есть — исполнение
не начинается. Необратимость закрыта стоп-знаком задачи 3.1 шаблона, который спрашивает всегда,
независимо от обёртки.

### D4. Предмет строит обёртка, а не владелец

Штамп берётся `date +%Y%m%d%H%M%S` локального времени в момент вызова; слаг — 2–5 английских слов
через дефис по смыслу требования. Предмет показывается владельцу в составе собранного вызова
`backlog generate` и правится при подтверждении. Коллизию адреса штамп делает практически
невозможной; гипотетический занятый адрес разбирается таблицей исходов `backlog-generate`
вопросом к владельцу — отдельного правила обёртки не заводим.

## Risks / Trade-offs

- [Шаблон правится под обёртку — ручной прогон `backlog generate` без `requirement` невозможен]
  → Приёмка `check-template` требует каждую подстановку группы `values`; вызов без значения
  останавливается ядром с кодом `2` — отказ самодокументирован, а `--help generate` называет
  способ передачи.
- [Обёртка зависит от навыков плагина и их таблицы исходов] → Зависимость объявлена текстом
  навыка; обновление плагина, меняющее исходы порождения, требует сверки обёртки с use-cases.md
  новой версии.
- [Слаг строится по смыслу требования LLM] → Слаг виден владельцу до прогона в показе вызова
  и правится при подтверждении; критерий «2–5 английских слов через дефис» зафиксирован в навыке.

## Migration Plan

1. Правка `templates/workflow.md` до 1.1.0 и приёмка `backlog check-template` — до заведения навыка.
2. Заведение `.claude/skills/workflow/SKILL.md`.
3. Откат — обратный порядок: удаление навыка, возврат шаблона к 1.0.0; лежащие беклоги не
   затрагиваются ни прямым, ни обратным ходом.

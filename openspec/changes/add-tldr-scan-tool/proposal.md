# Proposal

## Why

Скрипт сканирования проекта образом tldr (`tools/tldr-scan.sh`) появился в проекте отдельным файлом
в корне `tools/`, вне принятой раскладки инструментов, и запускается только вручную на хосте: агенту
в контейнере недоступны ни `docker`, ни `make`. Изменение оформляет сканирование как инструмент проекта —
со своим каталогом, целью `make` и вызовом агентом через раннер на хосте, — чтобы отчёты tldr можно
было получать и разбирать, не выходя из сессии агента.

Проект использует установленный SDD Developer Kit 1.5.0: `Makefile`, `.env.example` и файлы раннера
`tools/host-runner/` принадлежат kit'у и записаны в `.sdd-kit-manifest.json` с контрольными суммами.
Поэтому сканирование встраивается в них так же, как Liquibase Forge, — помеченными блоками, а не правкой
содержимого kit'а.

## What Changes

- Скрипт переносится из `tools/tldr-scan.sh` в `tools/tldr/scan.sh` — по раскладке остальных
  инструментов: каталог назван по инструменту, файл — по действию (`tools/make-lint/check.sh`,
  `tools/forge-env/up.sh`). Строка использования в скрипте указывает новый путь.
- Рядом со скриптом появляется `tools/tldr/README.md`: назначение, настройка, вызов человеком и агентом,
  перечень отчётов, коды возврата и ограничения.
- В `Makefile` блоком `# >>> tldr-scan` … `# <<< tldr-scan` добавляется цель `tldr-scan`: сканирует корень
  проекта, складывает отчёты в `reports/tldr`, образ, расширение дерева файлов и скрываемые каталоги
  берёт из `TLDR_IMAGE`, `TLDR_EXT`, `TLDR_EXCLUDE` — из окружения либо из `.env`. Каталог отчётов
  всегда скрыт от анализа.
- Блоками `# >>> tldr-scan` дополняются `.env.example` (три переменные `TLDR_*` с пустыми значениями,
  `TLDR_EXCLUDE` — список через запятую) и `.gitignore` (`/reports/tldr/`).
- Блок `# >>> tldr-scan` в `tools/host-runner/runner.py` расширяет белый список раннера целью `tldr-scan`,
  не трогая литерал `ALLOWED_TARGETS`: агент вызывает её командой `tools/host-runner/call.sh tldr-scan`.
- Прямые правки файлов kit'а, внесённые до оформления изменения, заменяются блоками: перечень `.PHONY`
  и литерал `ALLOWED_TARGETS` kit'а возвращаются к исходному виду, `tools/host-runner/README.md`
  возвращается к версии kit'а целиком.

## Capabilities

### New Capabilities

- `code-scan`: сканирование кода проекта образом tldr — набор команд по уровням, изоляция проекта
  от записи, настройка через окружение, расположение отчётов, коды возврата, запуск агентом через раннер
  на хосте и встраивание в файлы kit'а только помеченными блоками.

### Modified Capabilities

Нет: спецификаций в `openspec/specs/` пока нет.

## Impact

- Код: `tools/tldr-scan.sh` → `tools/tldr/scan.sh`; блоки в `Makefile` и `tools/host-runner/runner.py`.
- Документация и конфигурация: новый `tools/tldr/README.md`; блоки в `.env.example` и `.gitignore`;
  `tools/host-runner/README.md` остаётся файлом kit'а без изменений.
- Kit: содержимое файлов kit'а вне блоков `tldr-scan` не меняется, обновление kit'а не затирает
  интеграцию и не конфликтует с ней сильнее, чем с блоками Liquibase Forge.
- Права агента: раннер расширяет их на запуск контейнеров образа tldr на хосте. Проект монтируется
  в них только для чтения; в рабочее дерево цель пишет лишь `reports/tldr`.
- Зависимости: на хосте нужны `docker` и доступ к реестру образа
  `ghcr.io/united-software-platform/tldr-code`.
- Исходное состояние: скрипт добавлен в индекс незакоммиченным; цель, переменные, запись `.gitignore`
  и белый список раннера внесены прямыми правками и проверены прогоном через раннер — 17 из 18 команд
  выполнены, `inheritance` упала на файле больше 5 МБ.

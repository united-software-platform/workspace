# Proposal

## Why

Аудит выгрузки таксономии SPCF (`tools/classifier/taxonomy/`) навыком domain-modeling выявил дефекты модели: расхождение канонического имени уровня L3 между документами, необъявленное в контракте данных поле `aliases`, выведенный идентификатор в собственном примере таксономии, отсутствие правила выбора для сквозной записи L1 и асимметрию описаний SOL-035. Дефекты ломают согласованность модели, по которой работает классификатор, и делают выгрузку частично невалидируемой по собственному контракту `data_model.json`. Задача WRSP-027 (issue #19).

## What Changes

- Выбирается единое каноническое русское имя уровня L3: «Область проблем» (как в `structure.json` — документе, вводящем понятие); в `classification_rules.json` имя «Область проблемы» приводится к нему.
- Поле `aliases` объявляется в контракте данных (`data_model.json`) для всех четырёх сущностей уровней; семантика алиаса (поглощённый идентификатор, разрешаемый к канонической записи) фиксируется в `structure.json`.
- В примере «Pinecone Goods» выведенный идентификатор `SUB-019` заменяется каноническим `SUB-020`: примеры демонстрируют канонические присваивания, разрешение алиасов — обязанность потребителя.
- В `classification_rules.json` фиксируется правило приоритета для L1: при конфликте отраслевой записи и сквозной функциональной записи (DOM-017 «Аналитика и отчётность») отрасль занимает primary, сквозная функция — secondary.
- Английское описание SOL-035 выравнивается к русскому (ЭЦП, реестры имущества и получателей поддержки, аналитика использования).
- Косметика: единый порядок полей записей L2/L4, code записи DOM-017 остаётся `analytics-reporting`; code DOM-003 дополняется до `commerce-and-trade`.

## Capabilities

### New Capabilities

_Нет._

### Modified Capabilities

- `classifier-taxonomy`: меняются требования к целостности выгрузки — каноническое единство имён уровней, объявление `aliases` в контракте данных, канонические идентификаторы в примерах, правило приоритета primary для сквозных записей L1, симметрия двуязычных описаний записей.

## Impact

- Файлы выгрузки: `tools/classifier/taxonomy/structure.json`, `classification_rules.json`, `data_model.json`, `example_project.json`, `l4_solution_archetypes.json`, `l2_activity_subdomains.json`, `l1_application_domains.json`.
- Тесты загрузки таксономии: проверка полей по контракту начинает требовать объявления `aliases`.
- Потребители выгрузки: строгое чтение по контракту перестаёт отвергать записи с алиасами; поиск по идентификатору в примерах даёт только канонические ссылки.
- Не меняется: состав и количество записей уровней, счётчики манифеста, идентификаторы канонических записей, поведение прогонов классификации.

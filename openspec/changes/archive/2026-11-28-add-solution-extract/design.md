# Design

## Context

Мотивация — в proposal.md, раздел Why. Навык строится как собственный навык репозитория по образцу
`requirement-add`, но без делегирования плагину backlog. Нормы, на которые опирается навык,
подключены в `AGENTS.md`: гейт чтения READ, границы git, оформление документов DOC, объявление
предмета PLG. Понятия — в `GLOSSARY.md`. Образец пакета —
`docs/solutions/PS-001-plugin-skills-setup.md`, созданный пробой и принятый владельцем.

## Goals / Non-Goals

**Goals:**

- Один файл-навык и один шаблон: чтобы поправить механизм, не нужно трогать плагин backlog.
- Пакет собирается по шаблону: состав частей фиксирован, работа идёт с источником, а не с формой.
- Навык проверяет черновик до показа владельцу — править до стоп-знака дешевле.

**Non-Goals:**

- Машинная проверка пакетов (структура, ссылки на функции) — после пилотов.
- Поиск по пакетам (BR-004) и индекс фонда.
- Возобновление прогона после обрыва сессии.

## Decisions

1. **Навык без операции беклога.** Альтернатива — полная операция по образцу `requirement-add`:
   шаблон в `templates/`, `backlog generate`, свидетельство в `backlog/`. Выбран навык: продукт
   прогона — сам файл пакета, процесс живёт в диалоге, а свидетельство не даёт пакету ничего сверх
   его таблицы версий. Проба PS-001 прошла именно так.

2. **Шаблон пакета — в каталоге навыка, а не в `templates/`.** Каталог `templates/` — домен шаблонов
   операций беклога; шаблон пакета там был бы принят за операцию. В каталоге навыка шаблон
   путешествует вместе с ним.

3. **Вторая точка входа — симлинк.** `.zcode/skills/solution-extract` ссылается на
   `.claude/skills/solution-extract`, как у `classify` и `domain-layout`: правится один файл,
   копии не расходятся.

4. **Стоп-знак на черновике пакета, без карточки сущности.** Альтернатива — карточка на одну
   страницу, затем пакет (ранняя договорённость прожарки). Черновик пакета — около 170 строк,
   отдельная карточка повторяла бы его.

5. **Исполнение — для спорных утверждений, а не для всех строк.** Альтернатива — сверка с
   источником исполнением для всех сценариев, как в слепой проверке. Полная сверка удваивает
   работу прогона; трёх сверок чтением достаточно, исполнение подключается там, где чтение
   оставляет сомнение. В пробе так найден дефект `canonical` в `setup.sh`.

6. **Сценарии приёмки — в формате openspec.** `Scenario`, `WHEN`, `THEN`, по одной паре шагов на
   сценарий — тот же вид, что в `openspec/specs/`: читатель владеет нотацией, сценарий проще
   перенести в спеку или тест.

7. **Статусы пакета: `Proposed`, `Accepted`, `Superseded`.** `Proposed` — записан после стоп-знака,
   `Accepted` — после взгляда владельца, `Superseded` — заменён другим пакетом. Номер пакета не
   переиспользуется.

8. **Блоки схемы — по роли решения, а не по блокам образца.** Первая редакция требования повторяла
   состав PS-001: управление, исполнение, верификация, три границы. Пилот A показал, что для
   клиента это вырождается: тип ошибки попал в «Верификацию», потребители — в «Целевое окружение».
   Теперь схема показывает вход, выход, части решения и границы, а имена берутся из решения;
   отсутствующих частей схема не выдумывает.

9. **«Задача» — три вопроса и границы.** Тот же пилот дал верные таблицы без смысла: не сказано,
   что за инструмент, зачем ему способность и где она стоит. Поэтому состав раздела задан явно.

10. **Известные копии ищутся, а не вспоминаются.** Аудит PS-002: в заголовке стояло «нет», хотя
    детерминированный вектор из хэша реализован дважды — стабом и фейком с разными константами.
    Поэтому поиск параллельных реализаций, включая тестовые двойники, — обязанность навыка.

11. **Четвёртая сверка — «смысл на месте».** Три сверки технические: PS-002 прошёл бы их, не сказав,
    что за инструмент. Сверка проверяет «Задачу» по трём вопросам; «Правила» при этом пишутся
    с причинами и ограничениями.

## Risks / Trade-offs

- [Обрыв сессии до стоп-знака теряет черновик] → Сознательная цена отказа от свидетеля прогона:
  повторный прогон стоит около 170 строк. После стоп-знака состояние живёт в файле пакета.
- [Навык читает лишнее в чужом проекте] → Источник называет владелец; читается только названное
  дерево, история git — только короткий хеш текущего коммита (READ-001, GIT-019).
- [Ссылки на функции устаревают при правках источника] → В заголовке пакета стоит ревизия
  источника; расходение ревизии — сигнал к новому извлечению той же версией пакета.
- [Схема пакета раскладывается по-разному в разных просмотрщиках Mermaid] → Выравнивание схемы
  в задачу не входит: раскладка автоматическая, владелец остановил эту работу как затратную.
- [Схема превышает лимит узлов DOC-018] → Исключение принято владельцем для схем пакетов и
  записано в спеке: число узлов не ограничено.

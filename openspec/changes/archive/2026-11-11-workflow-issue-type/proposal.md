# Proposal

## Why

Операция workflow заводит задачу на GitHub без явного типа: задачи разного назначения
смешиваются, их границы и ожидаемое содержание размываются. Организационные шаблоны задач
уже существуют в `united-software-platform/.github` (каталог `.github/ISSUE_TEMPLATE`) и являются
источником истины, но шаблон операции их не использует.

## What Changes

- Группа 3 «Задача на GitHub» шаблона `templates/workflow.md` перерабатывается с 3 задач
  на 5: определение типа и выбор организационного шаблона, составление черновика по шаблону,
  первая прожарка черновика через `/mattpocock-skills:grilling`, стоп-знак и создание задачи
  с телом из файла черновика и ярлыком из шаблона, сверка созданной задачи.
- Вводится кеш организационных шаблонов `~/.cache/wrsp/issue-templates/`: файлы шаблонов как есть
  (включая `config.yml`) и JSON-метаданные (репозиторий-источник, SHA `main`, время получения UTC,
  перечень файлов). Кеш — вне репозитория, не коммитится, не правится вручную.
- Во фронтматтер порождённого беклога добавляются значения `issue_type` (имя выбранного
  организационного шаблона) и `issue_draft` (заполненный черновик после первой прожарки).
- Задача 5.1 передаёт прожарке формирования изменений контекст задачи целиком: тип, черновик,
  `issue_url` и `branch` — дальнейшая прожарка начинается с конкретного черновика, а не с пустого
  описа́ния.

## Capabilities

### New Capabilities

- Нет. Поведение принадлежит существующей спеке `dev-workflow` — её требования меняются.

### Modified Capabilities

- `dev-workflow`: требование «Контракт шаблона операции workflow» дополняется типом задачи,
  кешем организационных шаблонов, значениями `issue_type`/`issue_draft` и передачей черновика
  в прожарку шага 5; требование «Исполнение без повторного вопроса» сохраняется — стоп-знак
  остаётся, но сдвигается на задачу 3.4 после первой прожарки.

## Impact

- `templates/workflow.md` — шаблон операции workflow; версия поднимается выше 1.2.0. Приёмка
  `backlog check-template` обязательна (код возврата `0`).
- `/app/.claude/skills/workflow/SKILL.md` — не изменяется: обёртка состава задач не несёт.
- Порождённые беклоги: фронтматтер пополняется `issue_type` и `issue_draft` — правка действует
  на следующие порождения, задним числом ничего не меняет.
- Зависимости: доступ к GitHub (`gh api`) для кеша и создания задач; каталог `~/.cache/wrsp/` —
  окружение агента, в репозиторий не попадает.

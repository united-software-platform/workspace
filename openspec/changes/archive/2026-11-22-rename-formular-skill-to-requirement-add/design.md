# Design

## Context

Имя `formular` принадлежит плагину исполняемого беклога (`formular/backlog` 1.4.0 — провайдер
`/backlog:backlog-generate`, `/backlog:backlog-run`, `/backlog:backlog-template`); операции
`workflow` и `classify` исполняются тем же плагином, не заимствуя его имя. Имя файла шаблона —
ключ операции: `backlog generate --operation <имя>` читает
`templates/<имя>.md`. Навык-обёртка лежит в каталоге своего имени в двух точках входа
(`.claude/skills/`, `.zcode/skills/`), capability носит имя операции с суффиксом
`-operation`. Коммит `fa8bac7` ввёл всё это под именем `formular`; лётный change
`add-multilevel-requirements-validation` адресует старое имя и перебазируется вместе
с переименованием.

## Goals / Non-Goals

**Goals:**

- Одно новое имя `requirement-add` на точке входа, операции, шаблоне и capability.
- Чистая запись переименования в openspec: REMOVED старой capability + ADDED новой
  с Reason/Migration.

**Non-Goals:**

- Изменение поведения: состав задач шаблона, поля карточки, порядок исполнения — без правок.
- Перенос свидетельств прошлого: `backlog/formular/20261121234009-past-work-search/`,
  формулировки «операцией formular» в `docs/requirements/BR-001.md`, архив `add-formular-skill`.
- Правка записей в `openspec/changes/archive/`.

## Decisions

### D1. Операция переименовывается вместе со шаблоном

Имя файла шаблона — ключ операции беклог-плагина; переименовать файл, не переименовав
операцию, нельзя. Отдельного решения об операции не требуется — оно механически задано
переименованием шаблона.

### D2. Capability — REMOVED + ADDED, не правка на месте

Путь каталога capability меняется только заведением новой: дельта снимает все девять
требований `formular-operation` (REMOVED с Reason/Migration) и заводит
`requirement-add-operation` с теми же требованиями под обновлёнными именами. *Альтернатива:*
RENAMED-требования внутри старой capability — не меняет путь каталога спеки, имя каталога
осталось бы прежним навсегда.

### D3. Свидетельства прошлого не переписываются

Прогон `backlog/formular/…`, «операцией formular» в BR-001 и архив `add-formular-skill` —
записи о событиях под старым именем; переименование их не ретроспективит. *Альтернатива:*
правка под новое имя — ломает неизменность свидетельства и обесценивает стоп-знак прогона.

### D4. Живые ссылки обновляются

Docstring `reqlint.py` («Вызов в операции formular») и заголовок `rules.yml` («для операции
formular») смотрят в будущее — как пользоваться инструментом, — и зовут новое имя операции.

### D5. Версии: SKILL.md — 1.0.2, шаблон — без bump

Переименование навыка — частичное изменение (1.0.1 → 1.0.2 с записью в таблице версий).
Содержание шаблона не меняется — `template_version` 1.2.0 сохраняется при переносе файла.

## Risks / Trade-offs

- [Старая точка вызова `/formular` пропадает] → вызовов вне репозитория нет: переименование
  идёт сразу после вводного коммита; списки навыков агентов обновляются вместе
  с каталогами.
- [После архивации `formular-operation` может остаться пустым каталогом в `openspec/specs/`] →
  проверка после архивации в tasks; пустой остаток удаляется руками.
- [Лётный `add-multilevel-requirements-validation` адресует старое имя] → перебазируется
  в этом же ходе; применяется строго после переименования.

## Migration Plan

Закоммиченные пути переносятся `git mv` (навык, шаблон), локальный `.zcode` — обычным
перемещением (каталог в gitignore). Справочник спек обновляется при архивации change.
Откат — `git revert` коммита переименования; свидетельства прошлого отката не требуют.

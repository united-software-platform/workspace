# Design

## Context

Мотивация — в [proposal.md](./proposal.md#why), требования — в [specs/code-scan/spec.md](./specs/code-scan/spec.md).

Исходное состояние рабочего дерева:

- `tools/tldr-scan.sh` добавлен в индекс, не закоммичен. Строка использования указывает
  `scripts/tldr-scan.sh` — путь, под которым скрипт копировался в сторонний проект.
- Прямыми правками внесены: цель `tldr-scan` в `Makefile` (включая перечень `.PHONY` kit'а),
  переменные `TLDR_*` в `.env.example`, `/reports/tldr/` в `.gitignore`, `tldr-scan` в литерал
  `ALLOWED_TARGETS` в `tools/host-runner/runner.py`, строки о цели в `tools/host-runner/README.md`.
- Цель проверена прогоном через раннер. Подтверждено: рабочий каталог образа — `/project`,
  ENTRYPOINT — `tldr`, монтирование `:ro` и uid хоста не мешают командам. Упала только `inheritance`:
  tldr отказывается разбирать файл больше 5 242 880 байт.

Ограничения:

- Проект — установка SDD Developer Kit 1.5.0. Файлы kit'а записаны в `.sdd-kit-manifest.json`
  с sha256. Прецедент встраивания — Liquibase Forge: блоки `# >>> liquibase-forge` … `# <<< liquibase-forge`
  в `Makefile`, `.env.example`, `.gitignore`, `runner.py`. Без своего блока `runner.py` совпадает
  с хэшем манифеста.
- Раннер передаёт только имя цели, без параметров, и выполняет `make` в корне проекта на хосте.
- Раннер загружает `.env` командой `.` при старте: значение с пробелом без кавычек ломает загрузку.
- Секция цели `Makefile` — не больше 30 строк ([MAKE-001](../../../rules/makefile-rules.md#норма-объёма-секции-make-001)).

## Goals / Non-Goals

**Goals:**

- Сканирование вызывается одной командой и человеком на хосте, и агентом через раннер.
- Интеграция переживает обновление kit'а: содержимое kit'а не меняется вне блоков `tldr-scan`.
- Настройки под язык проекта задаются в `.env`, без правки `Makefile`.

**Non-Goals:**

- Устранение отказа `inheritance` на файлах больше 5 МБ: это предел tldr, обход — `TLDR_EXCLUDE`.
- Передача параметров сканирования через раннер: раннер параметров не принимает намеренно.
- Закрепление версии образа tldr по digest.
- Разбор и устранение находок сканирования.
- Перенос инструмента в репозиторий kit'а.

## Decisions

### Каталог `tools/tldr/`, файл `scan.sh`

Каталог назван по инструменту, файл — по действию: так устроены `tools/make-lint/check.sh`,
`tools/forge-env/up.sh`, `tools/liquibase/gateway.py`. Перенос — `git mv`, чтобы git видел
переименование.

Альтернатива — `tools/tldr-scan/scan.sh`: повторяет действие в имени каталога и файла.

### Встраивание блоками `# >>> tldr-scan`

Решение пользователя по прецеденту Liquibase Forge. В `runner.py` блок стоит после литерала
и после блока `liquibase-forge` и расширяет множество: `ALLOWED_TARGETS = ALLOWED_TARGETS | frozenset({"tldr-scan"})`.
Литерал и перечень `.PHONY` kit'а возвращаются к исходному виду; у блока в `Makefile` свой `.PHONY`.

Альтернативы: прямая правка файлов kit'а (затирается обновлением kit'а, расходится с манифестом);
перенос в kit (отклонён пользователем).

### Документация в `tools/tldr/README.md`, README раннера не трогается

`tools/host-runner/README.md` — документ kit'а, блоков в нём нет, и любая правка расходится
с манифестом. Цель `tldr-scan` описывается в README инструмента: туда же ведёт ссылка
из комментария блока в `runner.py`. Файл следует [DOC-014](../../../rules/documentation-rules.md#структура-файла);
таблицу версий `README.md` не ведёт по исключению [DOC-022](../../../rules/documentation-rules.md#жизненный-цикл-документа).

### Настройки: окружение, затем `.env`, затем умолчание скрипта

Тот же порядок, что у `openspec-init`: ручной запуск `TLDR_EXT=.go make tldr-scan` перекрывает `.env`.
Значение из `.env` читается построчно через `sed`, а не через `include`: секреты `.env` не попадают
в пространство имён `make`. Блок определяет собственный разборщик, а не вызывает `env_value` kit'а:
блок не зависит от внутренних имён `Makefile` kit'а.

Альтернатива — загрузка `.env` в рецепте командой `.`, как у целей Liquibase Forge: экспортирует все
секреты в окружение процесса `docker`, а это шире, чем нужно трём переменным.

### `TLDR_EXCLUDE` — список через запятую

Раннер загружает `.env` командой `.`: `TLDR_EXCLUDE=.idea backlog` выполнил бы `backlog` как команду,
а кавычки разборщик через `sed` вернул бы вместе со значением. Запятая безопасна для обоих способов
чтения; цель переводит её в пробелы для скрипта. Тот же приём — `FORGE_TEST_DB_ALLOWLIST`.

### Отчёты в `reports/tldr` рабочего дерева, `reports` всегда скрыт

Агент читает отчёты из контейнера, поэтому они лежат в смонтированном рабочем дереве.
Цель добавляет `reports` к скрываемым каталогам всегда, поэтому умолчание `vendor,public` повторено
в цели: при пустом `TLDR_EXCLUDE` иначе остался бы только `reports`.

Альтернатива — `/tmp` на хосте: агенту недоступен.

## Risks / Trade-offs

- [Раннер держит `TLDR_*` из окружения, прочитанного при старте, а окружение приоритетнее `.env`] →
  `.env.example` и README инструмента требуют перезапуска раннера после правки `TLDR_*`.
- [Предел раннера — 900 секунд на цель; на большом проекте 18 команд и первая загрузка образа могут
  его превысить] → README называет `AGENT_RUNNER_TIMEOUT`; на хосте цель запускается без предела.
- [`inheritance` падает на файле больше 5 МБ, tldr не называет файл] → README описывает обход
  через `TLDR_EXCLUDE` и поиск `find . -type f -size +5M`.
- [Скрипт не передаёт `-w /project` и полагается на `WORKDIR` образа] → подтверждено прогоном;
  при смене образа ошибка проявится сканированием не того каталога. Устранение — вне изменения.
- [Обновление kit'а, переписывающее файл целиком, может удалить блоки] → тот же риск у блоков
  Liquibase Forge; блоки восстанавливаются повторением их содержимого из `tools/tldr/README.md`.
- [Тег образа `latest` не закреплён] → `TLDR_IMAGE` позволяет закрепить тег или digest.

## Migration Plan

1. Закоммитить исходное состояние по [GIT-020](../../../rules/git-rules.md#гейт-редактирования):
   у файлов, которые меняет изменение, есть незакоммиченные правки.
1. Перенести скрипт и заменить прямые правки блоками.
1. Перезапустить раннер на хосте: белый список читается при старте.
1. Проверить прогоном `tools/host-runner/call.sh tldr-scan`.

Откат: удалить блоки `tldr-scan` и каталог `tools/tldr/`, перезапустить раннер.

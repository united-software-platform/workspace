# Design

## Context

Контракт навыка `grilling` (плагин mattpocock-skills 1.3.2): допрос раундами — каждый раунд
задаёт пронумерованные вопросы фронтира дерева решений с рекомендованным ответом и ждёт
ответов; факты выясняет сам (саб-агенты), решения — за владельцем; конец — пустой фронтир
и подтверждённое общее понимание. Задача 2.2 шаблона 1.3.0 называет навык, но описывает
ручную механику и не передаёт намерение.

## Goals / Non-Goals

**Goals:**

- Задача 2.2 = вызов навыка с намерением; разнос ответов раундов по девяти полям —
  за исполнителем.

**Non-Goals:**

- Состав полей, правило номера BR-NNN, запреты выдумывать; линтинг (2.4–2.5) и стоп-знак (3.1).

## Decisions

### D1. Намерение = значение `requirement` + формулировка задачи 2.1

Значение фронтматтера — исходная формулировка владельца; формулировка 2.1 — уже согласованная
с владельцем краткая версия. Вместе они вход навыка. *Альтернатива:* передавать только
`requirement` — отвергнута: согласованная формулировка 2.1 уже существует, выбрасывать её
из вызова расточительно.

### D2. Термины контракта — одной строкой

«Фронтир» и «раунды» упоминаются в задаче кратко; полный контракт несёт сам навык, шаблон
его не пересказывает — тот же паттерн, что у носителя порядка исполнения (BKL-008).

### D3. Сборка карточки — за исполнителем

Навык про девять полей карточки не знает: он grilled понимание, а разнос ответов по полям
и запись `br_card` выполняет исполнитель беклога.

## Risks / Trade-offs

- [Раунды навыка могут выйти за пределы карточки — в дизайн решения] → конец по пустому
  фронтиру, запрет выдумывать, стоп-знак возвращает карточку на правку.

## Migration Plan

Шаблон 1.3.0 → 1.4.0, обратно совместимо: лежащие беклоги не перегенерируются. Откат —
возврат задачи 2.2 к прежней формулировке в истории git.

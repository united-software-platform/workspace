# Design

## Context

Набор кита подключает правила `@`-импортами в двух точках входа — `CLAUDE.md` и `AGENTS.md`;
перечень в них поддерживается одинаковым (см. историю версий обоих файлов). Мотивация сужения
состава — в [proposal.md](./proposal.md), раздел Why. Спеки openspec с удаляемыми документами
не связаны: retire_capabilities и правки спек не требуются.

## Goals / Non-Goals

**Goals:**

- Сузить состав правил кита до пяти документов; обе точки входа правятся синхронно одной правкой.
- Сохранить историю: записи таблиц версий не переписываются, добавляются новыми строками.

**Non-Goals:**

- Внедрение `GLOSSARY.md` и механизма внешнего навыка `domain-modeling` — отдельная работа
  владельца, не часть этого изменения.
- Изменение операций и их спек: `requirement-add-operation` и остальные десять спек не меняются.

## Decisions

1. **Полное удаление четырёх документов вместо ослабления TERM-001.** Альтернатива — оставить
   `rules/terminology.md`, разрешив в нём глоссарий. Отвергнуто: владелец опробует механизм навыка
   в родном виде, частичное сохранение терминологии оставило бы половину конфликта в изменённой форме.
2. **Синхронная правка обеих точек входа.** Из `CLAUDE.md` удаляются `@`-импорты четырёх файлов,
   из `AGENTS.md` — строки списка; в каждом файле добавляется строка таблицы версий по
   [DOC-022](../../../rules/documentation-rules.md#жизненный-цикл-документа).
3. **Пример в `rules/reading-rules.md` переводится на существующий документ** (`rules/environment.md`)
   вместо оставления битого пути на `rules/terminology.md`.
4. **Исторические записи не ретроспективятся.** Упоминание TERM-002 в строке 1.0.2 таблицы версий
   `.claude/skills/requirement-add/SKILL.md` остаётся как записано: запись истории описывает
   состояние на момент правки.
5. **`skip_specs: true`.** Ни одна действующая спека не опирается на удаляемые документы; изменений
   на уровне требований нет, требования ради валидации не изобретаются.

## Risks / Trade-offs

- [Установки кита, ссылающиеся на удалённые документы, теряют их при обновлении] → файлы остаются
  в git-истории кита; откат — `git revert` этого изменения.
- [Агенты теряют автоприменение правил проектирования (TERM/CLAR/CQRS/DDD)] → осознанный выбор
  владельца: моделирование и единый язык переходят на внешний навык по мере его применения.
- [Рассинхрон терминов между артефактами без TERM-правил] → единый язык берёт на себя навык
  `domain-modeling` со своим `GLOSSARY.md`; вне его применения — обычная редакторская дисциплина.

## Migration Plan

Удаление файлов и правки точек входа выполняются одним коммитом; миграции данных нет. Откат —
`git revert` коммита изменения. Для целевых проектов обновление кита перестаёт приносить четыре
документа; на уже установленные копии изменение не действует.

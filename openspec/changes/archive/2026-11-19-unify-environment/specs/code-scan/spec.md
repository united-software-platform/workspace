# Spec Delta

## MODIFIED Requirements

### Requirement: Сканирование стороннего проекта по файлу запроса

Задача `mise run tldr-scan-ext` SHALL исполнять сканирование стороннего проекта по файлу запроса
`.tldr/scan-request.json` через шлюз `tools/tldr/gateway.py`. Запрос MUST содержать поля
`request_id`, `project` — абсолютный путь к каталогу проекта на хосте — и `report_name` — имя
каталога отчётов; поля `ext` и `exclude` опциональны. Отчёты MUST складываться в
`reports/<report_name>` рабочего дерева.

#### Scenario: Запрос на сканирование стороннего проекта

- **WHEN** агент пишет в `.tldr/scan-request.json` запрос с абсолютным путём стороннего проекта и `report_name` и вызывает `mise run tldr-scan-ext`
- **THEN** сканирование выполняется над указанным каталогом, а отчёты появляются в `reports/<report_name>` рабочего дерева

#### Scenario: Нет файла запроса

- **WHEN** задача `tldr-scan-ext` вызвана, а файла `.tldr/scan-request.json` нет
- **THEN** шлюз отказывает с кодом `2`, не запуская сканирование, и пишет исход отказа в файл результата

## ADDED Requirements

### Requirement: Задача mise для сканирования проекта

Задача `mise run tldr-scan` SHALL сканировать корень проекта и складывать отчёты в `reports/tldr`.
Каталог `reports` MUST всегда скрываться от анализа, чтобы прогон не учитывал отчёты прошлого.
Каталог `reports/tldr` MUST быть исключён из git.

#### Scenario: Повторный прогон

- **WHEN** `mise run tldr-scan` выполняется второй раз и в `reports/tldr` лежат отчёты прошлого прогона
- **THEN** отчёты прошлого прогона не попадают в анализ, а `git status` их не показывает

### Requirement: Коды возврата сканирования контейнером

Сканирование SHALL завершаться кодом `0`, если все команды выполнены, кодом `1`, если часть команд
завершилась ошибкой, и кодом `2` при ошибке вызова или окружения: нет пути проекта, каталог проекта
не найден, нет `docker`, не удалось запустить контейнер сканирования.

#### Scenario: Нет docker

- **WHEN** `docker` не найден в `PATH`
- **THEN** скрипт печатает `error: docker not found in PATH` и завершается с кодом `2`

#### Scenario: Часть команд упала

- **WHEN** 17 из 18 команд выполнены, одна завершилась ошибкой
- **THEN** скрипт печатает `17/18 commands succeeded` и завершается с кодом `1`

### Requirement: Настройка сканирования через mise

Задача `mise run tldr-scan` SHALL брать образ, расширение дерева файлов и скрываемые каталоги
из переменных `TLDR_IMAGE`, `TLDR_EXT`, `TLDR_EXCLUDE` окружения задачи; умолчания объявлены
в скрипте `tools/tldr/scan.sh`. Пустое значение MUST оставлять умолчание: образ
`ghcr.io/united-software-platform/tldr-code:latest`, расширение `.php`, каталоги `vendor`
и `public`. `TLDR_EXCLUDE` MUST задаваться списком каталогов через запятую. Каталог `reports`
MUST всегда добавляться к скрываемым.

#### Scenario: Настройки из окружения

- **WHEN** при запуске задачи заданы `TLDR_EXT=.py` и `TLDR_EXCLUDE=.idea,backlog`
- **THEN** дерево файлов строится по `.py`, а скрыты каталоги `.idea`, `backlog` и `reports`

#### Scenario: Переменные не заданы

- **WHEN** переменные `TLDR_*` пусты и в окружении, и в `mise.toml`
- **THEN** сканирование идёт образом по умолчанию по `.php`, а скрыты `vendor`, `public` и `reports`

## REMOVED Requirements

### Requirement: Цель make для сканирования проекта

**Reason**: Makefile исключён из окружения; сканирование запускается задачей mise, а не make-целью.

**Migration**: действует новая редакция «Задача mise для сканирования проекта» в этом же изменении:
`mise run tldr-scan`, поведение с отчётами и скрытием `reports` сохранено.

### Requirement: Коды возврата сканирования

**Reason**: прежняя редакция описывала код `2` отсутствием docker и загрузкой образа в эпоху
make-целей; сканирование исполняется задачей mise одноразовым контейнером docker.

**Migration**: действует новая редакция «Коды возврата сканирования контейнером» в этом же
изменении: код `2` — нет `docker` или не удалось запустить контейнер.

### Requirement: Настройка сканирования через окружение

**Reason**: прежняя редакция читала умолчания из `.env` через make-цель; make-цели и forge-блоки
`.env` исключены, умолчания объявляются в `[env]` файла `mise.toml`.

**Migration**: действует новая редакция «Настройка сканирования через mise» в этом же изменении:
сначала окружение, затем `[env]` из `mise.toml`.

### Requirement: Запуск сканирования агентом через раннер

**Reason**: контейнерная поставка sdd-kit и раннер `tools/host-runner/` исключены из окружения —
агенты работают на хосте и запускают задачи напрямую.

**Migration**: агент запускает `mise run tldr-scan` на хосте; построчный вывод и код возврата
доступны ему напрямую, отчёты — в `reports/tldr` рабочего дерева.

### Requirement: Встраивание в файлы kit'а только помеченными блоками

**Reason**: интеграция kit'а — манифесты и помеченные блоки — исключена из окружения вместе
с контейнерной поставкой.

**Migration**: файлы окружения (`mise.toml`, `.env.example`, `.gitignore`) правятся как обычные
файлы репозитория; сверка по контрольным суммам манифестов не ведётся.

# Proposal

## Why

Классификация проектов по таксономии SPCF 2.0 (источник истины `tools/classifier/taxonomy/`)
выполняется вручную: качество и полнота зависят от эксперта, результат невоспроизводим.
Прожарки WRSP-022 (issue #10) зафиксировали техническое решение — семантическое
сопоставление карточки проекта с записями уровней L1–L4 через векторные представления.
Сейчас в репозитории нет ни утилиты, ни операции, возвращающих классификацию воспроизводимо.

## What Changes

- Новая утилита классификации `tools/classifier/`: uv-проект по образцу `tools/forge/`,
  слои domain / application / infrastructure; вход — файл карточки проекта, выход —
  JSON-контракт классификации на stdout.
- Семантическое сопоставление: тексты карточки и записи таксономии векторизуются
  OpenAI-совместимым эндпоинтом embeddings за прокси (переменные окружения
  `EMBEDDINGS_*`), близость — косинусная.
- Выходной контракт: по каждому уровню L1–L4 кандидаты с ролями primary (топ-1)
  и secondary (до 3), confidence (косинус 0–1), rationale, needs_confirmation
  (пустой `purpose` или топ-1 ниже порога; порог — флаг CLI, стартово 0.5).
- Коды возврата CLI: `0` — порог пройден, `1` — needs_confirmation, `2` — ошибка
  входа или окружения.
- Границы: реестры утилита не трогает (результат только stdout), режима авто нет,
  кеш векторов и выбор провайдера embeddings — вне зоны компонента.
- Новая операция беклога `classify`: шаблон в `templates/`, навык-обёртка — по образцу
  `workflow`; шаги вызова утилиты, стоп-знак с результатами и цикл дополнения данных
  (отказ — новый беклог с дополненной карточкой, до готовности).
- Карточка проекта живёт вне git; обезличенный шаблон карточки — в README утилиты.
- Тесты — на фейковом клиенте embeddings по контракту домена; реальный эндпоинт
  в тестах не зовётся.

## Capabilities

### New Capabilities

- `domain-classifier`: утилита классификации проектов по SPCF 2.0 — загрузка таксономии
  из `tools/classifier/taxonomy/`, векторизация, косинусное ранжирование кандидатов L1–L4,
  выходной контракт с confidence / rationale / needs_confirmation, CLI с кодами
  возврата 0/1/2.

- `classify-operation`: операция беклога `classify` — прогон классификации по шагам
  со стоп-знаком принятия и циклом дополнения данных карточки.

### Modified Capabilities

Нет — `code-scan`, `dev-work-format`, `dev-workflow` не затрагиваются: их требования
не меняются, change не правит их поведение.

## Impact

- Новый каталог `tools/classifier/` (uv-проект, src-укладка, слои домена/приложения/
  инфраструктуры, dev-группа pytest/mypy/ruff).
- Новый файл `templates/classify.md` и навык-обёртка операции; каталог `backlog/classify/`
  начинает накапливать прогоны (как `backlog/workflow/`).
- Новые переменные окружения `EMBEDDINGS_BASE_URL`, `EMBEDDINGS_API_KEY`,
  `EMBEDDINGS_MODEL` — placeholder-имена, точные значения утверждает реализация этапа 1;
  заглушки в `.env.example`.
- Зависимости утилиты: HTTP-клиент и числовые массивы (например `httpx` + `numpy`);
  точный состав утверждает реализация.
- `tools/classifier/taxonomy/` используется как есть, не правится.
- Задача GitHub #10 (WRSP-022), PR #11; реализация идёт в ветке
  `feature/wrsp-022-domain-classifier-architecture`.

# Design

## Context

Решения прожарок WRSP-022 (issue #10 и комментарий к нему) уже зафиксированы владельцем:
семантика по близости векторов, эндпоинт за прокси, косинусная близость, стоп-знак
без режима авто, результат только stdout. Образец укладки Python-инструмента —
`tools/forge/` (uv-проект, `src/`-укладка, слои domain/application/infrastructure,
dev-группа pytest/mypy/ruff). Источник таксономии `tools/classifier/taxonomy/` лежит
в репозитории и правке не подлежит. `uv` 0.12.7 доступен в окружении.

## Goals / Non-Goals

**Goals:**

- Воспроизводимая классификация карточки по уровням L1–L4 с показателями уверенности.
- Утилита, встраиваемая в рабочий процесс: одноразовый CLI-прогон без состояния.
- Операция беклога `classify` со стоп-знаком и циклом дополнения данных.

**Non-Goals:**

- Кеш векторов таксономии, выбор провайдера embeddings, режим авто, запись в реестры —
  сняты владельцем по итогам прожарок (см. issue #10).
- Обучение или дообучение моделей: сопоставление чисто векторное, без обучающей выборки.

## Decisions

### D1. Укладка: uv-проект по образцу forge

`tools/classifier/pyproject.toml` с точкой входа `classifier = "classifier.cli.main:main"`,
`src/classifier/` со слоями по правилам чистой архитектуры: домен (сущности таксономии,
контракт клиента embeddings, расчёт близости), приложение (сценарий классификации
с входным и выходным контрактами), инфраструктура (HTTP-клиент эндпоинта, загрузчик
файлов выгрузки).

- Альтернатива: плоский скрипт без слоёв. Отвергнута — правила чистой архитектуры
  обязательны, а forge уже доказал укладку жизнеспособной в этом репозитории.

### D2. Домен объявляет контракт клиента embeddings, инфраструктура реализует

Сценарий классификации зависит только от контракта `EmbeddingClient` в домене
(по CLAR-021), реализация `HttpEmbeddingClient` живёт в инфраструктуре и подменяется
фейком в тестах. Это делает тесты сетенезависимыми и позволяет менять эндпоинт
конфигурацией, не трогая сценарий.

- Альтернатива: HTTP-вызовы из сценария. Отвергнута — ломает CLAR-012 и делает тесты
  сетевыми.

### D3. Один батч-запрос на прогона таксономии, один на карточку

Тексты таксономии (109 записей × 4 уровня) векторизуются одним batch-запросом
к эндпоинту (`input: [тексты]`), карточка — вторым. Два запроса на прогон вместо
110: прокси и бюджет остаются целы.

- Альтернатива: по запросу на запись. Отвергнута — 110 сетевых обращений лишние.

### D4. Численная часть без тяжёлых зависимостей

Косинусная близость — скалярное произведение и нормы: достаточно чистого Python
или `numpy` на выбор реализации; тяжёлый ML-стек не тянется. Точный состав
зависимостей (httpx, numpy) утверждает реализация этапа 1.

- Альтернатива: numpy обязателен. Отклонена как преждевременная — при 110 векторах
  чистый Python измеримо не медленнее.

### D5. Операция classify — шаблон `templates/classify.md` + навык-обёртка

Шаблон по грамматике существующих (`workflow.md`, `forge-*.md`): значения `card`
и `threshold`, задача вызова утилиты, стоп-знак, цикл дополнения. Навык-обёртка
`classify` — по образцу `workflow`: предмет-адрес, target из git remote, делегирование
`/backlog:backlog-generate` и `/backlog:backlog-run`.

- Альтернатива: встраивание вызова в операцию workflow. Отвергнута — у workflow иное
  назначение (путь от требования до прожарки), смешение раздувает шаблон.

### D6. Порог и его место

Порог confidence — флаг CLI `--threshold` (стартово 0.5), в операции — значение
`threshold`. Косинусная близость передаётся в confidence как есть, без шкалы —
решение о достаточности остаётся за владельцем на стоп-знаке.

- Альтернатива: калибровка порога на корпусе. Отвергнута владельцем — корпуса-эталона
  нет, стартовое значение уточняется на реальных прогонах.

## Risks / Trade-offs

- [Прокси несовместим с OpenAI-контрактом] → этап 2 (прототип) проверяет контракт
  первым; при расхождении контракт HTTP-клиента правится в инфраструктуре, домен
  и спека не меняются.
- [Косинус 0.5 как стартовый порог неточен] → порог флагом; значение уточняется
  на реальных прогонах, спека фиксирует только механику порога.
- [Семантика неоднозначна на коротких карточках] → needs_confirmation при недостатке
  данных; цикл дополнения карточки — часть операции classify.
- [Размер ответа embeddings для 109 записей] → батч-запрос D3; при лимите прокси
  на размер батча реализация режет батч на части в инфраструктуре.

## Migration Plan

Новый компонент и шаблон, ничего не заменяют: откат — удалить `tools/classifier/`,
`templates/classify.md`, навык-обёртку и накопленные беклоги `backlog/classify/`.
На существующие возможности (code-scan, dev-workflow, dev-work-format) не влияет.

## Open Questions

- Точные имена переменных окружения (placeholder `EMBEDDINGS_*`) — утверждает этап 1;
  на спеку и подход не влияют.
- Формат rationale в выходном контракте (свободный текст или структура) — этап 1;
  спека требует только его наличия.

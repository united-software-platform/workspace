# Spec Delta

## Purpose

Утилита классификации проектов по таксономии SPCF 2.0: по карточке проекта возвращает
воспроизводимый контракт классификации по уровням L1–L4 с показателями уверенности,
не трогая реестры и не выдумывая категории при нехватке данных.

## ADDED Requirements

### Requirement: Загрузка таксономии
Утилита SHALL загружать таксономию SPCF 2.0 из выгрузки `tools/classifier/taxonomy/`
и собирать записи уровней L1–L4 с двуязычными полями (name/name_ru,
description/description_ru). Таксономия принимается как есть и утилитой не правится.

#### Scenario: Нормальная загрузка
- **WHEN** утилита запущена и выгрузка `tools/classifier/taxonomy/` доступна и полна
- **THEN** записи L1 (16), L2 (35), L3 (25), L4 (33) загружены целиком,
  с двуязычными полями каждой записи

#### Scenario: Выгрузка недоступна или неполна
- **WHEN** каталог выгрузки отсутствует, файл уровня не читается или структура записи
  не соответствует ожидаемой
- **THEN** утилита завершается с кодом `2` и сообщением об ошибке входа на stderr;
  классификация не выполняется

### Requirement: Вход — карточка проекта
Утилита SHALL принимать карточку проекта в формате JSON с полями `name`, `purpose`
и `facets`. Поле `purpose` обязательно; `facets` опционален, неизвестные поля
игнорируются.

#### Scenario: Карточка с полным составом
- **WHEN** на вход подан JSON-файл карточки с `name`, `purpose` и `facets`
- **THEN** карточка принимается, классификация выполняется по `purpose` и значимым
  фасетам

#### Scenario: Карточка без purpose
- **WHEN** поле `purpose` отсутствует или пусто
- **THEN** утилита не обращается к эндпоинту embeddings, возвращает контракт
  с needs_confirmation=true и завершается с кодом `1`

#### Scenario: Карточка не читается
- **WHEN** файл карточки отсутствует, не является корректным JSON или не объект
- **THEN** утилита завершается с кодом `2`, сообщение об ошибке — на stderr

### Requirement: Векторизация через эндпоинт за прокси
Утилита SHALL векторизовать тексты карточки и записи таксономии через
OpenAI-совместимый эндпоинт `POST {EMBEDDINGS_BASE_URL}/embeddings` с телом
`{"model": <EMBEDDINGS_MODEL>, "input": [<тексты>]}` и ключом
`EMBEDDINGS_API_KEY`. Текст записи таксономии — склейка полей name, name_ru,
description, description_ru; текст карточки — purpose и значимые фасеты без пустых.
Выбор провайдера (локальный или удалённый) — конфигурация окружения, не поведение
утилиты.

#### Scenario: Переменные окружения заданы
- **WHEN** заданы `EMBEDDINGS_BASE_URL`, `EMBEDDINGS_API_KEY`, `EMBEDDINGS_MODEL`
  и эндпоинт отвечает
- **THEN** тексты векторизуются, близость считается по векторам эндпоинта

#### Scenario: Переменные не заданы или эндпоинт недоступен
- **WHEN** любая из переменных не задана, эндпоинт не отвечает или возвращает ошибку
- **THEN** утилита завершается с кодом `2`, сообщение об ошибке — на stderr

### Requirement: Косинусное ранжирование кандидатов
Утилита SHALL считать косинусную близость вектора карточки к вектору каждой записи
каждого уровня L1–L4 и ранжировать кандидатов по убыванию близости. Primary —
кандидат с максимальной близостью на уровне; secondary — следующие кандидаты до 3
на уровень.

#### Scenario: Ранжирование по уровню
- **WHEN** векторы карточки и записей уровня получены
- **THEN** кандидаты уровня упорядочены по убыванию косинусной близости, первый
  помечен primary, последующие до 3 — secondary

#### Scenario: На уровне меньше кандидатов, чем мест
- **WHEN** в топе уровня оказалось меньше записей, чем мест secondary
- **THEN** в контракт попадают только существующие кандидаты, пустые placeholder-записи
  не создаются

### Requirement: Выходной контракт классификации
Утилита SHALL возвращать на stdout JSON-контракт: по каждому уровню L1–L4 список
кандидатов с идентификатором записи таксономии, ролью (primary/secondary),
confidence (косинусная близость 0–1), rationale и признаком needs_confirmation.
Needs_confirmation=true SHALL выставляться при пустом `purpose` или когда primary
уровня ниже порога; порог задаётся флагом CLI, стартовое значение 0.5. Результат
попадает только на stdout — реестры и другие файлы утилита не пишет.

#### Scenario: Порог пройден
- **WHEN** primary каждого уровня не ниже порога
- **THEN** контракт выводится с needs_confirmation=false, код возврата `0`

#### Scenario: Порог не пройден
- **WHEN** primary хотя бы одного уровня ниже порога
- **THEN** контракт выводится с needs_confirmation=true, код возврата `1`

#### Scenario: Итог только на stdout
- **WHEN** классификация завершена
- **THEN** изменённых файлов нет: результат выведен только на stdout

### Requirement: Коды возврата CLI
Утилита SHALL завершаться с кодом `0` при успешной классификации с пройденным
порогом, `1` при needs_confirmation=true, `2` при ошибке входа или окружения
(карточка не читается, переменные не заданы, эндпоинт недоступен, выгрузка неполна).

#### Scenario: Успешный прогон
- **WHEN** карточка корректна, эндпоинт ответил, порог пройден
- **THEN** код возврата `0`

#### Scenario: Данные недостаточны
- **WHEN** карточка корректна, но порог не пройден или purpose пуст
- **THEN** код возврата `1`

#### Scenario: Ошибка входа или окружения
- **WHEN** карточка, выгрузка, переменные окружения или эндпоинт неисправны
- **THEN** код возврата `2`

### Requirement: Тесты без реального эндпоинта
Тесты утилиты SHALL выполняться на фейковом клиенте embeddings, подменяющем контракт
домена; реальный эндпоинт в тестах не вызывается.

#### Scenario: Прогон тестов
- **WHEN** выполняется тестовый прогон утилиты
- **THEN** все тесты проходят на фейковом клиенте без сетевых обращений

# Spec Delta

## ADDED Requirements

### Requirement: Склейка близких записей справочников
Выгрузка таксономии SHALL соединять семантически тождественные записи одного уровня в одну каноническую запись с полем `aliases` для поглощаемых идентификаторов; счётчики справочников и манифеста MUST отражать объединённое состояние.

#### Scenario: Поглощаемый идентификатор разрешается алиасом
- **WHEN** потребитель таксономии обращается к записи по поглощённому идентификатору из `aliases`
- **THEN** разрешение даёт каноническую запись уровня

#### Scenario: Счётчики после склейки
- **WHEN** две записи уровня объединены в одну каноническую
- **THEN** `record_count` справочника уровня и манифест уменьшаются на единицу

#### Scenario: Различимые понятия не склеиваются
- **WHEN** записи уровня родственны, но выражают разные понятия
- **THEN** записи остаются раздельными, поле `aliases` не заводится

### Requirement: Объединённые записи пяти склеек
Выгрузка таксономии SHALL содержать объединённые записи пяти склеек: SUB-009 «Инженерия качества ПО» (aliases: SUB-013), SUB-020 «Обработка данных» (aliases: SUB-019), PRB-003 «Низкое качество управления данными» (aliases: PRB-015), PRB-011 «Низкая понятность кода» (aliases: PRB-023), SOL-010 «Система управления требованиями» (aliases: SOL-011). Имя объединённой записи MUST отражать объединённое понятие, описание — объединять тексты исходных записей.

#### Scenario: Тестирование — алиас инженерии качества
- **WHEN** утилита классификации ищет кандидата для карточки о тестировании ПО
- **THEN** кандидат L2 разрешается записью SUB-009 с алиасом SUB-013

#### Scenario: Объединённое описание обработки данных
- **WHEN** потребитель читает запись SUB-020 после склейки
- **THEN** описание покрывает и конвейеры обработки, и интеграцию источников — обе исходные записи

## MODIFIED Requirements

### Requirement: Проблема ручной подготовки документов в L3
Выгрузка таксономии SHALL содержать на уровне L3 (problem domains) объединённую запись
«Ручная обработка информации» (Manual Information Processing): извлечение, преобразование
и представление информации, включая повторяющуюся ручную подготовку документов, заявок
и комплектов, требует непропорциональных усилий. Идентификатор записи — PRB-025; запись
MUST нести алиас PRB-027 (поглощённая «Ручная подготовка документов»), заполнять все
обязательные поля уровня и отражать объединённое понятие в имени и описании.

#### Scenario: Кандидат L3 для карточки с проблемой подготовки документов
- **WHEN** утилита классификации прогоняет карточку, чей purpose называет трудности
  повторяющейся ручной подготовки документов, заявок или комплектов для участия
- **THEN** в списке кандидатов L3 присутствует запись «Ручная обработка информации»
  (PRB-025, алиас PRB-027).

### Requirement: Согласованность манифеста таксономии
После изменения уровней манифест выгрузки (`manifest.json`) MUST отражать актуальные
количества записей каждого уровня: слияния записей уменьшают счётчики на число поглощённых,
дополнения — увеличивают на число добавленных, а любые поля суммарного состава выгрузки,
ссылающиеся на количества записей, приводятся к фактическим (L2 — 35, L3 — 24, L4 — 34,
примеры — 4). Прогон классификации по выгрузке с рассинхронизированным манифестом MUST
сохранять код возврата `0`. Тест загрузки таксономии MUST ожидать фактического числа записей
(35 для L2, 24 для L3, 34 для L4).

#### Scenario: Прогон после правки выгрузки
- **WHEN** утилита классификации запускается по карточке после слияния записей L2 и L3
- **THEN** утилита завершается кодом `0`, возвращает контракт классификации, и кандидаты
  объединённых записей присутствуют в ответе без ошибок валидации выгрузки.

#### Scenario: Счётчики сходятся после добавления
- **WHEN** выгрузка загружена после слияния записей L2 и L3
- **THEN** `record_count` в `l2_activity_subdomains.json` равен 35 и записей в файле 35,
  `record_count` в `l3_problem_domains.json` равен 24 и записей в файле 24, `manifest.json`
  называет 35 для L2 и 24 для L3, тест загрузки проходит.

#### Scenario: Манифест после склейки
- **WHEN** справочник уровня теряет запись при слиянии
- **THEN** счётчик уровня в манифесте уменьшается на единицу, `updated_at` обновляется

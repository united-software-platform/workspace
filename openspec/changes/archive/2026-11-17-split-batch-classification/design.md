# Design

## Context

Нынешний пакетный прогон — единственный: навык `classify-batch` опрашивает список проектов, фоновые агенты исполняют операцию `classify-project-auto` (веб-поиск → выбор источника → карточка из источника → утилита → цикл дополнения до трёх вызовов), оркестратор пишет `projects/{штамп}.json`. Мотивация разделения — в `proposal.md`.

Составные части, которые переиспользуются без изменений: контракт записи прогона (кроме `source`), механизм фоновых агентов (`Agent`, `subagent_type: claude`, по одному на элемент), предмет беклога `{штамп}-item-{NN}`, штамп `date +%Y%m%d%H%M%S`, каталог карточек `projects/{штамп}.cards/item-NN.json`, устойчивость к падению элемента.

## Goals / Non-Goals

**Goals:**

- Два навыка с разделёнными именами: `classify-batch-enrich` — прежний прогон с обогащением, `classify-batch` — карточный прогон без веб-поиска.
- Карточный прогон принимает готовые карточки: массив текстом вызова либо путь к файлу вне репозитория; карточки в репозиторий не попадают.
- Один вызов утилиты на карточку: без цикла дополнения, без выбора источника.

**Non-Goals:**

- Не меняем утилиту классификации, таксономию и их контракты.
- Не меняем семантику enrich-прогона: опрос, поиск, выбор источника, цикл дополнения остаются как есть.
- Не добавляем режимов смешанного пакета (часть карточек готовых, часть — по именам): это отдельная задача, если возникнет.

## Decisions

### D1. Новое имя навыка занимает `classify-batch`, обогащаемый уходит на `classify-batch-enrich`

Альтернатива — оставить `classify-batch` обогащаемому и дать карточному имя с суффиксом — отклонена выбором владельца: базовый путь без суффикса, различие несёт вариант с расширением. Переименование — `git mv .claude/skills/classify-batch .claude/skills/classify-batch-enrich` с дозаписью строки версий в `SKILL.md`; ссылок на старое имя вне переименовываемого файла и спеки нет (проверено поиском).

### D2. Карточный прогон наследует каркас enrich-прогона, а не пишется с нуля

Опрос списка проектов исключается — состав пакета несёт сам вход. Остаются: опрос отсутствует, проверка окружения (суженная — только `EMBEDDINGS_*` и таксономия), штамп, фоновые агенты по одному на карточку, один итоговый файл, сводный отчёт. Порог и модель исполнителя принимаются из вызова с умолчаниями `0.5` и `haiku` — повторять enrich-опрос ради двух значений не нужно: карточный прогон адресован сценаристу, а не диалогу.

### D3. Новый шаблон `templates/classify-card-auto.md` вместо переиспользования `classify-project-auto`

Шаблон `classify-project-auto` несёт задачи поиска, выбора источника и цикла дополнения — для готовой карточки это мёртвые группы, а условные флаги усложнили бы шаблон enrich-прогона. Отдельный шаблон короче: предусловия (носитель порядка, lint, окружение без `WEBSEARCH_*`), запись карточки в `projects/{штамп}.cards/item-NN.json`, один вызов утилиты, разбор кода, возврат результата. Значения операции: `card_json` (карточка сериализована строкой), `threshold`, `package_stamp`, `item_number`, `runner_model`. Фронтматтер без полей поиска: `results_found`/`chosen_source`/`enrichment_*` исключены, `source` в записи прогона всегда `null`.

Альтернатива — параметризовать существующий шаблон флагом `no-enrich` — отклонена: один шаблон нёс бы два разных поведения, а `backlog check-template` прогонял бы оба сочетания.

### D4. Код `1` — отказ элемента, без попыток дополнения

Обогащение невозможно: источника нет, карточка уже дана владельцем, дописывать факты неоткуда. Данные классификации сохраняются в записи прогона — владелец видит кандидатов и причины, повторный прогон с уточнённой карточкой остаётся его решением. Код `0` с меткой «A & B» — чистый результат, принимается (унификация с enrich-прогоном по WRSP-026).

### D5. Входной массив нормализуется до запуска агентов

Массив (из текста вызова или файла) проверяется целиком: элемент без `purpose` не отбрасывается молча — прогон останавливается до запуска агентов с перечнем бракованных индексов. Причина: карточка без `purpose` гарантированно вернёт `needs_confirmation` у всей пачки агентов; дешевле остановить до старта. Карточки раскладываются по `projects/{штамп}.cards/item-NN.json` оркестратором до запуска агентов — так агент получает карточку путём файла, а не телом задачи (в истории агента не остаётся дубля данных карточки).

## Risks / Trade-offs

- [Два шаблона авто-операций расходятся] Оба шаблона несут общие блоки (предусловия, вызов утилиты, закрытие) → расхождение правится в двух местах. Смягчение: шаблон карточной операции строится сноской на нормы BKL, как существующий; общие изменения кода утилиты не затрагивают шаблоны.
- [`source: null` в контракте записи] Поле сохранено для совместимости формата с enrich-прогоном → читатель файла обязан различать прогоны. Смягчение: значение `null` документировано в контракте записи; формат файла един.
- [Валидация массива до старта отклоняет пачку целиком] Одна бракованная карточка останавливает прогон → дороже для владельца, чем пометить её `failed`. Осознанный обмен: молчаливый пропуск искажал бы состав пакета, а исправить одну карточку до старта дешевле повторного прогона.

## Migration Plan

1. `git mv` каталога навыка — до создания нового `classify-batch`; одно имя каталога в один момент.
2. Новый шаблон и новый навык — после переименования; `backlog check-template templates/classify-card-auto.md` до коммита.
3. Отката не требуется: enrich-прогон не меняет поведения, новое имя не занято другими вызовами.

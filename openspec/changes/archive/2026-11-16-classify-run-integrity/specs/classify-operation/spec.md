# Spec Delta

## ADDED Requirements

### Requirement: Прогон по закоммиченному состоянию таксономии

Беклог classify SHALL перед вызовом утилиты проверять, что выгрузка
`tools/classifier/taxonomy/` закоммичена: `git status --porcelain tools/classifier/taxonomy/`
пуст. Незакоммиченные правки выгрузки — стоп-знак с названным препятствием: прогон идёт
только по закоммиченному состоянию таксономии.

#### Scenario: Выгрузка закоммичена

- **WHEN** `git status --porcelain tools/classifier/taxonomy/` пуст
- **THEN** предусловие пройдено, беклог продолжает исполнение до вызова утилиты

#### Scenario: В выгрузке незакоммиченные правки

- **WHEN** `git status --porcelain tools/classifier/taxonomy/` непуст
- **THEN** исполнение останавливается на предусловии, препятствие названо владельцу;
  беклог остаётся пригодным к продолжению после коммита

### Requirement: Контракты прогона в каталоге беклога

Задача записи итога прогона SHALL писать в каталог прогона два файла: `card.json` — копия
карточки проекта, `classification.json` — итог утилиты целиком. Контракт остаётся во
фронтматтере и после принятия; беклог самодостаточен: вход и выход прогона читаются из его
каталога без обращения к временным каталогам.

#### Scenario: Итог прогона записан

- **WHEN** утилита завершилась и итог дописывается во фронтматтер
- **THEN** в каталоге прогона лежат `card.json` и `classification.json`, а фронтматтер
  несёт код возврата и контракт целиком

#### Scenario: Карточка переживает временный каталог

- **WHEN** временный каталог с исходной карточкой очищен
- **THEN** вход прогона восстанавливается из `card.json` в каталоге прогона

## MODIFIED Requirements

### Requirement: Стоп-знак принятия

Беклог classify SHALL останавливаться на стоп-знаке после показа результата: владелец
принимает классификацию либо отказывает. Подтверждение фиксируется во фронтматтере
беклога. Режима авто нет: без явного принятия классификация не считается присвоенной.
Показ на стоп-знаке обязан называть потребовавшие подтверждения причины из контракта:
порог не пройден или отрыв primary от secondary ниже margin — владелец решает с полным
знанием того, что предложенный первенец уровня не уверен в себе.

#### Scenario: Принятие

- **WHEN** владелец подтвердил результат на стоп-знаке
- **THEN** подтверждение записано во фронтматтер, операция завершается

#### Scenario: Отказ

- **WHEN** владелец отказал
- **THEN** исполнение прекращается, беклог остаётся пригодным к продолжению;
  следующий прогон — новый беклог с дополненной карточкой

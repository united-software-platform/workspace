# Spec Delta

## ADDED Requirements

### Requirement: Архетип государственной АИС в L4

Выгрузка таксономии SHALL содержать на уровне L4 (solution archetypes) запись архетипа
«Государственная автоматизированная информационная система» (Government Information System) —
внешний контур взаимодействия ведомств и организаций с получателями поддержки. Идентификатор
записи SHALL следовать формату `SOL-NNN` со следующим свободным номером уровня (SOL-035).
Запись MUST заполнить все поля, обязательные для записей уровня, в том же стиле, что
существующие записи.

#### Scenario: Классификация карточки государственной АИС

- **WHEN** утилита классификации прогоняет карточку проекта класса «государственная АИС»
  (приём регламентированной отчётности, ведение реестров имущества и получателей поддержки,
  контроль использования мер)
- **THEN** архетип «Государственная автоматизированная информационная система» занимает
  primary L4 с confidence не ниже порога, а ERP-система (SOL-001) позицию primary теряет;
  присутствие ERP в secondary допустимо.

### Requirement: Вымышленный пример государственной АИС

Выгрузка таксономии SHALL содержать в `example_project.json` вымышленный пример (`fictional:
true`) государственной АИС отчётности и реестров. Имя примера MUST быть вымышленным и не
раскрывать реальные системы.

#### Scenario: Назначение примера по уровням

- **WHEN** вымышленный пример прочитан из выгрузки
- **THEN** его назначение указывает primary на государственный сектор (L1), предоставление
  государственных услуг (L2), низкое качество управления данными (L3) и государственную АИС (L4).

#### Scenario: Пример не раскрывает реальную систему

- **WHEN** вымышленный пример прочитан из выгрузки
- **THEN** его имя и purpose не содержат имён реальных систем и организаций, поле
  `fictional` истинно.

## MODIFIED Requirements

### Requirement: Согласованность манифеста таксономии

После дополнения уровней манифест выгрузки (`manifest.json`) MUST отражать актуальные
количества записей каждого уровня: счётчики записей L4 увеличиваются на число добавленных
записей, счётчик примеров — на число добавленных примеров, а любые поля суммарного состава
выгрузки, ссылающиеся на количества записей, приводятся к фактическим (L4 — 35, примеры — 4).
Прогон классификации по выгрузке с рассинхронизированным манифестом MUST сохранять код
возврата `0`. Тест загрузки таксономии MUST ожидать фактического числа записей (35 для L4).

#### Scenario: Прогон после правки выгрузки

- **WHEN** утилита классификации запускается по карточке после дополнения L4 и примеров
- **THEN** утилита завершается кодом `0`, возвращает контракт классификации, и кандидаты новых
  записей присутствуют в ответе без ошибок валидации выгрузки.

#### Scenario: Счётчики сходятся после добавления

- **WHEN** выгрузка загружена после добавления записи L4 и примера
- **THEN** `record_count` в `l4_solution_archetypes.json` равен 35, записи в файле 35,
  `manifest.json` называет 35 для L4 и 4 для примеров, тест загрузки проходит.

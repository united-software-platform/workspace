# Design

## Context

Мотивация и состав изменения — в [proposal.md](./proposal.md), поведенческий контракт — в [спеке](./specs/domain-layout/spec.md). Контекст, определивший подход:

- Принятые прогоны classify несут контракты в собственном каталоге (`card.json`, `classification.json`) — беклоги classify git-ignored, раскладка читает их с диска, не из git.
- Выгрузка таксономии `tools/classifier/taxonomy/` уже несёт латинский слаг `code` у каждой записи уровней; меняется только потребитель, не выгрузка.
- Старый корневой проект `~/Workspace` ведёт собственную систему раскладки (реестр `projects.yaml`, миграции `layout/`); решением владельца она не учитывается, не интегрируется и не сносится — механизм доменной раскладки живёт в этом репозитории и не зависит от неё.

## Goals / Non-Goals

**Goals:**

- Один вызов инструмента от карточки до созданных каталогов и записи реестра происхождения — внутри этого репозитория.
- Идемпотентность: повторный прогон той же карточки не меняет пространство.
- Носитель поведенческого контракта раскладки — спека `domain-layout` этого репозитория.

**Non-Goals:**

- Старый корневой проект `~/Workspace`: его реестр, миграции и спеки не трогаются; интеграция с ними и снос — вне изменения.
- Перенос существующих чекаутов в новое дерево: инструмент создаёт каталоги; перемещение каталогов проектов — отдельное действие владельца.
- Массовая раскладка всех проектов: прогон — один проект за вызов, по одной принятой карточке.
- Миграции и откат раскладки: каталог дерева — пустой плейсхолдер, изменение раскладки — повторный прогон с новой карточкой; журнала миграций не заводится.
- Изменение классификатора, операции classify и таксономии.

## Decisions

### Корень дерева — этот репозиторий

Дерево `projects/` растёт в корне репозитория toolkit workspace и git-ignored строкой `/projects/`. Альтернатива — корень в старом корневом проекте `~/Workspace`, где физически лежат чекауты, — отклонена владельцем: `~/Workspace` — старый корневой проект, новые механизмы в нём не заводятся.

### Размещение инструмента: `tools/layout/` по образцу `tools/classifier/`

Самостоятельный uv-подпроект со своим `pyproject.toml`, точкой входа `layout` и тестами в `tests/`. Альтернатива — пакет внутри `tools/classifier/` — отклонена: классификатор и раскладка — разные прогонные инструменты с разными входами; расширение классификатора размывало бы его контракт «карточка → метки», тогда как раскладка — «метки → дисковое дерево».

### Вход — каталог прогона целиком, а не отдельные файлы

Инструмент принимает путь каталога беклога classify и читает из него пару `card.json` + `classification.json`; принятие проверяется по `confirmed.accepted` в `tasks.md` этого беклога. Альтернатива — принимать два файла порознь — отклонена: пара теряет связь с прогоном, и реестр происхождения не смог бы назвать источник.

### Слаги — только из выгрузки таксономии

Слаг уровня — поле `code` записи, найденной по идентификатору primary-кандидата. Отдельная карта «метка → слаг» не заводится: второй носитель слага разошёлся бы с выгрузкой при первом пополнении таксономии. Отсутствие `code` — отказ прогона, не выдумывание слага.

### Реестр происхождения — JSON-файл в корне дерева

`projects/layout-registry.json`: массив записей `{name, organization, path, l1: {id, slug}, l2: {id, slug}, source, date}`. Ключ записи — пара имени и организации карточки: повторный прогон того же проекта обновляет его запись, а одноимённые проекты разных организаций остаются разными записями. Альтернатива — ключ по одному имени — отклонена при реализации: одноимённые проекты разных организаций схлопывались бы в одну запись. YAML — отклонён: реестр ведёт только инструмент, ручное редактирование не предполагается, а контракты прогона уже JSON.

### Коллизия имени — префикс организации из карточки

Проверка единственности имени в пределах пары слагов ведётся по реестру происхождения. Коллизия разрешается префиксом `facets.organization` из карточки (`usp-forge`); занятость префиксного имени — отказ. Альтернатива — глобальная уникальность имён — отклонена в диалоге с владельцем: домен — локальная область видимости имени.

## Risks / Trade-offs

- [Беклоги classify не коммитятся: источник реестра невоспроизводим из git] → реестр происхождения — рабочий артефакт дерева, не аудируемый из истории; принято владельцем вместе с некоммитимостью дерева.
- [Чекауты остаются на старых путях, дерево получает пустые каталоги] → осознанное ограничение: перенос — отдельное действие владельца; раскладка не теряет смысла, пока реестр происхождения ведёт соответствие.

## Migration Plan

1. Инструмент, навык, спека — в этом репозитории.
2. `.gitignore` репозитория пополняется `/projects/`.
3. Прогоны на карточках forge и formular создают дерево и реестр.
4. Откат при необходимости — `rm -rf projects/` в корне репозитория.

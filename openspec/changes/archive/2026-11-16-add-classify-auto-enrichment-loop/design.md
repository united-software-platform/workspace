# Design

## Context

Прогоны WRSP-026 падают по `needs_confirmation` из-за отрывов primary меньше margin 0.02: утилита не уверена в первенце уровня, данных карточки не хватает. Пример из прогона — государственная аналитическая система (вымышленный образ кейса): отрывы 0.0181 на L1 и 0.0042 на L3, все primary выше порога 0.5. Повторный вызов на том же входе даёт тот же результат: эмбеддинги детерминированы. Требование — proposal.md, раздел Why; изменяемое поведение — specs/batch-project-classification/spec.md (дельта).

## Goals / Non-Goals

Goals:

- поднять долю `classified` в пакете без участия владельца;
- оставить след каждой попытки во фронтматтере — решения прослеживаются;
- не ломать контракт записи и оркестратор: попытки невидимы за границей беклога.

Non-Goals:

- автоматическое принятие неуверенных результатов после исчерпания попыток — порог и margin остаются законом;
- изменение утилиты, margin или ручной операции `classify`;
- повторный поиск источника при попытках — источник уже выбран и зафиксирован.

## Decisions

### D1. Цикл — внутри одного беклога, попытки не порождают новых

Триггер цикла — код возврата `1`. Задачи 4.2/4.3 шаблона расширяются: при `1` и счётчике < 3 исполнитель анализирует `reasons` (уровень и пара кандидатов с малым отрывом названы текстом), дописывает карточку сведениями из `chosen_source`, релевантными спорным уровням, и повторяет вызов утилиты. Карточка перезаписывается на месте — она артефакт агента, не пользователя. Счётчик `enrichment_attempts` и тексты дополнений — во фронтматтере: BKL-005 сохраняется, прерванный агент продолжает с записанного состояния.

Альтернатива — порождение нового беклога на попытку — отвергнута: след размножается, «выполнено ранее» теряет силу, а повторная генерация без изменения входа бессмысленна.

### D2. Дополнение — по спорным уровням, а не по всему источнику

`reasons` утилиты называют конкретные уровни (пример: L1 DOM-002 против DOM-001, L3 PRB-017 против PRB-003). Дополнение целится в них: в `purpose`/`facets` добавляются факты, разведению­щие кандидатов, из уже выбранного источника. Спекулятивное дополнение «всём подряд» раздувает карточку и разводит шум, а не кандидатов.

### D3. Три попытки, код `2` — без цикла

Первая попытка — исходная карточка, две — дополнения: эмпирический компромисс между стоимостью и шансом (каждая итерация — один вызов эмбеддингов, копейки, но агентные шаги дороже). Код `2` — ошибка входа или окружения — дополнением не лечится, отказ сразу.

## Risks / Trade-offs

- [Пограничный проект объективно не разводится] → после трёх попыток остаётся `failed` с данными — сигнал владельцу разобраться одиночным `classify`; это правильное поведение, а не дефект.
- [Дополнение «под ответ» смещает семантику] → дополнение пишется только фактами из выбранного источника, релевантными спорным уровням; ход дополнений во фронтматтере доступен для разбора.
- [Пакет удлиняется на попытки] → потолок 3 попытки; оркестратор ждёт то же число агентов, длительность элемента растёт не более чем втрое.

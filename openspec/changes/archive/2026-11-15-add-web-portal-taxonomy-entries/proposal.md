# Proposal

## Why

Классификатор доменов (`tools/classifier/`) не относит проекты класса «официальный информационный
портал» (публикация новостей, нормативных документов, сведений о деятельности организации,
афиши событий; аудитория — неограниченный круг посетителей) к адекватному архетипу решения.
Контрольный прогон по карточке этого класса ставит на primary L4 спорные архетипы — «CRM-система»
(SOL-002), затем «Система управления процессом разработки» (SOL-013), — потому что в выгрузке
`tools/classifier/taxonomy/` архетипа контент-портала нет вовсе: таксономия L4 покрывает
корпоративные и инженерные классы систем (ERP, CRM, BPM, LLM, e-commerce, инструменты
разработчика), но не веб-публикацию. Уровень L1 («Государственный сектор», DOM-002)
классифицируется стабильно; дефект локализован в L4 и — частично — в L2.

## What Changes

- **L4**: добавлен архетип «Информационный веб-портал» (Information Web Portal) — публичный сайт
  агрегирования и публикации официальной информации: новости, документы, события, структура
  организации; аудитория — неограниченный круг посетителей. Термин опирается на общепринятые
  классификации (классы Information Portal / Government Portal в перечнях типов веб-порталов;
  класс WCM/DXP аналитических квадрантов).
- **L2**: добавлен поддомен деятельности «Публикация официальной информации» — информирование
  аудитории о деятельности организации: новости, документы, события.
- Таксономия остаётся выгрузкой JSON-файлов `tools/classifier/taxonomy/`; скрипты классификатора
  не правятся — они читают выгрузку, включая манифест с количеством записей.
- Прогон classify по карточке портала после правки выгрузки должен поднять на primary L4 новый
  архетип; допустимый побочный эффект — смещение secondary-кандидатов, не требующее правки кода.

## Capabilities

### New Capabilities

- `classifier-taxonomy`: состав и целостность выгрузки таксономии SPCF, используемой
  классификатором доменов: уровни L1–L4, уникальность и формат идентификаторов записей
  (`DOM-`, `SUB-`, `PRB-`, `SOL-`), согласованность манифеста с содержимым уровней, применимость
  таксономии к классам проектов за пределами корпоративных и инженерных систем.

### Modified Capabilities

_(нет — существующие спецификации `code-scan`, `dev-work-format`, `dev-workflow` требований
к таксономии классификатора не несут)_

## Impact

- `tools/classifier/taxonomy/l4_solution_archetypes.json` — новая запись `SOL-034`.
- `tools/classifier/taxonomy/l2_activity_subdomains.json` — новая запись `SUB-036`.
- `tools/classifier/taxonomy/manifest.json` — счётчики записей уровней; возможные поля суммарного
  состава выгрузки.
- Результаты прошлых прогонов classify не меняются: результат утилиты — stdout, зафиксированные
  классификации не пересматриваются.
- Беклоги `backlog/classify/` не правятся; следующий прогон classify по карточке портального
  класса выполняется новым предметом после принятия change.
- Документация: `tools/classifier/README.md` пересказывает состав таксономии кратко со ссылкой
  на контракт — правка не требуется, если README не фиксирует численность уровней; проверяется
  задачей.

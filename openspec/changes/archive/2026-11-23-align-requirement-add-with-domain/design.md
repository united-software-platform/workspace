# Design

## Context

Шаблон `templates/requirement-add.md` 1.4.0: предусловия — только носитель порядка и lint;
группа прожарки — задачи 2.1–2.5 (выявление, grilling, сборка, линтер, семантика); стоп-знак
3.1 сводит вердикты двух уровней. `GLOSSARY.md` v2.0.0 несёт ДДД-классификацию понятий
(контекст, роли, сущности, объекты-значения, доменные службы, внешние справочники) и правилом
репозитория является единственным источником определений. Навык-обёртка `requirement-add`
существует в двух одинаковых копиях — `.claude/skills/` и `.zcode/skills/` (требование спеки).
Плагин `mattpocock-skills` 1.3.2 уже поставляет вызываемый навык `grilling`; навык
`domain-modeling` того же плагина в операциях репозитория ещё не вызывался.

## Goals / Non-Goals

**Goals:**

- Домен входит в прогон дважды: пассивно — глоссарий в контексте с предусловий, активно —
  сверка предмета и терминов перед прожаркой.
- Механика сверки живёт в задаче шаблона, а не в линтере: сверка семантическая, исполняет её
  исполнитель, решения за владельцем.
- Дубль предмета останавливает заведение нового BR — правка существующей карточки новой
  версией по правилам документации.

**Non-Goals:**

- Автоматизация сверки в `tools/reqlint/` — лексические правила не ловят смысловые дубли.
- Внесение новых статей в `GLOSSARY.md` самим прогоном — глоссарий правится решением владельца;
  прогон только предлагает статьи.
- Изменение состава девяти полей, номерной модели BR-NNN, границ операции (без GitHub)
  и механики прожарки/линтинга.

## Decisions

1. **Предусловие глоссария — задача 1.3, а не вставка в 1.1.** Чтение глоссария — отдельное
   предусловие с собственной строкой проверки («глоссарий в контексте до группы 2»), а не
   расширение задачи 1.1 о носителе порядка: у предусловий разные предметы и разные
   «выполнено ранее». Альтернатива — читать глоссарий внутри задачи 2.1 — отклонена: контекст
   домена нужен до любой работы с формулировкой, а не после выявления.

2. **Сверка — задача 2.2 между выявлением и прожаркой, нумерация группы 2 сдвигается.**
   Сверке нужна краткая формулировка задачи 2.1, а прожарке — её вердикт: канонические имена
   и новые понятия должны войти в намерение grilling, иначе прожарка проведёт владельца
   по неканоническому языку. Новая нумерация: 2.1 выявление, 2.2 сверка, 2.3 grilling,
   2.4 сборка, 2.5 линтер, 2.6 семантика. Альтернатива — сверка после прожарки по собранной
   карточке — отклонена: исправление языка после заполнения всех полей дороже, чем до.

3. **Вызов `/mattpocock-skills:domain-modeling` — условный, по факту новых понятий.** Навык
   вызывается, когда формулировка или карточка вводят понятия вне глоссария; согласование
   идёт по классификации глоссария (предметы, сущности, объекты-значения, доменные службы,
   внешние справочники). Безусловный вызов на каждый прогон отклонён: для предмета из
   известных понятий навык не даёт нового.

4. **Три исхода сверки названы в задаче, вердикт — третьим пунктом стоп-знака.** Исход
   «дубль предмета» разворачивает прогон на правку существующего BR новой версией: ID
   не меняется, файл артефакта растёт версией по правилам документации. Заведение нового BR
   при подтверждённом дубле запрещается строкой проверки задачи.

5. **Навык-обёртка меняется минимально.** В назначение и порядок добавляются: глоссарий —
   контекст прогона, доменная сверка — шаг шаблона; версии 1.0.3 → 1.1.0 в обеих копиях
   с одинаковым содержанием. Механику сверки навык не пересказывает — её носитель шаблон,
   обёртка делегирует.

## Risks / Trade-offs

- [Семантическая сверка зависит от исполнителя, не от кода] → строка проверки требует
  названный вердикт одного из трёх исходов; miss сверки ловится ревизией артефакта,
  а не прогона.
- [Рост длины шаблона: +2 задачи] → задачи композитны, строка «Выполнено ранее» сохраняет
  возобновляемость прогона; длина группы остаётся в пределах грамматики ядра.
- [Навык `domain-modeling` — новая вызываемая зависимость операции] → плагин уже
  зафиксирован в окружении (`mattpocock-skills` 1.3.2, grilling); отказа по отсутствию
  плагина не возникает.
- [Дубль предмета разворачивает прогон на правку чужого артефакта] → разворот происходит
  до прожарки и обязательно через стоп-знак с вердиктом владельца — правка без ведома
  владельца невозможна.

## Migration Plan

Шаблон и обе копии навыка правятся одним применением изменения; порождённые ранее беклоги
не пересобираются — они исполняются по своей версии шаблона (BKL-004). Откат — возврат
версий 1.4.0 / 1.0.3 git-историей без миграций.

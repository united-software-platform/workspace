# Proposal

## Why

Операция `requirement-add` формирует бизнес-требование на языке домена, но домен в прогоне
отсутствует: `GLOSSARY.md` не попадает в контекст, предмет и термины не сверяются ни
с глоссарием, ни с существующим корпусом `docs/requirements/`. Новые понятия вводятся
бесконтрольно и расходятся с доменной моделью, дубль предмета можно завести новым BR под другим
именем, а номер `BR-NNN` подбирается без сверки по смыслу. Владелец объединил в одно изменение
две заявки на версию шаблона 1.5.0 — доменное выравнивание (WRSP-037, задача GitHub #29)
и сверку предмета с существующими BR.

## What Changes

- Предусловия шаблона дополняются задачей обязательного чтения `GLOSSARY.md` и добавления его
  в контекст прогона: глоссарий — единственный источник канонических понятий домена.
- Между выявлением требования и прожаркой появляется задача доменной сверки: сверка предмета
  по смыслу с существующими BR из `docs/requirements/`, сверка терминов с `GLOSSARY.md`;
  при введении новых понятий — вызов навыка `/mattpocock-skills:domain-modeling` и согласование
  предметов нового требования, сущностей, объектов-значений, доменных служб и прочих атрибутов
  с текущим доменом. Три исхода: новый предмет / существующий термин — каноническое имя /
  дубль предмета — правка существующего BR новой версией, не новый BR.
- Стоп-знак принятия называет третий вердикт — вердикт доменной сверки: применённые
  канонические имена, новые понятия с предложенными статьями глоссария, исход для дубля
  предмета.
- Навык-обёртка `requirement-add` (обе копии — `.claude/` и `.zcode/`) описывает доменную
  сверку и глоссарий в контексте прогона.
- Шаблон 1.4.0 → 1.5.0, навык 1.0.3 → 1.1.0.
- Вне рамок: `tools/reqlint/` не автоматизируется — сверка семантическая, её место в задаче
  шаблона; внесение новых статей в `GLOSSARY.md` остаётся решением владельца вне операции —
  прогон только называет предложенные статьи на стоп-знаке; границы операции (без GitHub)
  и состав девяти полей не меняются.

## Capabilities

### New Capabilities

_Нет_: расширяется существующая операция формирования требований.

### Modified Capabilities

- `requirement-add-operation`: добавляются требования «Контекст глоссария в прогоне»
  и «Доменная сверка предмета и терминов»; требование «Стоп-знак сводит вердикты двух
  уровней» переименовывается и расширяется до трёх вердиктов.

## Impact

- `templates/requirement-add.md` — новая задача предусловий, новая задача доменной сверки,
  перенумерация группы прожарки, версия 1.5.0.
- `.claude/skills/requirement-add/SKILL.md` и `.zcode/skills/requirement-add/SKILL.md` —
  одинаковое содержание, версия 1.1.0.
- `openspec/specs/requirement-add-operation/spec.md` — накат дельты при архивации.
- Зависимость: плагин `mattpocock-skills` 1.3.2 — навык `/mattpocock-skills:domain-modeling`
  становится второй вызываемой зависимостью операции наряду с `grilling`.
- Закрывает задачу GitHub #29 (WRSP-037) с учётом объединения владельцем двух заявок
  на версию 1.5.0.

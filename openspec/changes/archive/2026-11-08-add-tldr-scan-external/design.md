# Design

## Context

Мотивация — в [proposal.md](./proposal.md#why), требования — в [specs/code-scan/spec.md](./specs/code-scan/spec.md).

Исходное состояние и прецеденты:

- Цель `tldr-scan` сканирует только корень проекта: рецепт в блоке `tldr-scan` `Makefile` собирает
  настройки из окружения и `.env` и вызывает `sh tools/tldr/scan.sh . reports/tldr`. Раннер исполняет
  цели как `["make", цель]` — параметров у цели нет и быть не может.
- Прецедент передачи параметров через раннер — шлюз Liquibase
  [`tools/liquibase/gateway.py`](../../../tools/liquibase/gateway.py): параметры едут файлом запроса,
  шлюз валидирует их (типы, лишние поля, allowlist `FORGE_TEST_DB_ALLOWLIST`), запускает команду,
  пишет файл результата с `request_id` и кодами `0`/`1`/`2`. Исход пишется в файл: `make` сводит
  любую ошибку рецепта к коду `2`, и истинный код иначе не добрался бы до вызывающего.
- `tools/forge/src/forge/shared/infrastructure/runner.py` — клиент раннера из forge: `AGENT_RUNNER_URL`,
  `AGENT_RUNNER_TOKEN`, `AGENT_RUNNER_TIMEOUT`. Для tldr-сканирования клиент — сам агент: пишет файл
  запроса, вызывает `tools/host-runner/call.sh tldr-scan-ext`, читает файл результата.
- Файлы kit'а (`Makefile`, `.env.example`, `.gitignore`, `tools/host-runner/runner.py`) записаны
  в `.sdd-kit-manifest.json` с sha256: интеграция — только блоками `# >>> tldr-scan` … `# <<< tldr-scan`.
- Каталог обмена `.forge/` скрыт от git собственным `.forge/.gitignore` со строкой `*`: корневой
  `.gitignore` при этом содержит запись `.forge/` в блоке `liquibase-forge`.

Ограничения:

- Раннер загружает `.env` командой `.` при старте: значение с пробелом без кавычек ломает загрузку,
  поэтому `TLDR_SCAN_ROOTS` — через запятую, без пробелов-разделителей.
- Раннер держит значения из окружения, прочитанного при старте: смена `TLDR_SCAN_ROOTS` требует
  перезапуска раннера.
- `tools/tldr/gateway.py` исполняется на хосте вне окружения проекта — только стандартная библиотека
  Python, как у шлюза Liquibase.
- Секция цели `Makefile` — не больше 30 строк ([MAKE-001](../../../rules/makefile-rules.md#норма-объёма-секции-make-001)).

## Goals / Non-Goals

**Goals:**

- Агент сканирует сторонние проекты из сессии: файл запроса → `call.sh tldr-scan-ext` → отчёты
  в рабочем дереве.
- Граница прав на чтение хоста задана конфигурацией (`TLDR_SCAN_ROOTS`), а не кодом, и проверяется
  шлюзом до запуска сканирования.
- Интеграция переживает обновление kit'а: всё — в существующих блоках `tldr-scan`.

**Non-Goals:**

- Параметризация раннера (передача аргументов к цели) — противоречит его границе безопасности.
- Просмотр произвольных файлов хоста: шлюз запускает только `tools/tldr/scan.sh` и только над путями
  внутри `TLDR_SCAN_ROOTS`.
- Передача в запросе образа (`TLDR_IMAGE`) — образ общий для всех сканирований, задаётся в `.env`.
- Автоперезапуск раннера после правки `TLDR_SCAN_ROOTS` — пользователь перезапускает сам.
- Разбор и устранение находок сканирования.

## Decisions

### Файл запроса `.tldr/scan-request.json` и цель `tldr-scan-ext`

Схема обмена повторяет Liquibase Forge, каталог — `.tldr/` у инструмента: шлюз, файл запроса и файл
результата принадлежат одному инструменту. Поля: `request_id` (связка запроса с результатом), `project`
(абсолютный путь на хосте), `report_name` (имя каталога отчётов), опциональные `ext` и `exclude`
(через запятую — тот же формат, что `TLDR_EXCLUDE`). `image` в запросе нет: образ — настройка окружения,
а не параметр вызова.

Альтернатива — цель под каждый проект (`tldr-scan-<имя>`, …): каждый новый проект требует правки
`Makefile` и перезапуска раннера; запрос с `report_name` покрывает то же без правок.

### Разрешённые корни `TLDR_SCAN_ROOTS` в `.env`

Формат — абсолютные пути через запятую, прецедент `FORGE_TEST_DB_ALLOWLIST`. Проверка — после
`Path.resolve()` (нормализация `..` и симлинков): путь запроса обязан лежать строго внутри одного
из корней. Пустое значение — внешний сканирование запрещено: настройка по умолчанию консервативна,
права расширяются явно.

Альтернатива — перечень корней в коде шлюза: новый корень требует коммита; `.env` меняется без правки
кода. Альтернатива «разрешить любой путь» отклонена: раннер расширил бы права агента на чтение всего
хоста.

### Коды возврата шлюза повторяют шлюз Liquibase

`0` — сканирование выполнено (включая частичные сбои команд tldr: их исход — в `stdout` и `exit_code`
внутри файла результата), `1` — не удалось запустить `scan.sh`, `2` — отказ шлюза до запуска (нет
запроса, неверный формат, путь вне корней, нет `TLDR_SCAN_ROOTS`). Истинный исход сканирования агент
читает из файла результата, а не из кода `make`.

### Расширение блоков `tldr-scan`, а не новые блоки

Цель `tldr-scan-ext`, шлюз и `TLDR_SCAN_ROOTS` — развитие той же интеграции: расширяются существующие
блоки `tldr-scan` в `Makefile` (новая цель и запись в `.PHONY`), `.env.example`, `.gitignore`,
`runner.py` (цель в множество блока). Секция цели — в пределах 30 строк: рецепт делегирует шлюзу,
разбор `.env` уже в блоке.

### Каталог обмена `.tldr/` скрыт собственным `.gitignore`

Шлюз при первом запуске создаёт `.tldr/.gitignore` со строкой `*` — как шлюз Liquibase в `.forge/`:
файлы обмена локальны. Запись `.tldr/` добавляется и в блок `tldr-scan` корневого `.gitignore` —
зеркально `.forge/` в блоке `liquibase-forge`.

### Отчёты сторонних сканирований: `/reports/` вместо `/reports/tldr/`

Отчёты нужны агенту в контейнере — значит, в рабочем дереве. Запись `/reports/tldr/` в блоке
`tldr-scan` корневого `.gitignore` заменяется на `/reports/`: любые `reports/<report_name>` —
результат прогона, не исходники. Замена записи — правка строки внутри блока, содержимое kit'а вне
блока не затрагивается.

### Вызов из сессии агента

Агент пишет файл запроса сам (это несколько строк shell/Python в его сценарии), вызывает
`tools/host-runner/call.sh tldr-scan-ext`, сверяет `request_id` в `.tldr/scan-result.json` и читает
`exit_code` с `stdout`. Отдельный клиент в `tools/` не заводится: в отличие от forge, где клиент — часть
CLI, здесь вызывающий всегда интерактивен и уже имеет `call.sh`.

## Risks / Trade-offs

- [Смена `TLDR_SCAN_ROOTS` требует перезапуска раннера] → задокументировано в `tools/tldr/README.md`
  рядом с `TLDR_*` (раннер читает `.env` при старте).
- [Пути в `TLDR_SCAN_ROOTS` с пробелами] → формат «через запятую» их не допускает; шлюз отклоняет
  корень, который не резолвится в существующий каталог, сообщением в файле результата.
- [Симлинк внутри разрешённого корня ведёт наружу] → проверка после `Path.resolve()`: нормализованный
  путь обязан оставаться внутри корня; проверяется сам путь запроса.
- [Предел раннера 900 секунд на большую пару проектов подряд] → то же ограничение, что у `tldr-scan`;
  README называет `AGENT_RUNNER_TIMEOUT`.
- [`scan.sh` пишет отчёты в текущий каталог при относительном пути] → шлюз всегда передаёт
  `reports/<report_name>` относительно корня проекта и запускает скрипт с `cwd` корня проекта.
- [Обновление kit'а может удалить блоки] → риск общий с `liquibase-forge`; восстановление —
  из `tools/tldr/README.md`.

## Migration Plan

1. Написать `tools/tldr/gateway.py` (валидация, корни, запуск, файл результата).
1. Расширить блоки `tldr-scan`: цель `tldr-scan-ext` в `Makefile`, `TLDR_SCAN_ROOTS` в `.env.example`,
   `.tldr/` и `/reports/` в `.gitignore`, цель в белом списке `runner.py`.
1. Дополнить `tools/tldr/README.md`: формат запроса, настройка корней, коды возврата.
1. Проверить: заглушкой `docker` — шлюз без хоста; через раннер — на реальных проектах после
   заполнения `TLDR_SCAN_ROOTS` и перезапуска раннера пользователем.

Откат: удалить цель и расширения блоков, `TLDR_SCAN_ROOTS` из `.env`, каталог `.tldr/`; `/reports/`
в `.gitignore` можно вернуть к `/reports/tldr/`.

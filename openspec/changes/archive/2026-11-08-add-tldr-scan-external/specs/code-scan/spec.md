# Spec Delta

## Purpose

Сканирование кода проекта образом tldr: набор отчётов об устройстве, безопасности, качестве и архитектуре
кода, который получает и человек на хосте, и агент из контейнера через раннер.

## ADDED Requirements

### Requirement: Сканирование стороннего проекта по файлу запроса

Цель `make tldr-scan-ext` SHALL исполнять сканирование стороннего проекта по файлу запроса
`.tldr/scan-request.json` через шлюз `tools/tldr/gateway.py`. Запрос MUST содержать поля
`request_id`, `project` — абсолютный путь к каталогу проекта на хосте — и `report_name` — имя
каталога отчётов; поля `ext` и `exclude` опциональны. Отчёты MUST складываться в
`reports/<report_name>` рабочего дерева.

#### Scenario: Запрос на сканирование стороннего проекта

- **WHEN** агент пишет в `.tldr/scan-request.json` запрос с абсолютным путём стороннего проекта и `report_name` и вызывает `make tldr-scan-ext`
- **THEN** сканирование выполняется над указанным каталогом, а отчёты появляются в `reports/<report_name>` рабочего дерева

#### Scenario: Нет файла запроса

- **WHEN** цель `tldr-scan-ext` вызвана, а файла `.tldr/scan-request.json` нет
- **THEN** шлюз отказывает с кодом `2`, не запуская сканирование, и пишет исход отказа в файл результата

### Requirement: Валидация запроса шлюзом

Шлюз MUST отклонять запрос отказом с кодом `2`, не запуская сканирование, если запрос не является
JSON-объектом, содержит лишние поля, содержит поле неверного типа или пустую строку вместо значения.
Поле `exclude`, если задано, MUST быть каталогами через запятую без пробелов; поле `ext` — расширением
с ведущей точкой.

#### Scenario: Лишнее поле в запросе

- **WHEN** запрос содержит поле `image`
- **THEN** шлюз отказывает с сообщением о лишнем поле и кодом `2`, сканирование не запускается

#### Scenario: Расширение без точки

- **WHEN** поле `ext` содержит `py` вместо `.py`
- **THEN** шлюз отказывает с кодом `2`, сканирование не запускается

### Requirement: Разрешённые корни сканирования

Шлюз MUST сканировать только каталоги, лежащие внутри корней из переменной `TLDR_SCAN_ROOTS`
окружения: корни — абсолютные пути хоста через запятую. Пустое или отсутствующее значение MUST
означать запрет внешних сканирований. Путь запроса MUST проверяться после нормализации симлинков,
чтобы выход за корни через символическую ссылку был невозможен.

#### Scenario: Проект вне корней

- **WHEN** `TLDR_SCAN_ROOTS=/home/user/workspace` и запрос просит сканировать `/etc`
- **THEN** шлюз отказывает с кодом `2`, не запуская сканирование

#### Scenario: Выход за корень через симлинк

- **WHEN** каталог внутри корня содержит симлинк на `/`, а запрос просит сканировать этот симлинк
- **THEN** нормализованный путь оказывается вне корней, шлюз отказывает с кодом `2`

#### Scenario: Корни не заданы

- **WHEN** `TLDR_SCAN_ROOTS` пуста
- **THEN** любой запрос внешнего сканирования отклоняется с кодом `2`

### Requirement: Файл результата с идентификатором запроса

Шлюз SHALL писать исход в `.tldr/scan-result.json` с полями `request_id`, `exit_code`, `stdout`,
`stderr`. Файл результата MUST писаться атомарно и приниматься вызывающей стороной только при
совпадении `request_id` с текущим запросом.

#### Scenario: Успешное сканирование

- **WHEN** сканирование выполнилось и все команды tldr завершились успешно
- **THEN** файл результата содержит `exit_code` `0`, `stdout` со строками `ok` и `request_id` запроса

#### Scenario: Часть команд упала

- **WHEN** часть команд tldr завершилась ошибкой
- **THEN** файл результата содержит `exit_code` `1` и вывод сканирования, а сам шлюз завершается кодом `0`: истинный исход — в файле результата

### Requirement: Отчёты сторонних сканирований вне git

Каталоги отчётов сторонних сканирований (`reports/<report_name>` при `report_name`, отличном
от `tldr`) MUST быть исключены из git.

#### Scenario: Отчёты стороннего проекта не видны git

- **WHEN** сканирование стороннего проекта завершилось и в `reports/<report_name>` лежат отчёты
- **THEN** `git status` их не показывает

## MODIFIED Requirements

### Requirement: Встраивание в файлы kit'а только помеченными блоками

Цель, переменные окружения, запись `.gitignore` и расширение белого списка раннера MUST добавляться
в файлы проекта только блоками между строками `# >>> tldr-scan` и `# <<< tldr-scan`. Содержимое файлов
kit'а вне этих блоков MUST NOT меняться, а файлы документации kit'а MUST NOT править вовсе.

#### Scenario: Сверка с манифестом kit'а

- **WHEN** из `tools/host-runner/runner.py` удалены блоки `tldr-scan` и `liquibase-forge`
- **THEN** контрольная сумма файла совпадает с записанной в `.sdd-kit-manifest.json`

#### Scenario: Документация раннера

- **WHEN** интеграция сканирования установлена
- **THEN** `tools/host-runner/README.md` совпадает с версией kit'а, а вызов сканирования агентом описан в `tools/tldr/README.md`

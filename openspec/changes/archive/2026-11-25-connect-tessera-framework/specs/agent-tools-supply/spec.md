# Spec Delta

## Purpose

Поставка инструментов агента — правил и навыков, применяемых в репозитории, — из фреймворка
tessera: единственный источник, установка в проект, состав git и точка входа агентов.

## ADDED Requirements

### Requirement: Единственный источник инструментов агента

Репозиторий SHALL NOT содержать копий навыков, правил и шаблонов операций, входящих в поставку
tessera: их единственным источником SHALL быть поставка. Перечень поставки печатает скрипт
поставки tessera в проектном режиме (`--registry --project`).

#### Scenario: Копий поставки в git нет

- **WHEN** реестр поставки получен в проектном режиме
- **THEN** ни один навык реестра и ни одно правило вне `.tessera/rules/` не отслеживается в git, а отслеживаемых копий шаблонов операций `workflow` и `workflow-fast` в репозитории нет

#### Scenario: Собственные навыки остаются

- **WHEN** навык отслеживается в `.claude/skills/` и не входит в реестр поставки
- **THEN** навык остаётся отслеживаемым и доступен харнесу

### Requirement: Установка поставки задачей mise

Поставка SHALL устанавливаться скриптом поставки tessera в проектном режиме (`--project`),
полным профилем и всеми правилами. Вызов SHALL выполняться задачей mise `init-tessera`,
входящей в `mise run init`; задача MUST быть идемпотентной.

#### Scenario: Свежий клон

- **WHEN** в свежем клоне выполнены `mise install` и `mise run init`
- **THEN** реестр проекта `.tessera/registry.json` называет навыки и правила статусом `complete`

#### Scenario: Повторный запуск

- **WHEN** задача `init-tessera` запущена повторно при неизменной поставке
- **THEN** ни один отслеживаемый файл не изменился

### Requirement: Размещение поставки в проекте

Навыки поставки SHALL связываться с каталогами навыков проекта (`.agents/skills/`,
`.claude/skills/`) ссылками на хранилище машины; правила SHALL размещаться копиями
в `.tessera/rules/`.

#### Scenario: Правила — копии, навыки — ссылки

- **WHEN** поставка установлена
- **THEN** `.tessera/rules/` содержит по файлу на каждое правило реестра, а записи навыков в `.agents/skills/` и `.claude/skills/` — ссылки

### Requirement: Копии правил коммитятся

Копии правил `.tessera/rules/` SHALL коммититься: ссылки точки входа и документов на правила
работают в каждом клоне, а изменение правила приходит проверяемым коммитом. Копии MUST NOT
правиться руками.

#### Scenario: Изменение правила видно до коммита

- **WHEN** поставка изменила правило и задача `init-tessera` запущена повторно
- **THEN** изменение показано в `git diff -- .tessera/rules/` до коммита

#### Scenario: Ссылки работают без установки

- **WHEN** репозиторий склонирован и поставка ещё не установлена
- **THEN** каждый файл, на который ссылается `AGENTS.md`, существует

### Requirement: Машинные части поставки вне git

Ссылки навыков и `.tessera/registry.json` MUST быть исключены из git: их цели и пути
принадлежат машине.

#### Scenario: Статус чист после установки

- **WHEN** поставка установлена
- **THEN** `git status --porcelain` не называет ссылки навыков и `.tessera/registry.json`

### Requirement: Каталоги навыков в git

Каталог `.agents/` MUST быть исключён из git целиком. В `.claude/skills/` SHALL отслеживаться
только собственные навыки проекта; остальное содержимое каталога MUST быть исключено из git.

#### Scenario: Новый навык поставки не попадает в статус

- **WHEN** поставка принесла навык, которого в проекте не было
- **THEN** его ссылки не названы в `git status --porcelain`, а `.gitignore` не правился

#### Scenario: Собственный навык отслеживается

- **WHEN** собственный навык проекта добавлен в перечень отслеживаемых в `.claude/skills/`
- **THEN** его файлы названы в `git status --porcelain` как новые

### Requirement: Точка входа агентов поставляется

`AGENTS.md` SHALL создаваться скриптом поставки и нести только его содержание: заголовок,
назначение и секцию правил, которую ведёт тот же скрипт. Собственные разделы в файл
SHALL NOT вноситься.

#### Scenario: Файл создан скриптом поставки

- **WHEN** до установки `AGENTS.md` в репозитории нет
- **THEN** после установки файл состоит из заголовка, назначения и одной секции правил, а ссылки секции ведут в `.tessera/rules/`

### Requirement: Единственная точка входа

`AGENTS.md` SHALL быть единственной точкой входа правил агентов в корне репозитория;
`CLAUDE.md` MUST NOT существовать.

#### Scenario: Второй точки входа нет

- **WHEN** поставка установлена
- **THEN** в корне репозитория из файлов правил агентов есть только `AGENTS.md`

### Requirement: Ссылки репозитория на правила

Документы и конфигурация репозитория SHALL ссылаться на правила по пути их установки
`.tessera/rules/<имя>.md`. Свидетельства прогонов в `backlog/` MUST NOT правиться
ретроспективно.

#### Scenario: Старый путь не используется

- **WHEN** отслеживаемые файлы вне `backlog/`, `openspec/changes/` и `docs/archive/` проверены на указание пути `rules/`
- **THEN** ни одно указание не ведёт в каталог `rules/` корня репозитория

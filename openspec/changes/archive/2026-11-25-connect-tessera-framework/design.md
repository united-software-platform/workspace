# Design

## Context

Мотивация — в proposal.md, требования — в `specs/agent-tools-supply/spec.md`
и `specs/dev-workflow/spec.md`. Здесь — как устроена поставка.

Скрипт поставки tessera в проектном режиме (`--project`) делает три вещи:

- навыки — ссылки из `.agents/skills/` и `.claude/skills/` проекта в хранилище машины
  `~/.local/share/tessera/`; существующий элемент каталога, не созданный скриптом,
  пропускается, а не заменяется;
- правила — копии в `.tessera/rules/` и секция между маркерами `<!-- delivery-tessera-… -->`
  в `AGENTS.md`; файла нет — он создаётся с заголовком `# <имя каталога проекта>`;
- реестр — `.tessera/registry.json` с меткой времени.

Состояние репозитория по сверке WRSP-039:

| В репозитории | Против поставки |
|----------------|------------------|
| `rules/` — 8 файлов | все в поставке; 7 равны, `project-docs-rules.md` в поставке новее |
| `.claude/skills/project-docs`, `workflow-fast`, `workflow-grill` | в поставке новее (1.0.1, 1.1.0, 1.1.0) |
| `templates/workflow.md`, `templates/workflow-fast.md` | побайтно равны шаблонам плагина |
| `.agents/skills/` — 34 ссылки | уже созданы скриптом, не отслеживаются |
| `.zcode/skills/` | ссылки на `.claude/skills/`, каталог в игноре |

Ограничения, из которых исходит решение: установщик ведёт только `AGENTS.md`; версии
источников не закрепляются (ветка `main`); `.zcode/` в игноре.

## Goals / Non-Goals

**Goals:**

- Один источник навыков, правил и шаблонов операций рабочего процесса — поставка tessera.
- Свежий клон приводится к рабочему состоянию одной командой `mise run init`.
- Изменение правил видно в `git diff` до коммита.

**Non-Goals:**

- Перенос в tessera собственных навыков проекта и их шаблонов.
- Уборка пользовательских каталогов навыков и плагинов харнесов.
- Правки в репозитории tessera, включая его ссылки, написанные для раскладки плагина.

## Decisions

### 1. Сначала снять копии, потом ставить

Установщик пропускает чужие элементы в каталогах навыков. Настоящие каталоги
`.claude/skills/{project-docs,workflow-fast,workflow-grill}` не дали бы создать ссылки,
и в проекте остались бы устаревшие копии. Поэтому удаление идёт до `mise run init-tessera`.
`AGENTS.md` удаляется по той же причине: существующий файл получил бы только секцию в конце.

### 2. Задача mise `init-tessera`, а не прямая команда в README

`mise run init` уже собирает инициализацию локального окружения из задач `init-*`
(ENV-006). Задача вызывает установщик с явными `--project --profile full --rules all --yes`:
профиль и перечень правил не зависят от прежней установки машины, диалог не открывается.
Альтернатива — прямая команда в README — даёт второй механизм инициализации рядом с mise.

### 3. Копии правил коммитятся, машинные части — нет

`.tessera/rules/` — обычные файлы: в клоне они на месте, ссылки `AGENTS.md`, `CONTRIBUTING.md`
и `GLOSSARY.md` разрешаются до установки, а изменение правила приходит проверяемым коммитом.
Ссылки навыков ведут в `/home/<пользователь>/.local/share/tessera/`, реестр носит метку
времени — оба ушли бы в шум. Альтернатива — игнорировать `.tessera/` целиком — оставила бы
в клоне повисшие ссылки точки входа и меняла бы правила на машине молча.

Копии не правятся руками: правка превращает копию в ручную, и установщик перестаёт её обновлять.

### 4. `.gitignore`: закрыть, затем разрешить свои

`.agents/` исключается целиком — установщик ведёт его весь. В `.claude/skills/` живут
и собственные навыки, и ссылки поставки: исключается всё содержимое каталога, затем явно
разрешаются 11 собственных навыков. Новый навык поставки не требует правки `.gitignore`;
новый собственный навык требует — и это видно. Альтернатива — перечислить имена навыков
поставки — устарела бы при первом же обновлении tessera.

### 5. Одна точка входа — `AGENTS.md` от установщика

`CLAUDE.md` дублировал перечень правил руками, а установщик его не ведёт — поэтому файл
удаляется. `AGENTS.md` создаётся установщиком: заголовок, назначение, секция правил.
Альтернатива — сохранить файл репозитория и перенести секцию на место раздела «Правила
кода» — оставила бы ручной документ, который нужно поддерживать вместе с поставкой.

### 6. Шаблоны операций снимаются

Навыки поставки 1.1.0 передают порождению `--templates`: каталог проекта, если в нём есть
шаблон операции, иначе — каталог плагина. Шаблоны проекта равны шаблонам плагина, значит
удаляются без потери. Альтернатива — оставить и перевести две ссылки на `rules/git-rules.md` —
сохранила бы копию, которую навык предпочитает поставленной.

### 7. Ссылки на правила — по пути установки

`CONTRIBUTING.md`, `GLOSSARY.md` и два комментария `mise.toml` ведут на `.tessera/rules/`.
Копии `.tessera/rules/` не правятся — ссылки внутри них пишет tessera. Свидетельства
`backlog/` не ретроспективируются.

### 8. Спецификация — минимальной дельтой

Новая способность `agent-tools-supply` описывает поставку. В `dev-workflow` меняются только
факты поведения обёртки 1.1.0: запасной шаблон плагина, каталог шаблонов в вызове порождения,
проверка зависимостей.

## Risks / Trade-offs

- [Версии источников не закреплены: установщик ставит ветку `main` tessera, formular
  и mattpocock/skills] → повторный запуск может принести новое поведение навыков без
  изменения репозитория; изменения копий правил при этом видны в `git diff` до коммита.
- [Claude Code читает `AGENTS.md` только с версии 2.1.277 и когда нет `CLAUDE.md` в проекте
  и выше него] → на этой машине выше проекта лежит `~/Workspace/CLAUDE.md` старого корня:
  Claude Code возьмёт его и пропустит точку входа tessera. Фиксируется в «Ограничениях»
  `README.md`; файл старого корня — вне изменения.
- [Напоминания о гейте чтения и `GIT-012` уходят из точки входа] → нормы остаются
  в `.tessera/rules/reading-rules.md` и `git-rules.md`, которые точка входа предписывает
  прочитать до задачи.
- [`AGENTS.md` от установщика без навигации и таблицы версий] → расхождение с `DOC-014`
  и `DOC-022` на стороне tessera; файл в проекте не правится.
- [Ссылки внутри поставленных файлов написаны для раскладки плагина (`../skills/…`,
  `../../rules/…`)] → в копиях и через ссылки проекта повисают; дефект tessera, вне изменения.
- [Шаблон плагина ссылается на `rules/git-rules.md`] → в проекте-потребителе путь
  не существует, агент находит правило по `AGENTS.md`; дефект tessera, вне изменения.
- [Навыки workflow теряют ссылку на `GLOSSARY.md`] → в поставке её нет намеренно; глоссарий
  остаётся документом проекта.
- [Установщик перезаписывает лаунчер `~/.local/bin/backlog` вне репозитория] → содержимое
  лаунчера то же, что уже стоит на машине.

## Migration Plan

Порядок исполнения:

1. Снять отслеживаемые копии: `rules/`, три навыка, два шаблона, `CLAUDE.md`, `AGENTS.md`.
2. Снять три повисшие ссылки в `.zcode/skills/`.
3. Задача `init-tessera` в `mise.toml`, записи `.gitignore`.
4. `mise run init-tessera`.
5. Ссылки и описания: `CONTRIBUTING.md`, `GLOSSARY.md`, `README.md`.
6. Проверки; перезапуск сессии харнеса.

Откат до коммита — восстановление файлов из git по явному запросу владельца (GIT-018),
после коммита — встречным коммитом (GIT-017).

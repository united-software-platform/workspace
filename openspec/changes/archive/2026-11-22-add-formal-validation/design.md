# Design

## Context

Уровни 0–1 (`reqlint` + категории A–F, семантическая задача 2.5) ловят лексические
и смысловые дефекты, но не доказывают непротиворечивость множества критериев. Уровень 2
откладывался до требований с конфликтующими числовыми ограничениями; владелец запросил
реализацию и английский вход. Дымовой материал — BR-001 (ожидание: `skipped + sat`,
критерии без общих переменных). Решатели: Z3 (`z3-solver`) для числовых связок,
SPOT (`spot`) для временных свойств.

## Goals / Non-Goals

**Goals:**

- Детерминированный конвейер карточка → канон → формула → вердикт, офлайн, RU/EN.
- Отчёт, который владелец читает без знания LTL: цитаты, свидетель, имена конфликтующих.
- Английский вход уровня 0 (`rules-en.yml`) тем же change'ом.

**Non-Goals:**

- Автовызов из прогона `requirement-add` и правка его шаблона/спеки.
- Реализуемость (realizability, синтез стратегий GR(1)) — доказывается только выполнимость.
- Формализация свободного текста «по смыслу» — только каноническая форма.

## Decisions

### D1. Каноническая форма — единственный вход компилятора

`[условие] → [субъект] [предикат] [порог + единица]`. Критерий вне канона возвращается
с образцом, формула не строится. *Альтернатива:* LLM-перевод свободного текста в формулы —
отвергнута: решатель доказывал бы свойства перевода, а не карточки; ошибка перевода
невидима. Приведение текста в канон — шаг вызова (семантический уровень помогает),
утверждается владельцем до формализации.

### D2. Двуязычие — словарь маркеров, не второй конвейер

К каждому правилу таблицы добавляется английская строка распознавания и английский шаблон
обратного перевода; логика одна, формулы одинаковы. *Альтернатива:* английский канон
с переводом русских карточек в него — отвергнута: вставляет LLM-перевод между текстом
и решателем.

### D3. Вердикты: именованные критерии и ядро противоречия

Каждый критерий входит в решатель именованным «включателем» `K1..Kn`:

```python
s = Solver()
s.assert_and_track(t_collect <= 5, "K1")   # «контекст по работе — не дольше 5 минут»
s.assert_and_track(t_verify >= 10, "K2")   # «проверка совпадения — минимум 10 минут»
s.assert_and_track(t_collect >= t_verify, "K3")  # «сбор включает проверку»
s.check()        # unsat
s.unsat_core()   # [K1, K2, K3] — противоречие названо
```

LTL-ветка: `spot.translate(conjunction)` → пустота = противоречие, принимающий прогон =
свидетель; vacuity — достижимость условия отдельной проверкой.

### D4. Отдельная команда, не шаг операции

BR-001 показал селективность: большинство карточек вернут `skipped + sat`. Гейт встроен
туда, где конфликт возможен, — вызовом по запросу. Встраивание в стоп-знак — будущее
изменение, если появятся карточки с постоянно формализуемыми критериями.

### D5. Правильность формализации подтверждает обратный перевод

Та же таблица правил разворачивается в естественный язык; владелец сверяет формулу
с критерием рядом. Решатель доказывает свойства модели, обратный перевод связывает модель
с текстом — это единственная защита от «доказательства не того».

### D6. Решатели — контейнер на Debian, хост не трогаем

SPOT не распространяется через PyPI и apt Ubuntu (факт-чек применения), sudo на хосте
недоступен. Решение владельца: образ `workspace-formal` на `debian:trixie-slim`;
`python3-spot` — из официального apt-репозитория LRDE (страница установки Spot,
GPG-подписан, бинарный пакет — без сборки из исходников; репозиторий собран под текущий
stable, поэтому база — trixie), z3 — свежий пин `z3-solver==5.4.1.0` из PyPI. `formal.py` —
обёртка `docker run` с монтированием рабочего каталога; ядро проверки (`formal_core.py`)
исполняется в контейнере. Инструменты хоста не растут (ENV-001), контейнерный одноразовый
прогон — принятый паттерн окружения; после сборки образа сеть не нужна. *Альтернативы:*
сборка SPOT из dist-тарбола в образе — отвергнута владельцем при найденном официальном
apt-канале (дольше сборка, обновление = пересборка); собственное LTL-кодирование в Z3
без SPOT — отвергнуто владельцем в пользу канонического движка.

## Risks / Trade-offs

- [Таблица правил не покроет реальные формулировки — канон отвергает чаще, чем находит
  конфликты] → отвергнутое возвращается с образцом; таблица растёт правилами, не эвристиками;
  BR-001 — ожидаемый `skipped`, не провал.
- [Vacuity-проверка ложноположительна на составных условиях] → проверяется достижимость
  конъюнкции условий, а не каждого конъюнкта по отдельности.
- [Английские A–F паттерны шумят] → severity-модель та же, что у русских: блокируют только
  `error`-находки, финальное суждение за семантикой и владельцем.

## Migration Plan

Новые файлы: `tools/reqlint/formal.py`, `tools/reqlint/formal_core.py`,
`tools/reqlint/rules-en.yml`, `tools/reqlint/Dockerfile`; в `mise.toml` добавляется задача
`formal-image` (сборка образа, идемпотентна). Откат — удаление файлов и задачи. Дымовой
прогон BR-001 фиксируется в отчёте применения как эталон `skipped + sat`.

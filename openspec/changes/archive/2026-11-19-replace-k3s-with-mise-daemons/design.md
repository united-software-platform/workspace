# Design

## Context

Change `unify-environment` применён к репозиторию (make/forge вырезаны, задачи в mise,
правила ENV-001..007), но не архивирован. Поверх него добавлялся helm-чарт `deploy/workspace`
(change `add-umbrella-helm-chart`), уже застейдженный на удаление вместе с самим change.
Остатки стандарта k3s: ENV-002..004 и ENV-007 в `rules/environment.md`, предусловия README,
`tools/tldr/scan.sh` на Job/kubectl.

Решение владельца (2026-11-19, после оценки возможностей mise daemons): mise — единственный
менеджер окружения; k3s, helm и compose уходят. Принятые цены: экспериментальный статус фичи,
pitchfork как зависимость, смешанные механики запуска (нативный PostgreSQL против контейнеров),
docker/podman остаётся для OpenSearch и MinIO. Мотивация — в proposal.md (Why).

## Goals / Non-Goals

**Goals:**

- один файл декларации окружения (`mise.toml`): инструменты, задачи, демоны, переменные;
- порты и координаты подключения — зафиксированный стандарт, а не договорённость на полях;
- сведение количества движущихся частей: минус k3s, containerd, kubelet, helm, port-forward.

**Non-Goals:**

- автостарт демонов при входе в каталог (`auto = ["start","stop"]`) — общий набор живёт
  независимо от оболочек, управляется задачами;
- выделенные демоны для конкретных дочерних проектов — потребность ещё не возникла, модель
  исключения зафиксирована в спеке;
- прод-сходство окружения — владелец признал потерю зеркалирования k8s несущественной;
- локальный registry — образов по-прежнему нет.

## Decisions

- **Демоны вместо кластера.** Альтернативы — k3s (текущее состояние) и docker compose —
  отвергнуты владельцем: port-forward обесценивал главный плюс k8s, compose вводил второй
  формат деклараций. Сервисы объявляются в `[daemons]` корневого `mise.toml`.
- **Разделение механики по сервисам.** PostgreSQL — нативный пресет демона: ставится сам,
  без контейнерного рантайма (сегодня единственный из тройки). OpenSearch и MinIO —
  image-демоны: серверных бинарей в реестрах mise/aqua нет (проверено по aqua-registry:
  minio представлен только клиентом `mc`, opensearch отсутствует), образ — единственный
  источник. Ключи `command`, `volumes`, `data_mount` для image-демонов подтверждены доками.
  Fallback: если image-форма не сможет передать аргументы команды или секреты, OpenSearch
  и MinIO переводятся в `run`-форму (`docker run …`) — в `run` шаблоны `{{ env.* }}`
  работают, контракт задач не меняется.
- **Фиксированные порты.** 5432/9200/9000 — константы стандарта: общий набор один, конфликты
  решаются выбором других портов в `mise.toml`, а не авто-выбором. Auto-порты оставлены
  будущим выделенным демонам проектов. Потребительская копия координат — `PG_PORT`,
  `OPENSEARCH_PORT`, `MINIO_PORT` в `[env]` — дублирует декларации демонов: шаблоны
  рендерятся только в `run` (проверено по докам, pitchfork ≥ 2.30), автоматически связать
  значения нельзя. Рассинхрон закрывается проверкой в `env-status`.
- **Секреты — прежний паттерн ENV-005.** `.env` + `_.file`, имена в `.env.example`. Вброс
  секретов в image-демоны (переменные окружения контейнера) проверяется на применении;
  при невозможности — тот же fallback на `run`-форму с `{{ env.* }}`.
- **pitchfork в `[tools]`, не глобально.** Глобальная установка нужна только автостарту
  из shell-хука, который не используется; локальный закреплённый pitchfork детерминирован
  и версионируется вместе с окружением.
- **Одноразовые прогоны — `docker run --rm` из задач mise.** Job-механика k3s свёртывается;
  bind-mount путей рабочего дерева заменяет hostPath, ожидание завершения — штатный код
  возврата контейнера. Коды возврата scan.sh (0/1/2) сохраняются, код 2 — «нет docker».
- **Согласование с открытым `unify-environment`.** Capability `environment` в живых спеках
  отсутствует; валидатор разрешает для новой capability только ADDED (проверено). Поэтому
  дельта `specs/environment/` change `unify-environment` удаляется — единственным создателем
  capability становится это изменение с финальным текстом; его дельта `specs/code-scan/`
  корректируется с Job-механики на docker-механику, чтобы при архивации не высадились
  kubectl-требования. Отмеченные задачи и design того change не переписываются — это запись
  о проделанной работе, реверсия фиксируется задачами этого изменения.

## Risks / Trade-offs

- [Экспериментальный формат деклараций меняется между релизами mise] → версии mise и
  pitchfork закреплены; смена формата — отдельным изменением (требование спеки).
- [Смешанные механики: процесс PostgreSQL против контейнеров] → `env-status` показывает
  состояние обоих миров единым списком.
- [docker/podman — предусловие для 2 из 3 сервисов и одноразовых прогонов] → фиксируется
  в «Что нужно» README вместо предусловий k3s/kubectl/helm.
- [OpenSearch требует `vm.max_map_count=262144` и под docker] → возвращается в README
  (был удалён вместе с k3s-предусловиями).
- [Дублирование портов: декларация демона + `[env]`] → проверка соответствия в `env-status`;
  убрать дублирование нельзя — шаблоны вне `run` не рендерятся.
- [Данные демонов в рабочем дереве (`data_dir`)] → каталог данных в `.gitignore` (задача).

## Migration Plan

1. Владелец фиксирует застейдженное удаление чарта и change `add-umbrella-helm-chart`
   (уже в рабочем дереве).
2. Применение этого изменения: декларации демонов, задачи env-*, возврат scan.sh на docker,
   правила, README, корректировка артефактов `unify-environment`.
3. Archive в порядке: `unify-environment` (с скорректированными дельтами), затем это
   изменение — capability `environment` создаётся финальным текстом.

Откат: git revert применения; k3s-механика восстановима из истории (коммиты ab1323d..1187834).

- ~~Гранулярность пина пресета PostgreSQL~~ — решено на применении: пресет пинится мажором
  («18»), минор разрешается свежим при установке (проверено: 18 → 18.7); полная версия не
  указывается, смена мажора — правкой декларации с пересозданием кластера.
- ~~Передача секретов и аргументов команды в image-демоны~~ — решено на применении:
  image-форма сразу переведена в `run`-форму docker (шаблоны `{{ env.* }}` рендерит
  pitchfork, проверено на opensearch), поведение задач не менялось.
- Канал образа MinIO: публичные образы MinIO закрыты во всех каналах (Docker Hub удалён
  2026-09-11, quay — только авторизованный pull, dl.min.io — 410, GitHub-релизы без
  бинарей; у владельца нет аккаунта quay). Решение: форк `united-software-platform/minio`
  собирает образ из исходников upstream-тега (workflow `build-image.yml`, еженедельно
  свежайший тег, ldflags вшивают версию) и публикует в публичный
  `ghcr.io/united-software-platform/minio` — анонимный pull, без логинов и смены сервиса.
  Обновление закреплённого тега в `mise.toml` — отдельным изменением.

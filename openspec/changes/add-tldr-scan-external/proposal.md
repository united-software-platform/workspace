# Proposal

## Why

Сканирование сторонних проектов — вне рабочего дерева этого проекта — сейчас требует ручного запуска
на хосте: агент из контейнера не может выполнить `sh tools/tldr/scan.sh <путь>`, потому что у него
нет ни `docker`, ни доступа к файловой системе хоста за пределами смонтированного рабочего дерева.
Цель `tldr-scan` через раннер сканирует только сам проект: раннер принимает одно имя цели и параметров
не передаёт. Ручной прогон сторонних проектов — повторяющийся шаг, который
хочется делать из сессии агента, как накат changelog через шлюз Liquibase.

## What Changes

- Появляется цель `make tldr-scan-ext`: шлюз `tools/tldr/gateway.py` читает файл запроса
  `.tldr/scan-request.json` (путь проекта на хосте, имя каталога отчётов, при желании расширение
  и скрываемые каталоги), проверяет его, запускает `tools/tldr/scan.sh` и пишет исход
  в `.tldr/scan-result.json`.
- Агент вызывает сканирование командой `tools/host-runner/call.sh tldr-scan-ext`: цель добавляется
  расширением блока `tldr-scan` в белом списке раннера, параметры едут файлом запроса — как у целей
  Liquibase Forge.
- Граница прав задаётся переменной `TLDR_SCAN_ROOTS` в `.env`: корни хоста через запятую, внутри
  которых шлюз разрешает сканировать. Пустое значение — внешние сканирования запрещены. Путь
  проверяется после нормализации симлинков, выход за корни — отказ без запуска сканирования.
- Отчёты сторонних сканирований складываются в `reports/<имя проекта>` рабочего дерева — агент читает
  их из контейнера; запись `.gitignore` расширяется с `/reports/tldr/` до `/reports/`, каталог обмена
  `.tldr/` добавляется в игнор.
- `tools/tldr/README.md` дополняется разделом о сканировании сторонних проектов: формат запроса,
  настройка корней, коды возврата шлюза.

## Capabilities

### New Capabilities

Нет: поведение расширяет существующую capability `code-scan`.

### Modified Capabilities

- `code-scan`: добавляются требования — сканирование сторонних проектов агентом через раннер по файлу
  запроса, разрешённые корни `TLDR_SCAN_ROOTS`, валидация запроса с отказом без запуска, файл
  результата с идентификатором запроса, исключение отчётов сторонних сканирований из git.

## Impact

- Код: новый `tools/tldr/gateway.py` (только стандартная библиотека — на хосте нет окружения проекта,
  `python3` уже нужен раннеру); цель `tldr-scan-ext` в блоке `tldr-scan` `Makefile`; расширение того же
  блока в `tools/host-runner/runner.py`.
- Конфигурация: `TLDR_SCAN_ROOTS` в блоке `tldr-scan` `.env.example`; `.gitignore` — `/reports/`
  вместо `/reports/tldr/`, плюс `.tldr/`.
- Документация: раздел в `tools/tldr/README.md`; файлы kit'а вне блоков не меняются, документация kit'а
  не правится.
- Права агента: раннер получает право читать сторонние каталоги хоста в пределах `TLDR_SCAN_ROOTS`
  только для чтения и только через отчёты tldr; каталоги монтируются в контейнеры сканирования `:ro`.
- Зависимости: `docker` и доступ к реестру образа tldr на хосте — уже требуются целью `tldr-scan`.

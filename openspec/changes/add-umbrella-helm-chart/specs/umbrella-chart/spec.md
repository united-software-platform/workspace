# Spec Delta

## Purpose

Зонтичный helm-чарт workspace: единый механизм, которым дочерние проекты получают сервисы общего набора в свой неймспейс, не пишая манифесты с нуля.

## ADDED Requirements

### Requirement: Чарт ставит включённые сервисы

Чарт `deploy/workspace` SHALL ставить каждый элемент списка `services` из values как пару
Deployment + Service (тип ClusterIP) в неймспейс применения. Пустой список `services` MUST
не ставить ни одного объекта. Сервисы чарта MUST NOT публиковать порты на хост.

#### Scenario: Включён один сервис

- **WHEN** чарт применяется со values, где `services` содержит одну позицию с образом и портом
- **THEN** в неймспейсе применения появляются Deployment и Service (ClusterIP) этого сервиса,
  а порты на хост не публикуются

#### Scenario: Набор пуст

- **WHEN** чарт применяется со values, где `services` пуст
- **THEN** в неймспейсе применения не появляется ни Deployment, ни Service

### Requirement: Применение одной задачей mise

Задача `mise run k3s-apply` SHALL применять чарт командой `helm upgrade --install workspace
deploy/workspace` в неймспейс из переменной `WORKSPACE_NAMESPACE` (умолчание — `workspace`),
создавая неймспейс при отсутствии. Повторное применение с теми же values MUST быть идемпотентным.

#### Scenario: Первое применение

- **WHEN** выполняется `mise run k3s-apply` при отсутствии неймспейса
- **THEN** неймспейс создаётся, релиз `workspace` устанавливается, включённые сервисы поднимаются

#### Scenario: Повторное применение

- **WHEN** `mise run k3s-apply` выполняется второй раз без изменения values
- **THEN** helm не меняет состояние кластера: применённых объектов столько же, ревизия релиза
  не увеличивает число подов

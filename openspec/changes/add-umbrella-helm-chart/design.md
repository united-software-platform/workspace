# Design

## Context

Кластер k3s после change `unify-environment` пуст: долгоживущих сервисов в наборе нет, единственный
исполнитель — Job tldr, собираемый `tools/tldr/scan.sh` на лету. ENV-007 объявил поставку сервисов
helm-манифестами зонтика в неймспейс потребителя — носителя у этой нормы пока нет.

## Goals / Non-Goals

**Goals:**

- каркас чарта, в котором включение сервиса общего набора — запись в values, а не новый манифест;
- применение одной командой из стандарта окружения (`mise run k3s-apply`).

**Non-Goals:**

- конкретные сервисы в наборе — появляются своими values при реальной потребности;

- локальный registry, PVC, Ingress — возвращаются с первым сервисом, которому они нужны;

- настройка ресурсов/проб per-service — минимальные поля сейчас, расширяются по необходимости.

## Decisions

- **values-фабрика вместо шаблона на сервис**: один `templates/service.yaml` разворачивает список
  `services[]`. Альтернатива — файл на каждый сервис — плодила бы копии одинаковых манифестов;
  фабрика держит механику в одном месте, а специфичный сервис позже получает собственный шаблон.
- **Service только ClusterIP**: доступ по ENV-003 — `kubectl port-forward`, публикация портов
  запрещена стандартом; в шаблоне тип зафиксирован явно.
- **Неймспейс применения, а не values**: неймспейс передаётся флагом `-n` из задачи mise
  (`WORKSPACE_NAMESPACE`), values его не содержит — один и тот же чарт ставится разным
  потребителям без правки values.
- **Пустой `services` валиден**: применение на пустом наборе — штатный случай «кластер ждёт»,
  чарт обязан проходить без объектов.

## Risks / Trade-offs

- [Фабрика ограничивает выразительность] → по мере роста потребностей специфичные сервисы
  получают собственные шаблоны рядом с фабрикой; values-подход не блокирует это.
- [helm отсутствует в среде ветки] → `helm lint` и применение остаются проверками хоста;
  синтаксис YAML проверен локально, шаблон — стандартная механика helm.

## Migration Plan

1. Создать чарт и задачу, прогнать `openspec validate`, проверить YAML.
2. На хосте владельца: `helm lint deploy/workspace`, `mise run k3s-apply` на пустом наборе —
  кластер без объектов; включить первый сервис values-записью при его появлении.
3. Archive изменения после приёмки.

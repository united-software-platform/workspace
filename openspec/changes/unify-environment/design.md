# Design

> **Примечание (2026-11-19):** стандарт сервисов этого изменения (k3s, helm, port-forward)
> до архивации superseded решением владельца о переходе на mise daemons — см. change
> `replace-k3s-with-mise-daemons`. Дельта `specs/environment/` удалена из этого изменения;
> ниже — исходный дизайн эпохи k3s как запись о проделанной работе.

## Context

Окружение сегодня целиком docker compose: агентские контейнеры claude/codex (образы sdd-kit,
bind-mount'ы рабочего дерева), Liquibase Forge (две Postgres и одноразовые прогоны liquibase),
tldr-скан одноразовым `compose run`. Задачи собраны в Makefile, переменные — в `.env`. Мотивация
изменения — в proposal.md (Why); решения о стандарте согласованы с владельцем: mise для
инструментария, k3s для сервисов, харнессы и forge исключены.

## Goals / Non-Goals

**Goals:**

- один зафиксированный стандарт окружения, пригодный для поставки дочерним проектам;
- контейнерная прослойка dev-набора и forge вырезаны без остатка мёртвых файлов;
- контракт tldr-сканирования (скрипт, шлюз, файлы запроса и результата, коды возврата) сохранён.

**Non-Goals:**

- миграция forge на k3s — forge отключается, возвращение отдельным изменением;
- локальный registry в кластере — после вырезки forge локально собираемых образов нет; вернёмся
  с первой реальной сборкой;
- поставка инфраструктуры реальным дочерним проектам — их ещё нет, стандарт фиксируется
  на пустом наборе.

## Decisions

- **Граница mise**: `node` (рантайм задач и навыков), `python` (скрипты среды: шлюз tldr,
  будущие задачи), `npm:@openspec/cli` (процесс разработки). Харнессы не закрепляются:
  контейнерной поставки больше нет, выбор агента — дело пользователя. Альтернатива — держать
  claude/codex в mise — отвергнута владельцем: среда не навязывает харнесс.
- **k3s вместо docker compose**: с уходом контейнерных раннеров главный аргумент за compose
  (bind-mount'ы интерактивных сессий) исчез; одноразовые прогоны (tldr) ложатся на Jobs,
  постоянных сервисов в наборе после вырезки forge нет — кластер становится платформой
  на вырост для сервисов дочерних проектов. Альтернатива compose отвергнута владельцем:
  два механизма в стандарте не допускаются.
- **Job сканирования tldr**: `tools/tldr/scan.sh` строит манифест Job (kubectl apply) вместо
  `docker run`: проект монтируется hostPath readOnly, скрываемые каталоги перекрываются
  emptyDir, отчёты пишутся в отдельный hostPath на каталог `reports/<имя>` (rw). Ожидание —
  `kubectl wait`, вывод — `kubectl logs`. hostPath допустим: кластер локальный, путь читается
  только на машине пользователя.
- **Переменные**: секреты (`EMBEDDINGS_API_KEY`) — `.env` (git-ignored), подключение через
  `[env]._file` в `mise.toml`; умолчания `TLDR_*` остаются внутри `tools/tldr/scan.sh` и в `[env]`
  не дублируются — значения `[env]` перекрывают переменные process-окружения (проверено
  экспериментом), а контракт сканирования требует приоритета окружения. Шаблон `.env.example`
  перечисляет только секретные имена и локальные значения git-хоста.
- **Задачи mise вместо Make**: задачи объявляются в `mise.toml` секцией `[tasks]`; SSH-логика
  переносится из рецептов Makefile один в один (идемпотентность сохраняется). Отдельные
  скрипты не заводятся, пока задача помещается в inline-recipe — скриптовая прослойка
  Make-эпохи (`tools/init/`, `tools/forge-env/`) не воссоздаётся.
- **Правила**: `rules/environment.md` — новый носитель стандарта; `makefile-rules.md` и
  `docker.md` покидают поставку вместе со своими предметами; перечни `CLAUDE.md` и `AGENTS.md`
  правятся синхронно.

## Risks / Trade-offs

- [k3s ест память машины] → принимается владельцем; на машинах без запаса сканирование можно
  запускать на любом внешнем кластере с тем же манифестом.
- [hostPath в Job сканирования] → каталог проекта монтируется readOnly; запись идёт только
  в каталог отчётов.
- [Не-Linux хосты требуют VM под k3s] → фиксируется в «Ограничениях» README (DOC-020).
- [Потеря forge-инструментария] → вырезка обратима историей git; возвращение — отдельным
  изменением с миграцией на k3s.

## Migration Plan

1. Породить и принять change `unify-environment` (openspec validate — чисто).
2. Удалить вырезаемое, править `mise.toml`, `.env.example`, `.gitignore`, правила, перечни,
   README, tldr-скрипты; прогнать проверки.
3. Archive изменения после приёмки; кластер k3s и helm — предусловия хоста по README,
   устанавливаются пользователем отдельно.

Откат: git revert правки ветки; контейнерное окружение восстанавливается из истории.

# environment Specification

## Purpose
Единый стандарт окружения зонтичного репозитория workspace: mise — единственный менеджер —
закрепляет инструментарий, задачи и демоны сервисов общего набора; порты и переменные
подключения стандартизованы, дочерние проекты подключаются через каскад mise.

## Requirements

### Requirement: Инструментарий через mise

Окружение SHALL закреплять инструментарий в `mise.toml` и ставить командой `mise install`:
рантайм проекта (`node`, `python`), CLI процесса разработки (`npm:@fission-ai/openspec`)
и supervisor демонов (`pitchfork`). Харнессы — claude, codex, dsh — MUST NOT закрепляться
и навязываться поставкой.

#### Scenario: Свежий клон

- **WHEN** пользователь клонирует репозиторий и выполняет `mise install`
- **THEN** весь закреплённый инструментарий, включая supervisor демонов, устанавливается
  без ручных шагов

### Requirement: Сервисы общего набора через демоны mise

Долгоживущие сервисы окружения SHALL объявляться демонами mise в `mise.toml`. Общий набор —
PostgreSQL, OpenSearch, MinIO — один экземпляр каждого: PostgreSQL — нативным пресетом демона
без контейнерного рантайма, OpenSearch и MinIO — image-демонами под docker/podman. Локальный
кластер k3s, helm и docker compose MUST NOT использоваться.

#### Scenario: Подъём общего набора

- **WHEN** выполняется задача подъёма окружения
- **THEN** три сервиса общего набора запускаются демонами и проходят проверку готовности

#### Scenario: PostgreSQL без контейнерного рантайма

- **WHEN** запускается демон PostgreSQL
- **THEN** он исполняется нативным процессом из пресета, не требуя docker или podman

### Requirement: Версии сервисов закреплены в декларациях

Версия каждого сервиса общего набора MUST быть закреплена в его декларации демона: версией
пресета для PostgreSQL и тегом образа для OpenSearch и MinIO. Закреплённые версии MUST
переживать перезапуск демонов без изменений.

#### Scenario: Перезапуск не меняет версий

- **WHEN** демоны останавливаются и запускаются снова
- **THEN** сервисы поднимаются тех же закреплённых версий

### Requirement: Фиксированные локальные порты сервисов

Демоны сервисов SHALL слушать фиксированные порты localhost, объявленные в декларациях
демонов `mise.toml`: PostgreSQL — 5432, OpenSearch — 9200, MinIO — 9000. Доступ с хоста —
прямым обращением по локальному адресу; `kubectl port-forward` и иная туннельная механика
MUST NOT требоваться.

#### Scenario: Обращение к сервису

- **WHEN** пользователю нужен доступ к сервису общего набора
- **THEN** он обращается по `localhost` и закреплённому порту без туннелей и проброса

#### Scenario: Порт стабилен между запусками

- **WHEN** окружение останавливается и поднимается снова
- **THEN** сервисы слушают те же порты, что и до остановки

### Requirement: Координаты подключения через секцию env

Несекретные координаты подключения к общему набору SHALL объявляться переменными `PG_PORT`,
`OPENSEARCH_PORT`, `MINIO_PORT` в секции `[env]` корневого `mise.toml`; значения MUST совпадать
с портами в декларациях демонов. Каскад конфигураций mise SHALL доносить эти переменные до
дочерних проектов.

#### Scenario: Задача видит координаты

- **WHEN** задача mise запускается командой `mise run`
- **THEN** ей доступны `PG_PORT`, `OPENSEARCH_PORT`, `MINIO_PORT` без ручного экспорта

#### Scenario: Дочерний проект наследует координаты

- **WHEN** дочерний проект лежит в дереве workspace со своим `mise.toml`
- **THEN** его задачи видят координаты общего набора из корневого `mise.toml` через каскад

### Requirement: Секреты в .env, имена в .env.example

Секретные значения окружения SHALL лежать в git-ignored файле `.env`, подключаемом записью
`_.file = ".env"` в секции `[env]`; шаблон `.env.example` MUST перечислять имена секретных
переменных с пустыми значениями: `POSTGRES_PASSWORD`, `OPENSEARCH_ADMIN_PASSWORD`,
`MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`. Секретные значения MUST NOT попадать в репозиторий;
умолчания инструментов в `[env]` MUST NOT дублироваться — значения `[env]` перекрывают
process-окружение.

#### Scenario: Секрет не в git

- **WHEN** пользователь заполняет `.env` реальными значениями
- **THEN** `git status` не показывает `.env`, а `.env.example` содержит только имена

#### Scenario: Демон получает секреты локально

- **WHEN** демоны запускаются на машине с заполненным `.env`
- **THEN** сервисы получают секреты из значений файла, не хранящихся в репозитории

### Requirement: Задачи окружения в mise

Задачи окружения SHALL быть задачами mise и запускаться `mise run <имя>`: подъём и остановка
общего набора, статус окружения, инициализация локальных файлов, openspec-init и задачи
сканирования. Задачи инициализации MUST быть идемпотентными. Makefile MUST NOT использоваться.

#### Scenario: Подъём и остановка окружения

- **WHEN** выполняются `mise run env-up` и затем `mise run env-down`
- **THEN** общий набор поднимается с ожиданием готовности и останавливается без остатка

#### Scenario: Статус окружения

- **WHEN** выполняется `mise run env-status`
- **THEN** выводится состояние каждого демона набора — запущен или остановлен

### Requirement: Одноразовые прогоны контейнерами

Одноразовые прогоны окружения — сканирования, миграции-проверки — SHALL исполняться
одноразовыми контейнерами `docker run --rm`, запускаемыми задачами mise, с монтированием
нужных путей рабочего дерева. Прогон MUST завершаться вместе с контейнером, не оставляя
долгоживущих процессов и объектов.

#### Scenario: Одноразовое сканирование

- **WHEN** запускается задача сканирования проекта
- **THEN** контейнер выполняет прогон, складывает отчёты в смонтированный каталог и завершается

### Requirement: Зонтичная поставка демонами

workspace — зонтичный репозиторий: общий набор сервисов SHALL объявляться демонами корневого
`mise.toml`, дочерние проекты потребляют набор через каскад mise. Изоляция по умолчанию —
логическая внутри общих экземпляров: отдельные БД, префиксы индексов, отдельные бакеты.
Выделенный экземпляр MUST быть собственной декларацией демона в `mise.toml` проекта —
осознанное исключение, когда изоляция важнее экономии ресурсов.

#### Scenario: Новый проект без новых контейнеров

- **WHEN** в дерево workspace добавляется дочерний проект
- **THEN** ему не требуется новых экземпляров сервисов — данные создаются внутри общих

#### Scenario: Выделенный экземпляр

- **WHEN** проекту нужна изолированная версия сервиса
- **THEN** проект объявляет собственный демон с нужной версией, не затрагивая общий набор

### Requirement: Экспериментальный статус mise daemons принят

Стандарт строится на экспериментальной фичи mise daemons: формат деклараций может меняться
между версиями mise и pitchfork. Версии mise и pitchfork MUST быть закреплены; смена формата
деклараций MUST оформляться отдельным изменением, а не ручной правкой на местах. Флаг
experimental MUST быть включён в `mise.toml` явно.

#### Scenario: Закреплённые версии инструментов

- **WHEN** окружение разворачивается на новой машине
- **THEN** mise и pitchfork ставятся закреплённых версий из `mise.toml`

#### Scenario: Изменение формата деклараций

- **WHEN** новая версия mise меняет формат деклараций демонов
- **THEN** переход оформляется отдельным изменением с проверкой подъёма окружения

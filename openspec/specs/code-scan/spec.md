# code-scan Specification

## Purpose

Сканирование кода проекта образом tldr: набор отчётов об устройстве, безопасности, качестве и архитектуре
кода, который получает и человек на хосте, и агент из контейнера через раннер.

## Requirements

### Requirement: Запуск сканирования скриптом инструмента

Скрипт сканирования SHALL располагаться в каталоге инструмента `tools/tldr/` под именем `scan.sh`
и вызываться командой `sh tools/tldr/scan.sh <путь к проекту> [каталог отчётов]`. Без каталога отчётов
скрипт MUST писать отчёты в `reports/<имя каталога проекта>` относительно текущего каталога.

#### Scenario: Вызов с путём проекта

- **WHEN** пользователь выполняет `sh tools/tldr/scan.sh /path/to/shop`
- **THEN** отчёты появляются в `reports/shop` текущего каталога

#### Scenario: Вызов без аргументов

- **WHEN** пользователь выполняет `sh tools/tldr/scan.sh` без пути проекта
- **THEN** скрипт печатает строку использования в stderr и завершается с кодом `2`

### Requirement: Проект недоступен сканированию для записи

Сканирование MUST получать проект только для чтения. Каталоги, скрытые от анализа, MUST перекрываться
пустыми каталогами внутри контейнера сканирования и не меняться на хосте. Скрываемый каталог,
которого в проекте нет, MUST пропускаться с сообщением, а не прерывать сканирование.

#### Scenario: Скрытие существующего каталога

- **WHEN** в проекте есть каталог `vendor` и он входит в скрываемые
- **THEN** команды tldr видят `vendor` пустым, а содержимое `vendor` на хосте не меняется

#### Scenario: Скрываемого каталога нет

- **WHEN** скрываемого каталога `public` в проекте нет
- **THEN** скрипт печатает `exclude: public — not found, skipped` и продолжает сканирование

### Requirement: Отчёт на каждую команду

Сканирование SHALL выполнять команды tldr по четырём уровням — обзор, безопасность, качество и горячие
точки, архитектура — и писать stdout каждой команды в свой файл отчёта, а stderr — в соседний файл
`.err`, удаляемый, если он пуст. По каждой команде MUST печататься строка со статусом `ok` или `FAIL`,
временем и самой командой. Сбой одной команды MUST NOT останавливать остальные.

#### Scenario: Одна команда завершилась ошибкой

- **WHEN** команда `inheritance` завершается ненулевым кодом
- **THEN** её строка помечена `FAIL`, рядом с её отчётом лежит непустой `.err`, а следующие команды выполняются

#### Scenario: Команда без вывода в stderr

- **WHEN** команда завершается успешно и ничего не пишет в stderr
- **THEN** файла `.err` для её отчёта нет

### Requirement: Команды по истории git только при наличии репозитория

Команды, анализирующие историю изменений (`hotspots`, `churn`), SHALL выполняться, только если в корне
проекта есть каталог `.git`; иначе сканирование MUST сообщать об их пропуске.

#### Scenario: Проект без репозитория git

- **WHEN** в корне проекта нет каталога `.git`
- **THEN** скрипт печатает `skip hotspots, churn — no .git in project`, а остальные команды выполняются

### Requirement: Коды возврата сканирования

Сканирование SHALL завершаться кодом `0`, если все команды выполнены, кодом `1`, если часть команд
завершилась ошибкой, и кодом `2` при ошибке вызова или окружения: нет пути проекта, каталог проекта
не найден, нет `docker`, не удалось загрузить образ.

#### Scenario: Нет docker

- **WHEN** `docker` не найден в `PATH`
- **THEN** скрипт печатает `error: docker not found in PATH` и завершается с кодом `2`

#### Scenario: Часть команд упала

- **WHEN** 17 из 18 команд выполнены, одна завершилась ошибкой
- **THEN** скрипт печатает `17/18 commands succeeded` и завершается с кодом `1`

### Requirement: Цель make для сканирования проекта

Цель `make tldr-scan` SHALL сканировать корень проекта и складывать отчёты в `reports/tldr`. Каталог
`reports` MUST всегда скрываться от анализа, чтобы прогон не учитывал отчёты прошлого. Каталог
`reports/tldr` MUST быть исключён из git.

#### Scenario: Повторный прогон

- **WHEN** `make tldr-scan` выполняется второй раз и в `reports/tldr` лежат отчёты прошлого прогона
- **THEN** отчёты прошлого прогона не попадают в анализ, а `git status` их не показывает

### Requirement: Настройка сканирования через окружение

Цель `make tldr-scan` SHALL брать образ, расширение дерева файлов и скрываемые каталоги из переменных
`TLDR_IMAGE`, `TLDR_EXT`, `TLDR_EXCLUDE`: сначала из окружения, затем из `.env`. Пустое значение MUST
оставлять умолчание: образ `ghcr.io/united-software-platform/tldr-code:latest`, расширение `.php`,
каталоги `vendor` и `public`. `TLDR_EXCLUDE` MUST задаваться списком каталогов через запятую.

#### Scenario: Настройки из .env

- **WHEN** в `.env` заданы `TLDR_EXT=.py` и `TLDR_EXCLUDE=.idea,backlog`, а в окружении этих переменных нет
- **THEN** дерево файлов строится по `.py`, а скрыты каталоги `.idea`, `backlog` и `reports`

#### Scenario: Переменные не заданы

- **WHEN** переменные `TLDR_*` пусты и в окружении, и в `.env`
- **THEN** сканирование идёт образом по умолчанию по `.php`, а скрыты `vendor`, `public` и `reports`

### Requirement: Запуск сканирования агентом через раннер

Цель `tldr-scan` SHALL входить в белый список раннера на хосте, чтобы агент в контейнере без `docker`
и `make` запускал сканирование командой `tools/host-runner/call.sh tldr-scan` и получал вывод цели
с её кодом возврата.

#### Scenario: Запрос сканирования агентом

- **WHEN** агент выполняет `tools/host-runner/call.sh tldr-scan` при запущенном раннере
- **THEN** раннер выполняет `make tldr-scan` на хосте, агент получает построчный вывод сканирования, а отчёты доступны ему в `reports/tldr` рабочего дерева

#### Scenario: Сканирование с ошибками через раннер

- **WHEN** часть команд сканирования завершилась ошибкой
- **THEN** ответ раннера начинается не с `exit: 0`, и `call.sh` завершается ненулевым кодом

### Requirement: Встраивание в файлы kit'а только помеченными блоками

Цель, переменные окружения, запись `.gitignore` и расширение белого списка раннера MUST добавляться
в файлы проекта только блоками между строками `# >>> tldr-scan` и `# <<< tldr-scan`. Содержимое файлов
kit'а вне этих блоков MUST NOT меняться, а файлы документации kit'а MUST NOT править вовсе.

#### Scenario: Сверка с манифестом kit'а

- **WHEN** из `tools/host-runner/runner.py` удалены блоки `tldr-scan` и `liquibase-forge`
- **THEN** контрольная сумма файла совпадает с записанной в `.sdd-kit-manifest.json`

#### Scenario: Документация раннера

- **WHEN** интеграция сканирования установлена
- **THEN** `tools/host-runner/README.md` совпадает с версией kit'а, а вызов сканирования агентом описан в `tools/tldr/README.md`

# domain-classifier

CLI-утилита классификации проектов по таксономии SPCF 2.0: по карточке проекта возвращает
контракт классификации по уровням L1–L4 с показателями уверенности. Понятия рабочего
пространства и классификации определены в [глоссарии](../../GLOSSARY.md).

## Справочник таксономии

Источник истины для сверки — [`taxonomy/`](./taxonomy/) внутри утилиты: выгрузка
SPCF 2.0 из 10 файлов JSON (17 записей L1, 35 L2, 24 L3, 34 L4, технологические паттерны,
правила классификации, манифест и вымышленные примеры). Справочник поставляется вместе
с утилитой и читается при каждом прогоне; переопределяется флагом `--export-dir`.
Таксономия принимается как есть — утилита её не правит.

## Установка

```bash
cd tools/classifier
uv sync
```

## Команда

```bash
uv run classifier <путь к карточке.json> [--threshold 0.5]
```

Карточка — файл JSON вне репозитория. Обезличенный шаблон:

```json
{
  "name": "novamart-checkout",
  "purpose": "Сервис оформления заказа магазина NovaMart: корзина, оплата, подтверждение заказа",
  "facets": {
    "origin": "venture",
    "organization": "novamart",
    "group": "novamart-platform",
    "customer": null,
    "period": { "from": 2026, "to": null },
    "status": "active",
    "technologies": ["go", "postgresql", "kafka", "docker"],
    "domains": ["ecommerce"],
    "roles": ["developer"]
  }
}
```

Полный состав входного и выходного контрактов — [docs/contracts.md](./docs/contracts.md).

## Коды возврата

| Код | Что значит | Что делаю |
|-----|------------|-----------|
| `0` | Классификация получена, порог пройден | Беру результат; пограничные уровни несут метку «A & B» в `combined_labels` |
| `1` | Классификация получена, но needs_confirmation=true: primary уровня ниже порога | Дополняю карточку и прогоняю заново |
| `2` | Ошибка входа или окружения | Проверяю карточку, переменные, эндпоинт |

## Переменные окружения

| Имя | Назначение |
|-----|------------|
| `EMBEDDINGS_BASE_URL` | Адрес OpenAI-совместимого эндпоинта embeddings за прокси |
| `EMBEDDINGS_API_KEY` | Ключ доступа к эндпоинту |
| `EMBEDDINGS_MODEL` | Идентификатор модели embeddings |

Значения локальные, в git попадают только имена (`.env.example` репозитория).

## Проверки

```bash
uv run pytest        # тесты (фейковый клиент embeddings, сети нет)
uv run mypy src      # типы
uv run ruff check .  # линтер
```

Интеграционные тесты CLI идут на `CLASSIFIER_EMBEDDINGS=stub` — детерминированный
фейк без сети; живой эндпоинт проверяется диагностическим скриптом
`uv run python scripts/live_run.py` (требует переменных `EMBEDDINGS_*`).
Тестовый режим `stub` — единственное допустимое значение флага.

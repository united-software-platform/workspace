## Веб-сверка с референсами

Метод: поисковые запросы через Perplexity-прокси, фиксация первичных источников (URL).
Сверка поверхностная — названия категорий и назначение уровней; определения и переводы
остаются полномасштабному аудиту.

### L1 — Application Domains

Референс: ISIC Rev.4 (классификатор видов экономической деятельности, ООН) и ACM CCS
2012 (таксономия информатики). Публичных следов самого SPCF в интернете нет — таксономия
самостоятельная, внешнего источника происхождения не существует.

| Категория L1 | Референс | Наблюдение |
|--------------|----------|------------|
| Healthcare, Finance, Commerce & Trade, Manufacturing, Logistics, Government & Public Sector | ISIC разделы Q, K, G, C, H, O | соответствуют отраслям |
| Software Engineering, IT Operations, Data Engineering, Artificial Intelligence, Cybersecurity | ISIC J62; ACM CCS | ИТ-области, соответствуют |
| Analytics & Reporting | ISIC — функция (деятельность офисной поддержки, 829), не отрасль | кандидат на проверку: функция, а не предметная область |
| Knowledge Engineering | классика: «прикладная сторона ИИ» (Feigenbaum, Stanford) | кандидат на проверку: пересечение с Artificial Intelligence |
| Mathematics & Formal Methods | ACM CCS Mathematics of computing | соответствие допустимо, но проверить назначение |
| Science & Research, Information Management | ISIC M | соответствуют |

### L2 — Activity Subdomains

Референс: SFIA 9 (147 навыков, категории деятельности) и SWEBOK v4 (18 областей знаний).
Инженерная часть L2 (Requirements Engineering, Software Architecture, Software Quality &
Testing, DevOps, Configuration Management) хорошо согласуется с SWEBOK KAs и SFIA.

| Категория L2 | Наблюдение |
|--------------|------------|
| Business Process Management, Customer Management, Order Management | бизнес-дисциплины, допустимы |
| E-commerce Management, Checkout & Payment Processing, Product Catalog Management, Product Recommendation | функции конкретной предметной области (e-commerce), не дисциплины; добавлены под вымышленные примеры — кандидаты на проверку уровня |
| Public Service Delivery, Official Information Publishing, Procurement & Tender Management | отраслевые функции госсектора — та же претензия, но с обоснованием WRSP-023/024 |
| LLM Engineering, AI Agent Engineering, Knowledge Graph Engineering, Ontology Engineering | современные дисциплины, в SFIA/SWEBOK отсутствуют — самостоятельность SPCF здесь оправдана |

### L3 — Problem Domains

Внешнего классификатора «проблем проектов» не существует: литература по technical debt
покрывает только часть (Architecture Drift, Poor Code Understandability). Сверка L3
с внешними референсами неприменима; проверка — внутренняя согласованность
(непересечение формулировок, уровень абстракции). Ничего противоречащего не найдено.

### L4 — Solution Archetypes

Референсы: таксономии корпоративных систем (ERP/CRM/BPM/KMS), ecosyste.ms oss-taxonomy,
типологии программных продуктов. ERP/CRM/BPM/KMS/Enterprise Search/Data Platform/
Recommendation Engine соответствуют устоявшимся классам систем.

| Категория L4 | Наблюдение |
|--------------|------------|
| Government Information System | закреплено задачей WRSP-023, соответствует классу государственных АИС |
| Standard or Specification, Research Artifact | нетрадиционные, но валидные классы результата (стандартизация допускает такие deliverables — W3C/COPRAS, ASAM) |
| Development or Runtime Environment | размытое имя с «or» — кандидат на переименование/разделение |
| Platform Software Component | широкий класс — кандидат на уточнение границ |

### Technology Patterns

`code` во всех 10 записях — аббревиатуры верхним регистром (`RAG`, `LLM`, `BM25`),
не kebab-case, в отличие от L1–L4. Загрузчик и тесты формат не ограничивают —
несоответствие конвенции, не функциональный дефект.

## Реестр дефектов

| № | Тип | Критичность | Описание |
|---|-----|-------------|----------|
| 001 | целостность документации | low | README заявляет L1=16, L2=36, L3=25, L4=34; фактически 17/35/24/34 |
| 002 | конвенция кода | low | `code` записей Technology Patterns не в kebab-case (10 записей) |
| 003 | семантика уровня | medium | L2 содержит функции e-commerce (4 записи) — нарушают правило «L2 — дисциплина, а не предметная функция» |
| 004 | семантика уровня | medium | L1 Analytics & Reporting — функция, не предметная область; Knowledge Engineering пересекается с Artificial Intelligence |
| 005 | именование | low | L4 Development or Runtime Environment — имя с «or», размывает класс |

Дефекты 003–005 требуют семантического решения по Decision Protocol полного аудита;
в этой фазе они только зафиксированы.

## Выводы для проектирования аудита

1. Инструментальная база зелёная (pytest/mypy/ruff), структурная целостность данных
   не нарушена — аудит может сфокусироваться на семантике и терминах.
2. Реальная внешняя сверка возможна для L1 (ISIC), L2 (SFIA/SWEBOK) и L4 (таксономии
   систем); для L3 внешнего референса нет — только внутренние проверки. ISO/IEC 25010
   для сверки категорий неприменим.
3. Основной класс семантических рисков — смешение уровней: предметные функции
   в L2, пересечения внутри L1. Проверку «категория на своём уровне» стоит делать
   первичной семантической проверкой аудита.
4. Рассинхрон README — модельный дефект для правила «не считать README источником
   истины»: количества должны читаться из manifest, а не дублироваться текстом.

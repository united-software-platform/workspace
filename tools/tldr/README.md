# Сканирование кода образом tldr

Сканирует код проекта образом tldr и складывает отчёты об устройстве, безопасности, качестве
и архитектуре кода в `reports/tldr`. Вызывается и человеком на хосте, и агентом из контейнера —
через раннер целей.

## Как это работает

Скрипт [scan.sh](./scan.sh) выполняет команды tldr в одноразовых контейнерах образа
`ghcr.io/united-software-platform/tldr-code`. Проект монтируется в контейнер только для чтения;
каталоги, скрытые от анализа, перекрываются пустыми `tmpfs` внутри контейнера и на хосте
не меняются. Скрываемый каталог, которого в проекте нет, пропускается с сообщением.

Каждая команда пишет stdout в свой файл отчёта, stderr — в соседний файл `.err`, удаляемый,
если он пуст. По каждой команде печатается строка со статусом `ok` или `FAIL`, временем
и самой командой. Сбой одной команды не останавливает остальные.

## Вызов человеком на хосте

Сканирование корня этого проекта — отчёты в `reports/tldr`:

```bash
make tldr-scan
```

Сканирование стороннего проекта или другой каталог отчётов — напрямую скриптом:

```bash
sh tools/tldr/scan.sh <путь к проекту> [каталог отчётов]
```

Без каталога отчётов скрипт пишет в `reports/<имя проекта>` текущего каталога. Цель `make`
всегда скрывает каталог `reports` от анализа, чтобы повторный прогон не учитывал отчёты
прошлого.

## Вызов агентом через раннер

В контейнере агента нет ни `docker`, ни `make`, поэтому сканирование запускается через раннер
целей на хосте:

```bash
tools/host-runner/call.sh tldr-scan
```

Раннер выполняет `make tldr-scan`, возвращает построчный вывод и код возврата. Отчёты лежат
в `reports/tldr` рабочего дерева и доступны агенту из контейнера. Устройство раннера —
в [README раннера](../host-runner/README.md).

Раннер читает переменные `TLDR_*` один раз, при старте, а значение окружения приоритетнее
`.env`: после правки переменных в `.env` раннер нужно перезапустить — иначе цель выполнится
со старыми настройками.

## Переменные окружения

Значение берётся сначала из окружения, затем из `.env`, затем — умолчание скрипта. Пустое
значение оставляет умолчание. Переменные задаются в `.env` в блоке `tldr-scan`
(шаблон — [.env.example](../../.env.example)).

| Переменная | Умолчание | Назначение |
|------------|-----------|------------|
| `TLDR_IMAGE` | `ghcr.io/united-software-platform/tldr-code:latest` | Образ tldr |
| `TLDR_EXT` | `.php` | Расширение, по которому строится дерево файлов |
| `TLDR_EXCLUDE` | `vendor,public` | Скрываемые каталоги от корня проекта, через запятую |

Каталог `reports` скрыт от анализа всегда, независимо от `TLDR_EXCLUDE`. Каталоги
перечисляются именно через запятую: значение с пробелом сломало бы загрузку `.env` командой `.`
при запуске раннера.

## Отчёты

Восемнадцать команд по четырём уровням; `hotspots` и `churn` выполняются только при наличии
`.git` в корне сканируемого проекта, иначе печатается пропуск.

| Уровень | Файлы отчётов |
|---------|---------------|
| Обзор (L1, метрики) | `01-tree.json`, `02-loc.json`, `03-structure.json`, `04-health.json` |
| Безопасность | `10-secure.json`, `11-vuln.json`, `12-api-check.json` |
| Качество и горячие точки | `20-hotspots.json`, `21-churn.json`, `22-cognitive.json`, `23-smells.json`, `24-clones.json`, `25-debt.json` |
| Архитектура (L2, паттерны) | `30-calls.json`, `31-hubs.json`, `32-inheritance.json`, `33-coupling.json`, `34-dead.json` |

Рядом с отчётом упавшей команды остаётся непустой `.err` — текст её stderr.

## Коды возврата

| Код | Что значит | Что делаю |
|-----|------------|-----------|
| `0` | Все команды выполнены | Читаю отчёты в `reports/tldr` |
| `1` | Часть команд завершилась ошибкой | Смотрю строки `FAIL` и соседние файлы `.err` |
| `2` | Ошибка вызова или окружения: нет пути проекта, каталог не найден, нет `docker`, не загрузился образ | Проверяю аргументы вызова и окружение хоста |

## Ограничения

- **Перезапуск раннера после правки `TLDR_*`.** Раннер держит значения из окружения,
  прочитанного при старте, а окружение приоритетнее `.env` — без перезапуска цель выполнится
  со старыми настройками.
- **Предел раннера — `AGENT_RUNNER_TIMEOUT`**, по умолчанию 900 секунд на цель: на большом
  проекте 18 команд и первая загрузка образа могут его превысить. На хосте цель запускается
  без предела.
- **`inheritance` отказывается разбирать файлы больше 5 242 880 байт**, не называя файл.
  Найти такие файлы: `find . -type f -size +5M`; скрыть содержащий каталог — добавить его
  в `TLDR_EXCLUDE`.
- **Тег образа `latest` не закреплён**: состав команд и их вывод меняются вместе с образом.
  Закрепить — задать в `TLDR_IMAGE` точный тег или digest.
- **Скрипт полагается на рабочий каталог образа** `/project` и не передаёт `-w`: при смене
  образа ошибка проявится сканированием не того каталога.
- **Проект монтируется только для чтения**: цель пишет в рабочее дерево лишь отчёты
  в `reports/tldr`.

## Блоки в файлах kit'а

`Makefile`, `.env.example`, `.gitignore` и [runner.py](../host-runner/runner.py) принадлежат
SDD Developer Kit и записаны в `.sdd-kit-manifest.json` с контрольными суммами, поэтому
интеграция добавлена в них помеченными блоками `# >>> tldr-scan` … `# <<< tldr-scan`, а не
правкой содержимого kit'а:

- `Makefile` — цель `tldr-scan` со своим `.PHONY` и разборщиком `tldr_env_value`;
- `.env.example` — переменные `TLDR_IMAGE`, `TLDR_EXT`, `TLDR_EXCLUDE`;
- `.gitignore` — запись `/reports/tldr/`;
- `runner.py` — расширение белого списка целью `tldr-scan`.

Обновление kit'а, переписывающее файл целиком, может удалить блоки. Восстановить — повторить
содержимое блоков ниже в тех же местах файлов.

```makefile
# >>> tldr-scan
# Значение переменной tldr-сканирования из .env. Собственный разборщик, а не env_value kit'а:
# блок не зависит от внутренних имён Makefile kit'а и переживёт его обновление. Разбор построчный
# по той же причине: .env — файл секретов, его содержимое не попадает в пространство имён make.
tldr_env_value = $$(sed -n 's/^$(1)=//p' .env 2>/dev/null | tail -n 1)

.PHONY: tldr-scan

# Сканирование проекта образом tldr. Цель вызывается и раннером по запросу агента, а раннер
# параметров не передаёт: образ, расширение и скрываемые каталоги берутся из окружения или .env,
# пустое значение оставляет умолчание tools/tldr/scan.sh. Каталоги в TLDR_EXCLUDE перечисляются
# через запятую — значение с пробелом ломало бы загрузку .env командой «.» при запуске раннера.
# Отчёты лежат в рабочем дереве, чтобы агент прочитал их из контейнера, и сами скрыты от анализа,
# иначе повторный прогон учёл бы JSON прошлого; поэтому умолчание vendor,public задано и здесь.
tldr-scan: ## Сканировать проект образом tldr, отчёты — в reports/tldr
	@image="$${TLDR_IMAGE:-$(tldr_env_value,TLDR_IMAGE)}"; \
	ext="$${TLDR_EXT:-$(tldr_env_value,TLDR_EXT)}"; \
	exclude="$${TLDR_EXCLUDE:-$(tldr_env_value,TLDR_EXCLUDE)}"; \
	exclude="$$(printf '%s' "$${exclude:-vendor,public}" | tr ',' ' ') reports"; \
	TLDR_IMAGE="$$image" EXT="$$ext" EXCLUDE="$$exclude" sh tools/tldr/scan.sh . reports/tldr
# <<< tldr-scan
```

```bash
# >>> tldr-scan
# Сканирование проекта образом tldr (make tldr-scan). Пусто — умолчание tools/tldr/scan.sh:
# образ ghcr.io/united-software-platform/tldr-code:latest, расширение .php, скрыты vendor и public.
# TLDR_EXCLUDE — каталоги от корня проекта через запятую. После правки перезапустить раннер
TLDR_IMAGE=
TLDR_EXT=
TLDR_EXCLUDE=
# <<< tldr-scan
```

```gitignore
# >>> tldr-scan
# Отчёты make tldr-scan — результат прогона, а не исходники
/reports/tldr/
# <<< tldr-scan
```

```python
# >>> tldr-scan
# Сканирование проекта образом tldr. Блок стоит за определением белого списка любой формы
# и расширяет его, не трогая литерал: цель tldr-scan запускает на хосте контейнеры образа
# tldr, но проект монтирует им только для чтения — в рабочем дереве цель пишет лишь отчёты
# в reports/tldr. Настройка и вызов — tools/tldr/README.md.
ALLOWED_TARGETS = ALLOWED_TARGETS | frozenset({"tldr-scan"})
# <<< tldr-scan
```

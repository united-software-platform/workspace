# Сканирование кода образом tldr

Сканирует код проекта образом tldr и складывает отчёты об устройстве, безопасности, качестве
и архитектуре кода в `reports/tldr`. Запускается задачей mise на хосте; сканирование исполняется
Job'ом в локальном кластере k3s.

## Как это работает

Скрипт [scan.sh](./scan.sh) собирает манифест Job'а и применяет его в кластер k3s. Образ
`ghcr.io/united-software-platform/tldr-code` исполняет команды tldr внутри Job'а: проект
монтируется в `/project` hostPath'ом только для чтения; каталоги, скрытые от анализа,
перекрываются пустыми tmpfs (`emptyDir` c `medium: Memory`) поверх монтирования и на хосте
не меняются. Отчёты пишутся в `/reports` — hostPath каталога отчётов на хосте.

Каждая команда пишет stdout в свой файл отчёта, stderr — в соседний файл `.err`, удаляемый,
если он пуст. По каждой команде печатается строка со статусом `ok` или `FAIL`, временем
и самой командой. Сбой одной команды не останавливает остальные. Итоговый вывод Job'а
печатается `kubectl logs` по завершении; сам Job удаляется.

## Вызов на хосте

Сканирование корня этого проекта — отчёты в `reports/tldr`:

```bash
mise run tldr-scan
```

Задача всегда скрывает каталог `reports` от анализа, чтобы повторный прогон не учитывал отчёты
прошлого. Сканирование стороннего проекта или другой каталог отчётов — напрямую скриптом:

```bash
sh tools/tldr/scan.sh <путь к проекту> [каталог отчётов]
```

Без каталога отчётов скрипт пишет в `reports/<имя проекта>` текущего каталога.

## Сканирование стороннего проекта

Проект вне рабочего дерева — например, соседний репозиторий на хосте — сканируется задачей
`tldr-scan-ext` через шлюз [gateway.py](./gateway.py): параметры едут файлом запроса.

Вызов:

```bash
mise run tldr-scan-ext
```

Файл запроса `.tldr/scan-request.json`:

```json
{
  "request_id": "req-001",
  "project": "/home/user/workspace/shop",
  "report_name": "shop",
  "ext": ".py",
  "exclude": "vendor,node_modules"
}
```

| Поле | Обязательность | Назначение |
|------|----------------|------------|
| `request_id` | да | Непустая строка; связывает запрос с файлом результата |
| `project` | да | Абсолютный путь к каталогу проекта на хосте |
| `report_name` | да | Имя каталога отчётов: отчёты лягут в `reports/<report_name>` рабочего дерева |
| `ext` | нет | Расширение дерева файлов с ведущей точкой; пусто — `TLDR_EXT`/умолчание `.php` |
| `exclude` | нет | Скрываемые каталоги от корня проекта через запятую, без пробелов |

Результат — в `.tldr/scan-result.json`, поля `request_id`, `exit_code`, `stdout`, `stderr`.
Принимать его стоит только при совпадении `request_id` с текущим запросом — иначе это исход
предыдущего прогона.

Шлюз сканирует только пути внутри корней `TLDR_SCAN_ROOTS` (см. таблицу ниже): путь проверяется
после нормализации симлинков, выход за корни через ссылку — отказ. Каталог обмена `.tldr/` скрыт
от git записями в корневом `.gitignore` и собственным `.tldr/.gitignore`.

Коды возврата шлюза (истинный исход сканирования — в `exit_code` и `stdout` файла результата):

| Код | Что значит | Что делаю |
|-----|------------|-----------|
| `0` | Сканирование выполнено, даже с частичными сбоями команд | Читаю `exit_code` и `stdout` в файле результата, отчёты — в `reports/<report_name>` |
| `1` | Не удалось запустить `scan.sh` | Смотрю `stderr` файла результата |
| `2` | Отказ шлюза: нет файла запроса, запрос неверен, путь вне корней, корни не заданы | Смотрю `stderr`, правлю запрос или `TLDR_SCAN_ROOTS` |

## Переменные окружения

Значение берётся из окружения задачи mise, затем — умолчание скрипта. Пустое значение оставляет
умолчание. Переменные можно задать в секции `[env]` файла `mise.toml` (учтите: значения `[env]`
перекрывают переменные process-окружения) или в командной строке: `TLDR_EXT=.py mise run tldr-scan`.

| Переменная | Умолчание | Назначение |
|------------|-----------|------------|
| `TLDR_IMAGE` | `ghcr.io/united-software-platform/tldr-code:latest` | Образ tldr |
| `TLDR_EXT` | `.php` | Расширение, по которому строится дерево файлов |
| `TLDR_EXCLUDE` | `vendor,public` | Скрываемые каталоги от корня проекта, через запятую |
| `TLDR_SCAN_ROOTS` | — (пусто) | Корни хоста, внутри которых `tldr-scan-ext` разрешает сканировать: абсолютные пути через запятую. Пусто — внешние сканирования запрещены |

Каталог `reports` скрыт от анализа всегда, независимо от `TLDR_EXCLUDE`.

## Отчёты

Восемнадцать команд по четырём уровням; `hotspots` и `churn` выполняются только при наличии
`.git` в корне сканируемого проекта, иначе печатается пропуск.

| Уровень | Файлы отчётов |
|---------|---------------|
| Обзор (L1, метрики) | `01-tree.json`, `02-loc.json`, `03-structure.json`, `04-health.json` |
| Безопасность | `10-secure.json`, `11-vuln.json`, `12-api-check.json` |
| Качество и горячие точки | `20-hotspots.json`, `21-churn.json`, `22-cognitive.json`, `23-smells.json`, `24-clones.json`, `25-debt.json` |
| Архитектура (L2, паттерны) | `30-calls.json`, `31-hubs.json`, `32-inheritance.json`, `33-coupling.json`, `34-dead.json` |

Рядом с отчётом упавшей команды остаётся непустой `.err` — текст её stderr.

## Коды возврата

| Код | Что значит | Что делаю |
|-----|------------|-----------|
| `0` | Все команды выполнены | Читаю отчёты в `reports/tldr` |
| `1` | Часть команд завершилась ошибкой | Смотрю строки `FAIL` и соседние файлы `.err` |
| `2` | Ошибка вызова или окружения: нет пути проекта, каталог не найден, нет `kubectl`, кластер не отвечает, Job не завершился вовремя | Проверяю аргументы вызова и окружение хоста |

## Ограничения

- **Нужен локальный кластер k3s и `kubectl`**: без них сканирование не запустится (код `2`).
- **hostPath требует кластер на той же машине**, что и сканируемый каталог: путь монтируется
  с хоста напрямую.
- **Дедлайн Job'а — 1800 секунд**: на большом проекте 18 команд и первая загрузка образа могут
  его превысить; исход в этом случае — код `2` с сообщением о незавершении.
- **`inheritance` отказывается разбирать файлы больше 5 242 880 байт**, не называя файл.
  Найти такие файлы: `find . -type f -size +5M`; скрыть содержащий каталог — добавить его
  в `TLDR_EXCLUDE`.
- **Тег образа `latest` не закреплён**: состав команд и их вывод меняются вместе с образом.
  Закрепить — задать в `TLDR_IMAGE` точный тег или digest.
- **Проект монтируется только для чтения**: скрипт пишет на хост лишь отчёты в каталог отчётов.

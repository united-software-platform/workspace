# Операция {{operation}}: формирование требования прожаркой в карточку BR

Беклог формирования требования: выявить потребность из значения `requirement`, прожарить её
в карточку BR из девяти полей, получить принятие владельца и зафиксировать принятую карточку
артефактом в `docs/requirements/`. Предмет `subject` — адрес прогона; исходная формулировка
владельца — значение `requirement`. На время прогона карточка живёт во фронтматтере значением
`br_card`; после принятия она покидает прогон и становится документом `docs/requirements/<ID>.md` —
требование доступно для работы вне этого беклога. Беклог остаётся свидетельством прогона.

Операция с GitHub не работает: задач на GitHub, веток и коммитов она не создаёт — заведение
задачи по принятому требованию несут операции `workflow`, вызываемые отдельно. Статусы `Approved`
и `Deprecated` операция не назначает: приём требования в работу — решение вне этого прогона.

Значения операции несёт фронтматтер — второй раз они не собираются
(BKL-005; текст нормы — `backlog norms --rule BKL-005`). Задачи исполняются
по порядку.

Порядок исполнения — отметки задач, выводимый признак «выполнено ранее», стоп-знак перед
принятием карточки — задан BKL-006 (`backlog norms --rule BKL-006`)
и BKL-007 (`backlog norms --rule BKL-007`), а его носитель —
`{{runner}}`: прочитать его перед первой задачей; здесь он
не пересказывается (BKL-008; текст нормы — `backlog norms --rule BKL-008`). Указатель носителя несёт
и фронтматтер значением `runner`: оттуда его читает проверка, отсюда — исполнитель.

Шаблон карточки BR — девять полей, во фронтматтере карточка живёт ключами из столбца «Ключ»:

| Поле | Ключ | Описание | Значения |
|---|---|---|---|
| ID | `id` | Уникальный идентификатор | BR-001 |
| Name | `name` | Название требования | Текст |
| Description | `description` | Описание бизнес-потребности | Текст |
| Rationale | `rationale` | Обоснование необходимости | Текст |
| Business Outcome | `business_outcome` | Ожидаемый бизнес-результат | Текст |
| Success Criteria | `success_criteria` | Критерии достижения результата | Текст |
| Priority | `priority` | Приоритет | `Must` / `Should` / `Could` / `Won't` |
| Status | `status` | Статус | `Draft` / `Proposed` / `Rejected` |
| Source | `source` | Источник требования | Текст |

## 2. Прожарка BR

- [ ] 2.1 Выявить требование из значения `requirement` фронтматтера: что нужно бизнесу, зачем
  и какую задачу решаем; краткую формулировку показать владельцу
  - Проверка: формулировка отвечает на все три вопроса и согласована с владельцем
  - Выполнено ранее: формулировка зафиксирована — `br_card` во фронтматтере заполнен
- [ ] 2.2 Провести прожарку требования через `/mattpocock-skills:grilling` по девяти полям
  карточки: уточнять формулировки, пока каждое поле не заполнено; сведений не хватает —
  выяснить их у владельца; выдумывать содержимое полей и оставлять поля пустыми запрещено.
  Номер `BR-NNN` предлагает исполнитель по известным занятым номерам, подтверждает владелец —
  подбор «по смыслу» без подтверждения запрещён
  - Проверка: каждое из девяти полей заполнено словами владельца, номер подтверждён
  - Выполнено ранее: прожарка завершена — все поля карточки названы
- [ ] 2.3 Собрать карточку и записать во фронтматтер в `br_card` со статусом `Draft`:
  ключи `id`, `name`, `description`, `rationale`, `business_outcome`, `success_criteria`,
  `priority`, `status`, `source`
  - Проверка: `br_card` во фронтматтере несёт девять полей, статус карточки `Draft`
  - Выполнено ранее: `br_card` заполнен — повторная сборка не выполняется
- [ ] 2.4 Прогнать линтер формулировок по значениям полей карточки — по строке на поле
  (Name, Description, Rationale, Business Outcome, Success Criteria, Priority, Status,
  Source) во временный файл:
  `python3 -I tools/reqlint/reqlint.py --config tools/reqlint/rules.yml <временный файл полей>`
  Линтер не заменяет прожарку; находки severity `error` требуют решения владельца
  на стоп-знаке — устранить правкой карточки и повторить прогон либо принять
  с обоснованием. Временный файл после прогона удаляется
  - Проверка: линтер прогнан по текущей карточке, находки severity `error` известны
    к стоп-знаку, временный файл удалён
  - Выполнено ранее: линтер прогнан по текущей карточке — повторный прогон только

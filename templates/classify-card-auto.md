# Автоматическая классификация карточки {{subject}}

Беклог операции classify-card-auto: карточка проекта берётся готовой — она дана значением
операции `card_json` и не составляется заново, веб-поиск и выбор источника не идут, утилита
классификации вызывается напрямую один раз без цикла дополнения. Прогон — часть пакета
`{{package_stamp}}`, элемент `{{item_number}}`; результат возвращается оркестратору пакета.

Значения операции несёт фронтматтер — второй раз они не собираются
(BKL-005; текст нормы — `backlog norms --rule BKL-005`). Задачи исполняются
по порядку.

Порядок исполнения — отметки задач, выводимый признак «выполнено ранее» — задан BKL-006
(`backlog norms --rule BKL-006`), а его носитель — `{{runner}}`: прочитать его перед первой
задачей; здесь он не пересказывается (BKL-008; текст нормы — `backlog norms --rule BKL-008`).

Норма стоп-знака необратимой задачи (BKL-007; текст нормы — `backlog norms --rule BKL-007`)
в этом шаблоне не задействована: необратимых задач карточный прогон не несёт, точка решения
одна — принятие итога классификации, и закрывается она исполнителем-автоматом пакета на модели
уровня `runner_model` (уровень выбирает владелец пакета; конкретная модель уровня разрешается
платформой через `ANTHROPIC_DEFAULT_<УРОВЕНЬ>_MODEL`), решение и его авторство записываются
во фронтматтер именем уровня. Неустранимый отказ не прерывает пакет: причина пишется
в `failure_reason`, неподтверждённая классификация закрывается значением
`skipped: <причина>`, прогон элемента завершается со статусом `failed`.

## 2. Классификация карточки

- [ ] 2.1 Вызвать утилиту классификации напрямую с карточкой и порогом `threshold`,
  один вызов на элемент — повторные вызовы и дополнение карточки не выполняются
  `cd tools/classifier && uv run classifier <путь карточки> --threshold {{threshold}}`
  и разобрать код возврата: `0` — чистый результат; `1` — needs_confirmation
  по непройденному порогу; `2` — ошибка входа или окружения
  - Проверка: код возврата разобран, вывод утилиты сохранён для записи прогона;
    повторных вызовов не было
  - Выполнено ранее: вывод утилиты уже разобран во фронтматтере `classification`
- [ ] 2.2 Закрыть точку решения по коду возврата — потолок вызовов не задействован,
  дополнения не идут:
  - код `0` — `classification` заполняется итогом утилиты (включая `combined_labels`),
    `confirmed.classification` = `{{runner_model}}: принято, код 0`;
  - код `1` — `classification` заполняется итогом утилиты, `failure_reason` =
    `needs_confirmation`, `confirmed.classification` = `skipped: needs_confirmation` —
    данные классификации сохраняются в записи прогона, повторный вызов остаётся решением
    владельца;
  - код `2` — `failure_reason` = `ошибка утилиты: <текст>`, `confirmed.classification` =
    `skipped: ошибка утилиты`.
  - Проверка: исход зафиксирован во фронтматтере: при коде `0` оба поля заполнены;
    при коде `1` причина и данные последней классификации на месте; при коде `2`
    причина ошибки записана
  - Выполнено ранее: исход во фронтматтере зафиксирован

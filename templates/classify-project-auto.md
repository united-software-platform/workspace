# Автоматическая классификация проекта {{subject}}

Беклог операции classify-project-auto: найти проект по названию в интернете, исполнитель-автомат
выбирает ближайший источник, по нему составляется карточка проекта, утилита классификации
вызывается напрямую, чистый результат принимается исполнителем-автоматом. Прогон — часть пакета
`{{package_stamp}}`, элемент `{{item_number}}`; результат возвращается оркестратору пакета.

Значения операции несёт фронтматтер — второй раз они не собираются
(BKL-005; текст нормы — `backlog norms --rule BKL-005`). Задачи исполняются
по порядку.

Порядок исполнения — отметки задач, выводимый признак «выполнено ранее» — задан BKL-006
(`backlog norms --rule BKL-006`), а его носитель — `{{runner}}`: прочитать его перед первой
задачей; здесь он не пересказывается (BKL-008; текст нормы — `backlog norms --rule BKL-008`).

Норма стоп-знака необратимой задачи (BKL-007; текст нормы — `backlog norms --rule BKL-007`)
в этом шаблоне не задействована: необратимых задач прогон элемента не несёт, точки решений
закрываются исполнителем-автоматом пакета на модели уровня `runner_model` (уровень выбирает
владелец пакета; конкретная модель уровня разрешается платформой через
`ANTHROPIC_DEFAULT_<УРОВЕНЬ>_MODEL`), решения и их авторство записываются во фронтматтер
именем уровня. Неустранимый отказ не прерывает пакет: причина пишется в `failure_reason`,
подтверждения, не дошедшие до заполнения, закрываются значением `skipped: <причина>`, прогон
элемента завершается со статусом `failed`.

## 4. Карточка и классификация

- [ ] 4.1 По выбранному источнику `chosen_source` составить карточку проекта по входному
  контракту `tools/classifier/docs/contracts.md`: `purpose` обязателен, `facets` опционален.
  Карточку сохранить файлом `projects/{{package_stamp}}.cards/item-{{item_number}}.json` —
  каталог прогонов вне коммита
  - Проверка: файл карточки существует, `purpose` заполнен по данным выбранного источника
  - Выполнено ранее: файл карточки по этому предмету существует
- [ ] 4.2 Вызвать утилиту классификации напрямую с карточкой и порогом `threshold`
  `cd tools/classifier && uv run classifier <путь карточки> --threshold {{threshold}}`
  и разобрать код возврата — этот вызов считается попыткой: `enrichment_attempts`
  инкрементируется на каждый вызов утилиты, включая первый. Коды: `0` — чистый
  результат, принять (пограничные уровни несут метку «A & B» в `combined_labels` —
  она часть принятого итога); `1` — needs_confirmation по непройденному порогу,
  цикл дополнения по задаче 4.3; `2` — ошибка входа или окружения, отказ элемента
  без попыток дополнения
  - Проверка: код возврата разобран, `enrichment_attempts` равен числу выполненных вызовов,
    вывод утилиты сохранён для записи прогона; при коде `2` `failure_reason` заполнен
    причиной ошибки, цикл не запускался
  - Выполнено ранее: вывод утилиты уже разобран во фронтматтере `classification`
- [ ] 4.3 Исполнить цикл дополнения по исходу вызова — потолок три вызова утилиты
  на элемент, в этом беклоге; причины дополнения — только непройденный порог:
  малый отрыв меткой «A & B» закрывается и дополнением не лечится:
  - код `0` — `classification` заполняется итогом утилиты (включая `combined_labels`),
    `confirmed.classification` = `{{runner_model}}: принято, код 0`;
  - код `1` и `enrichment_attempts` < 3 — проанализировать `reasons` итога: назвать
    уровни и записи ниже порога; дополнить карточку фактами из источника
    `chosen_source`, целевыми для непройденных уровней (не «всё подряд»); перезаписать
    карточку по пути `projects/{{package_stamp}}.cards/item-{{item_number}}.json`;
    дописать ход дополнения в `enrichment_log`; вернуться к задаче 4.2 с дополненной
    карточкой — повторный вызов инкрементирует счётчик;
  - код `1` и `enrichment_attempts` = 3 — попытки исчерпаны: `classification` заполняется
    итогом последнего вызова, `failure_reason` = `needs_confirmation`,
    `confirmed.classification` = `skipped: needs_confirmation`;
  - код `2` — `failure_reason` = `ошибка утилиты: <текст>`, без попыток.
  Первый вызов — исходная карточка, два повторных — дополнения; новый беклог
  не порождается
  - Проверка: при принятии оба поля заполнены; при цикле `enrichment_attempts` растёт
    до трёх по вызовам, `enrichment_log` растёт по дополнениям, карточка перезаписана
    на месте; при исчерпании — `failure_reason` с данными последней классификации
  - Выполнено ранее: исход во фронтматтере зафиксирован

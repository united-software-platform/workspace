# Операция workflow: рабочий процесс от требования до прожарки

Беклог рабочего процесса: выявить требование, завести по нему задачу на GitHub, открыть ветку
изменений и запустить прожарку формирования изменений. Предмет `subject` — адрес прогона; исходная
формулировка владельца — значение `requirement`. Код и номер задачи рождает этот прогон
и дописывает во фронтматтер.

Значения операции несёт фронтматтер — второй раз они не собираются
(BKL-005; текст нормы — `backlog norms --rule BKL-005`). Задачи исполняются
по порядку.

Порядок исполнения — отметки задач, выводимый признак «выполнено ранее», стоп-знак перед
необратимой задачей — задан BKL-006 (`backlog norms --rule BKL-006`)
и BKL-007 (`backlog norms --rule BKL-007`), а его носитель —
`/backlog:backlog-run`: прочитать его перед первой задачей; здесь он
не пересказывается (BKL-008; текст нормы — `backlog norms --rule BKL-008`). Указатель носителя несёт
и фронтматтер значением `runner`: оттуда его читает проверка, отсюда — исполнитель.

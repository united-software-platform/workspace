# Формат реализованной работы разработчика

Контракт выгрузки работы одного разработчика или команды из git-истории репозитория: каждый коммит
со связью с кодом из слепка tldr. Машиночитаемый вход для дальнейшего анализа — реляционного
хранения, индекса Elastic, LLM-обработки. Все примеры вымышлены; реальные выгрузки и реальный реестр
идентичностей — локальные файлы вне git.

## Понятия

| Понятие | Определение |
|---------|-------------|
| Реализованная работа (Implemented Work) | Совокупность коммитов лица или команды на линии истории, включая merge, с затронутыми путями и их связью со слепком |
| Слепок (Snapshot) | Каталог отчётов tldr по способности `code-scan`, снятый с репозитория: `01-tree.json`, `03-structure.json` и другие |
| Пара (Pair) | Связь затронутого коммитом пути с элементом слепка по нормализованному POSIX-пути; семантика — «путь присутствует в слепке» |
| Реестр идентичностей (People Registry) | Файл, задающий каждому разработчику slug, имя, список email и команду |
| Область (Scope) | Перечень префиксов каталогов и файлов, попадающих в записи коммитов; пути вне области учитываются счётчиком |

> **Важно:** слепок не несёт ревизии, на которой снят. Пара означает «путь присутствует в слепке»,
> а не «код родился этим коммитом». Потребитель не вправе утверждать второе на основании выгрузки.

## Канонический носитель и JSON-проекция

Канонический носитель контракта — YAML. Производная JSON-проекция предназначена для загрузки
в Elastic и реляционное хранилище; конверсия детерминирована и обратима без потерь (YAML⊃JSON):

- YAML: `yaml.safe_dump(data, sort_keys=True, allow_unicode=True)`
- JSON: `json.dumps(data, ensure_ascii=False, sort_keys=True)`

Обе проекции строятся из одной структуры данных. Сортировка ключей и стабильный порядок списков
(коммиты — по `authored_at`, затем `sha`; пути — лексикографически) делают повторные выгрузки
сопоставимыми построчно. Схемы хранения (ES-mapping, DDL) — задача потребителя и в этот документ
не входят.

---

## Структура контракта

```yaml
header:
  <шапка — см. ниже>
commits:
  - <запись коммита — см. ниже>
```

Два верхнеуровневых ключа: `header` (параметры выборки и оговорки) и `commits` (список записей
в хронологическом порядке).

## Шапка

| Поле | Обязательность | Смысл |
|------|----------------|-------|
| `format_version` | да | Версия формата, строка `"1.0"` |
| `generated_at` | да | ISO 8601 дата и время формирования выгрузки |
| `registry` | да | Путь к реестру идентичностей, по которому собрана выборка |
| `selection.kind` | да | `person` или `team` |
| `selection.value` | да | slug лица или имя команды |
| `persons` | да | Список вошедших в выборку лиц: `{slug, name, emails[], team}` |
| `period.from`, `period.to` | нет | Границы периода по `authored_at`; отсутствуют — вся история линии |
| `line` | да | Имя ветки линии истории, по которой собрана выгрузка |
| `snapshot.name` | да | Имя слепка (имя каталога отчётов) |
| `snapshot.taken_at` | да | Дата съёмки слепка |
| `snapshot_revision_unknown` | да | Всегда `true`: ревизия слепка не зафиксирована |
| `scope.include` | да | Список префиксов каталогов и файлов области |
| `scope.outside_count` | да | Число уникальных путей вне области за всю выборку |

## Запись коммита

| Поле | Обязательность | Смысл |
|------|----------------|-------|
| `sha` | да | Хэш коммита |
| `authored_at` | да | ISO 8601 дата и время со смещением (`2026-04-14T11:28:12+03:00`) |
| `author` | да | slug лица из реестра — кому приписан коммит |
| `author_email` | да | Фактический email автора коммита из истории |
| `kind` | да | `code` — коммит кода, `integration` — merge-коммит |
| `merged` | для integration | `own` — влита ветка из одних своих коммитов, `others` — есть чужие |
| `subject` | да | Заголовок коммита |
| `body` | нет | Тело коммита; отсутствует, если тела нет |
| `task` | нет | Код задачи из заголовка (`^[A-Z]+-[0-9]+$`), best effort |
| `branch` | нет | Имя ветки из merge-топологии, best effort |
| `paths` | да | Статус-лист затронутых путей области |

Поля `task` и `branch` — плавающий источник истины: покрывают не всю историю, отсутствие — норма,
а не ошибка. Формат не содержит полей ревью: «отревьюировал» — интерпретация потребителя поверх
механических фактов.

Элемент `paths`:

| Поле | Обязательность | Смысл |
|------|----------------|-------|
| `path` | да | POSIX-путь относительно корня репозитория |
| `status` | да | `A` добавлен, `M` изменён, `D` удалён, `R` переименован |
| `added`, `deleted` | да | Число добавленных/удалённых строк (numstat); `null` для binary |
| `snapshot` | да | Пара со слепком: `found` / `missing` |
| `symbols` | нет | Для `found`: символы файла из `03-structure.json` |

Для `status: R` пара со слепком строится по пути после переименования. Удалённые пути фиксируются
явно: `status: D` с numstat и парой `missing` (если файл не существует в слепке) либо `found`
(если путь в слепке вновь появился — например, пересоздан позже).

## Реестр идентичностей

Реестр задаёт каждому разработчику `{slug, name, emails[], team}`:

- `slug` — ключ выборки `person`;
- `emails` — список адресов: один человек с несколькими email представляется одной записью
  со списком; коммит попадает в выборку при точном совпадении email автора с одним из адресов
  списка;
- `team` — имя команды для выборки `team`.

Реестр — источник истины по адресам: формат не нормализует email (trim, lower, «починка» опечаток).
Решение о слиянии адресов принимает ведущий реестра. Коммитимый шаблон — `docs/people.yaml`
(вымышленные записи); реальный реестр — локальный файл вне git.

## Пара со слепком

Пара строится по нормализованному POSIX-пути: git-путь и путь слепка приводятся к общему виду
и сравниваются на точное совпадение. Ядро связки:

- `01-tree.json` — существование пути: рекурсивный обход `children`, все файлы с их `path`;
- `03-structure.json` — символы найденного пути: классы и методы с диапазонами строк.

Элемент `symbols` (опциональный, для `snapshot: found`):

```yaml
symbols:
  - name: <имя класса или метода>
    kind: class | method
    line_start: <int>
    line_end: <int>
```

Сопоставление символов при использовании выгрузки — по имени, не по номерам строк: строки дрейфуют
между коммитом и слепком. Прочие отчёты слепка (агрегаты истории, метрики качества) — опциональные
аннотации по нужде потребителя.

## Нормализация путей слепка

Пути в отчётах слепка относительные, POSIX, но с непоследовательными префиксами. Нормативная
таблица нормализации:

| Отчёт слепка | Ведущий префикс | Действие |
|---|---|---|
| `01-tree.json` (`path`), `03-structure.json` (`files[].path`) | — | нет, путь уже канонический |
| `04-health`, `10-secure`, `11-vuln`, `12-api-check`, `22-cognitive`, `24-clones`, `25-debt`, `32-inheritance` | `./` | отрезать ведущий `./` |
| `23-smells.json` | `/project/` | отрезать ведущий `/project/` |
| `20-hotspots`, `21-churn`, `30-calls`, `31-hubs`, `33-coupling`, `34-dead` | — | нет, путь уже канонический |

Особые случаи ключей путей: `30-calls` — узлы графа `"path:symbol"`, путь до первого `:`;
`24-clones` — `fragment1.file`, `fragment2.file`; `32-inheritance` — `child_file`, `parent_file`.

## Область и счётчик вне области

`scope.include` — список префиксов каталогов и/или имён файлов. Путь входит в область, если
начинается с одного из префиксов или совпадает с одним из файлов. Состав области задаёт потребитель
формата при формировании выгрузки.

В `paths` записей попадают только пути области. Прочие пути не выбрасываются бесследно: уникальные
пути вне области за всю выборку суммируются в `header.scope.outside_count`. Это удерживает записи
сфокусированными на коде и отделяет шум сторонних артефактов.

---

## Типовые запросы потребителя

Агрегаты — не поля контракта; счётчики считает потребитель. Примеры запросов поверх выгрузки:

- Сколько коммитов кода и интеграций у лица: подсчёт `commits[]` по `author` и `kind`.
- Сколько влито своих и чужих веток: подсчёт `kind: integration` с разбиением по `merged`.
- Динамика +/- строк по датам: суммирование `paths[].added`/`paths[].deleted` по `authored_at`.
- Коммиты по человеку в team-выборке: группировка `commits[]` по `author`/`author_email`.
- Работа по файлам слепка: соединение `paths[].path` с `snapshot: found` и аннотациями символов.

## Пример выгрузки

> **Примечание:** пример целиком вымышлен — имена, email, пути, sha, слепок. Структура нормативна.

```yaml
header:
  format_version: "1.0"
  generated_at: "2026-11-07T10:15:00+03:00"
  registry: "/secure/registries/people.yaml"
  selection:
    kind: team
    value: backend
  persons:
    - slug: aivanov
      name: Андрей Иванов
      emails:
        - a.ivanov@example.dev
        - andrey.ivanov@example.org
      team: backend
    - slug: mpetrova
      name: Мария Петрова
      emails:
        - m.petrova@example.dev
      team: backend
  line: main
  snapshot:
    name: inventory-service
    taken_at: "2026-11-01"
  snapshot_revision_unknown: true
  scope:
    include:
      - src/
      - config/
      - tests/
      - Makefile
      - composer.json
    outside_count: 42
commits:
  - sha: "1a2b3c4d5e6f7890abcdef1234567890abcdef12"
    authored_at: "2026-09-03T14:22:10+03:00"
    author: aivanov
    author_email: a.ivanov@example.dev
    kind: code
    subject: "SHOP-101: добавить расчёт скидки в корзине"
    body: |
      Скидка применяется к позициям корзины по правилам из конфигурации.
    task: SHOP-101
    paths:
      - path: src/Cart/DiscountCalculator.php
        status: A
        added: 84
        deleted: 0
        snapshot: found
        symbols:
          - name: DiscountCalculator
            kind: class
            line_start: 12
            line_end: 96
          - name: apply
            kind: method
            line_start: 40
            line_end: 62
      - path: src/Legacy/OldCartProcessor.php
        status: D
        added: 0
        deleted: 210
        snapshot: missing
  - sha: "2b3c4d5e6f7890abcdef1234567890abcdef1234"
    authored_at: "2026-09-05T09:40:33+03:00"
    author: mpetrova
    author_email: m.petrova@example.dev
    kind: code
    subject: "SHOP-104: правка валидации адреса доставки"
    paths:
      - path: src/Order/ShippingAddress.php
        status: M
        added: 12
        deleted: 3
        snapshot: found
        symbols:
          - name: ShippingAddress
            kind: class
            line_start: 8
            line_end: 74
  - sha: "3c4d5e6f7890abcdef1234567890abcdef123456"
    authored_at: "2026-09-06T18:05:47+03:00"
    author: aivanov
    author_email: andrey.ivanov@example.org
    kind: integration
    merged: others
    subject: "Merge branch 'feature/SHOP-104' into 'main'"
    paths:
      - path: src/Order/ShippingAddress.php
        status: M
        added: 12
        deleted: 3
        snapshot: found
```

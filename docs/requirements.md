## Описание

### Назначение

Система управляет рабочим пространством (Workspace) разработчика: собирает и агрегирует данные
о проектах и бизнес-кейсах, анализирует проекты и выполняет гибридный поиск по данным пространства.

### Роли

| Роль | Кто это | Что делает |
|------|---------|------------|
| Разработчик | Владелец рабочего пространства | Управляет составом пространства, инициирует сбор данных, ведёт бизнес-кейсы, пользуется анализом и поиском |
| LLM-агент | Ассистент разработчика | Пользуется анализом и поиском как источником контекста, ведёт бизнес-кейсы; состав пространства не меняет |

### Понятия

| Понятие | Определение |
|---------|-------------|
| Рабочее пространство (Workspace) | Совокупность проектов, бизнес-кейсов и собранных о них данных одного разработчика |
| Проект (Project) | Один git-репозиторий, зарегистрированный в рабочем пространстве по пути |
| Группа проектов (Project Group) | Именованный набор проектов для агрегации, анализа и поиска по подмножеству |
| Бизнес-кейс (Business Case, BC) | Бизнес-решение и задача: проблема, решение и, при наличии, измеримые метрики; результат подкрепляется данными git проектов, к которым относится BC |
| Сборщик (Collector) | Источник данных о проекте: git, AST, метрики кода и другие подключаемые источники |
| Намерение (Intent) | Заявленная пользователем цель сбора: какие проекты и какие данные нужны |

### Границы

Входит: учёт проектов и групп, сбор данных по намерению, агрегация, ведение BC, анализ проектов
и BC, гибридный поиск.

Не входит: нефункциональные требования, модель данных, интерфейсы, архитектура, командная работа
с разграничением прав, анализ силами LLM, сбор по расписанию и по git-хукам.

## Возможности

| Код | Возможность | Суть |
|-----|-------------|------|
| CAP-001 | Управление пространством | Учёт проектов и групп, настройка сборщиков и исключений проекта |
| CAP-002 | Сбор данных | Сбор данных о проектах, инициированный намерением пользователя |
| CAP-003 | Агрегация | Сведение собранных данных по проекту, группе и пространству, в том числе во времени |
| CAP-004 | Ведение BC | Регистрация BC и подтверждение его результата данными git |
| CAP-005 | Анализ | Отчёты по проектам и BC на основе собранных данных |
| CAP-006 | Гибридный поиск | Поиск по данным проектов и BC с объединённым ранжированием |

Возможности (Capability, CAP) — укрупнённые способности системы; каждая раскрывается операциями
(Operation, OP) в разделе [Операции](#операции).

## Ограничения и допущения

- **Допущение:** любой сбор данных инициирует пользователь; намерение задаёт охват сбора. Форма
  намерения и способ его исполнения прорабатываются позднее.
- **Допущение:** git, AST и метрики кода — примеры источников, а не обязательный состав; набор
  сборщиков расширяем. Перечень языков для AST не фиксируется — он определяется доступными парсерами.
- **Ограничение:** детали агрегации — оси, периоды, хранение истории — не проработаны.
- **Ограничение:** содержание BC проработано только верхнеуровнево: состав полей, жизненный цикл
  и порядок подтверждения результата уточняются отдельно.
- **Риск:** понятие «Кейс (Case)» уже определено в [правилах документов проекта](../rules/project-docs-rules.md#понятия)
  в другом смысле; поэтому здесь используется отдельное имя — бизнес-кейс (BC).

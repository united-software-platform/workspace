# BR-004: Поиск проектных решений пространства

Бизнес-требование к семантическому поиску зафиксированных проектных решений рабочего
пространства. Карточка принята владельцем в прогоне requirement-add и является основой
будущей работы.

## Карточка

| Поле | Значение |
|---|---|
| ID | BR-004 |
| Name | Поиск проектных решений пространства |
| Description | Бизнес должен уметь искать по смыслу возникшей проблемы зафиксированные проектные решения всех проектов рабочего пространства, включая завершённые и архивные, и получать список релевантных решений по убыванию релевантности |
| Rationale | Проектное решение переживает свой проект и накапливается фондом, но в момент, когда та же проблема встаёт в другом проекте, накопленное не находится — работа решается заново |
| Business Outcome | Накопленный фонд проектных решений перестаёт теряться: возникшая проблема находит уже зафиксированное решение, та же проблема не решается с нуля |
| Success Criteria | На контрольном наборе пар «проблема → релевантное решение» не менее 80 % пар находят своё решение в топ-5 выдачи; выдача списка релевантных решений по запросу занимает не более 300 мс |
| Priority | Must |
| Status | Proposed |
| Source | Владелец, 2026-11-22, прогон requirement-add |

Терминология — [Глоссарий](../../GLOSSARY.md): «Проектное решение (Project Solution, PS)»,
«Рабочее пространство (Workspace)».

> **Примечание:** Хвост Business Outcome «та же проблема не решается с нуля» измеряется
> вне этого требования — поведенческое следствие находимости; критерием принят прокси
> находимости (80 % в топ-5). Состав контрольного набора пар — операционализация при
> проверке, не предмет карточки.

## Вне рамок

- Фиксация и извлечение проектных решений из проектов: фонд решений пополняется отдельной
  работой, здесь он данность.
- Сборка нового проекта из найденных решений.
- Заведение задач по принятому требованию — операции `workflow`, вызываемые отдельно.

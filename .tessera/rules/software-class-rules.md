# Нормы классов ПО

**Предмет:** продукт — уровень предмета: что описывается, поведение компонента.

Нормы, относящиеся к классу ПО: характеризуют плагин двумя потоками — поставки и зависимостей —
и отделяют в описаниях артефактов продукт от разработки продукта, чтобы агент различал по самому
описанию нормы поведения компонента и нормы работы над ним. Сейчас класс один — плагины, ПО,
поставляющее что-либо куда-либо.

## Таблица норм

Нормы ведутся по классам ПО: у класса своя серия кодов и своя таблица. Характеристику класса
задают нормы о его потоках. Другой класс заводится своей таблицей здесь же, когда появляется ПО,
к которому действующие нормы не подходят.

## Понятия

| Понятие | Определение |
|---------|-------------|
| Класс ПО (Software Class) | Множество продуктов одной природы, к которому относятся нормы: сейчас — плагины, ПО, поставляющее что-либо куда-либо |
| Поток поставки (Delivery Flow) | Артефакты, которые плагин отдаёт в другую систему: скрипты, навыки, правила и иные артефакты |
| Поток зависимостей (Dependency Flow) | Артефакты, которые плагин берёт извне: внешние плаги, правила и иные артефакты, без которых он не работает и не разрабатывается |
| Состав плагина (Plugin Composition) | Артефакты потока поставки — то, что плагин отдаёт получателю |
| Зависимости плагина (Plugin Dependencies) | Артефакты потока зависимостей — то, что плагин берёт извне |
| Продукт (Product) | То, что получает потребитель: компонент и его поведение — уровень предмета |
| Разработка продукта (Product Development) | Работа над созданием продукта: правила и процесс — уровень работы над предметом |
| Предмет описания (Description Subject) | То, что описывает описание для агентов: продукт либо разработка продукта |
| Описание для агентов (Agent-Facing Description) | Документ, который читают агенты: правило, навык, точка входа агентов, README, иной документ репозитория |
| Носитель (Carrier) | Файл, несущий описание для агентов |
| Потребитель (Consumer) | Тот, кто применяет продукт, не меняя его исходников; читает описания предмета «продукт» |
| Контрибьютор (Contributor) | Тот, кто меняет исходники продукта в его репозитории; читает описания предмета «разработка продукта» |

## Границы нормы

Норма действует для ПО класса. Она требует от плагина объявить состав плагина и зависимости
плагина и разводит описания по предметам и потокам; содержание перечней, состав правил
и порядок работы над продуктом остаются за плагином и проектом.

Объявления не несут файлы, не являющиеся описаниями: заготовки порождения, манифесты и каталоги,
спецификации и изменения процесса, следы прогонов, сценарии. Их предмет объявляет навык или
документ, который ими пользуется. Служебные элементы файла — заголовок, назначение, навигация,
таблица версий — предмета не описывают.

Объявление предмета не заменяет правила оформления документа: оно стоит между заголовком
и назначением. Формат любого md-файла задают [правила документации](./documentation-rules.md).

## Предмет описания [PLG-001..002]

**[PLG-001]** Каждое описание для агентов принадлежит ровно одному предмету:

- **продукт** — уровень предмета: что описывается, поведение компонента;
- **разработка продукта** — уровень работы над предметом: как этот предмет создаётся — правила
  и процесс.

Плагин состоит из описаний для агентов и создаётся через описания для агентов. Без объявления
предмета читающий не отличает норму поведения компонента от нормы работы над ним.

**[PLG-002]** Каждому предмету соответствует роль. Описания предмета «продукт» читает
потребитель, описания предмета «разработка продукта» — контрибьютор. Слово «разработчик» роль
не называет: оно обозначает обе и потому смешивает предметы.

```text
Предмет «продукт»:          навык запуска операции, правило оформления документов
Предмет «разработка продукта»: порядок подготовки харнесов к работе над репозиторием
```

## Объявление предмета [PLG-003..004]

**[PLG-003]** Описание для агентов открывается объявлением предмета — одной канонической строкой
сразу после заголовка. Строки две, и в описании они приводятся дословно:

```markdown
**Предмет:** продукт — уровень предмета: что описывается, поведение компонента.
**Предмет:** разработка продукта — уровень работы над предметом: как этот предмет создаётся, правила и процесс.
```

Объявление — первая содержательная строка после заголовка первого уровня. YAML-фронтматтер
не считается; для README с блоком бейджей объявление ставится после блока, перед назначением.
В описании объявление одно.

```markdown
# Название правила

**Предмет:** продукт — уровень предмета: что описывается, поведение компонента.

Назначение правила — одна-три строки.

---

## Навигация
```

**[PLG-004]** Объявленный предмет соответствует носителю:

| Носитель | Предмет |
|----------|---------|
| Навыки и правила плагина, README плагина | продукт |
| README репозитория, документ кейсов и иные описания продукта для потребителя | продукт |
| Точка входа агентов репозитория, `CONTRIBUTING.md`, глоссарий | разработка продукта |

Чужой предмет у носителя — расхождение: порядок подготовки к работе над репозиторием в описании
навыка означает, что материал не вынесен в носитель своего предмета.

## Один предмет на артефакт [PLG-005]

**[PLG-005]** Артефакт и его описания обслуживают ровно один предмет. Материал другого предмета
выносится в носитель своего предмета; в источнике остаётся ссылка на новое расположение
по [DOC-023](./documentation-rules.md#жизненный-цикл-документа).

```text
Нарушение:  README плагина содержит порядок добавления навыка и проверки манифестов
Правильно:  README плагина описывает плагин, а порядок его расширения лежит в CONTRIBUTING.md
```

---

## Навык и правила плагина [PLG-006..007]

**[PLG-006]** Навык описывает только поведение продукта. Порядок подготовки харнесов к работе
над репозиторием живёт вне навыка — в точке входа агентов и в `CONTRIBUTING.md`. Отказ навыка
с командой установки зависимости — поведение продукта: он одинаков для потребителя
и контрибьютора.

**[PLG-007]** Правила плагина описывают только поведение продукта и не содержат порядка
разработки самого плагина. Какую норму принимает для работы над репозиторием проект,
объявляет точка входа агентов — там, где норму принимают, а не в самом правиле:

```markdown
Правила плагина — содержание продукта. Для работы над репозиторием приняты как нормы: <перечень>.
Их правка — изменение продукта.
```

## Сверка объявлений [PLG-008]

**[PLG-008]** Объявление предмета сверяется у каждого носителя: оно на своём месте, одно,
дословно каноническое и соответствует носителю. Непройденная сверка называет файл. Перечень
носителей живёт только в проверке.

## Два потока [PLG-009]

**[PLG-009]** Плагин характеризуется двумя потоками:

- **поток поставки** — артефакты, которые плагин отдаёт в другую систему: скрипты, навыки,
  правила и иные артефакты, — **состав плагина**;
- **поток зависимостей** — артефакты, которые плагин берёт извне: внешние плаги, правила и иные
  артефакты, без которых он не работает и не разрабатывается, — **зависимости плагина**.

Потоки названы по направлению: поставка отдаёт, зависимости берут. Перечни потоков названы
по владельцу: состав плагина ведёт сам плагин, зависимости плагина он же объявляет о чужом.

```text
Поток поставки tessera-plugin:      навыки, правила, шаблоны операций
Поток зависимостей tessera-plugin:  плагин backlog, плагин mattpocock-skills
```

---

## Состав и зависимости плагина [PLG-010]

**[PLG-010]** Плагин объявляет оба перечня: состав плагина — артефакты, которые он отдаёт
получателю, — и зависимости плагина — то, что он берёт извне. Для каждой зависимости названо,
кто её требует: навык, правило или работа над плагином.

Зависимость живёт в носителе своего предмета: нужная для работы плагина — без неё навык
не работает — объявляется в носителях предмета «продукт», её читают и потребитель,
и контрибьютор; нужная только для работы над плагином — правила, принятые как нормы,
инструменты — в носителях предмета «разработка продукта».

---

## Разведение потоков [PLG-011]

**[PLG-011]** Артефакт потока зависимостей не значится в составе плагина, даже когда оказывается
на машине получателя вместе с поставкой. Артефакт, входящий в оба потока, значится дважды:
в составе плагина — как то, что плагин отдаёт, в зависимостях плагина — как то, что берёт.

```text
Только поток зависимостей:  лаунчер backlog — CLI зависимости, в состав плагина не входит
Оба потока:                 правило оформления — поставляется в составе и принято
                            для работы над репозиторием tessera
```

> **Примечание:** сверка состава плагина и зависимостей плагина идёт чтением описаний;
> машинной сверки норма не задаёт.
